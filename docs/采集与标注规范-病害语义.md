# 采集与标注规范：病害语义（S0 / X3）

> 配套文档：`docs/采集规范-色卡与ArUco.md`（**先满足那份，再满足这份**）。
> 本文的每一条约束都对应 `scripts/check_damage_labels.py` 里的一条检查——
> 写在这里却没人执行的规定等于没有。

## 0 这份规范解决什么问题

S0 病害语义一直开不了，不是因为代码，而是因为**没有可学的病害实例**：
现有候选区全是「UV 岛边界 / 材质交界」，残存彩绘只占 1.89%，硬标只能分出
「彩绘 / 胎体」——那是域分类，不是病害。

本文定义：**拍什么、怎么拍、怎么命名、标成什么格式**，以及**拍完怎么自检**。
拍齐 + 自检过，才能开工。

## 1 前置条件（不满足就别开始）

| # | 条件 | 为什么 |
|---|---|---|
| 1 | 一件**病害形态明确**的文物 | 裂隙/起翘/脱落/泛碱，肉眼能指着说"这就是" |
| 2 | 同一批照片**跑得通 S1**（COLMAP） | 语义要复用 M4 的位姿做多视图票决，位姿错了一切白搭 |
| 3 | 色卡与本规范的照片**在同一次采集**内 | ΔE 类判据要色卡；两次采集的光照不可比 |
| 4 | 至少 **3 类**病害，每类 ≥ **10 处**实例 | 低于这个量只能做 few-shot 演示，做不了评估 |

## 2 目录与命名

```
<项目根>/
  阶段成果/00_photo/<item>/           IMG_0001.JPG …        （原有，不改名）
  阶段成果/90_meta/<item>_capture_meta.json                   （S1 产物）
  damage/<item>/
      labels.json                     ← 本规范定义的标注文件（一件一个）
      overview.md                     ← 可选：现场笔记、裂缝草图标号

<标注包根>/（可选，独立于项目也行）
  <item>/labels.json
```

**约定**
- 一件文物一个 `labels.json`，**不按病害拆文件**——拆开就必须靠目录名维系一致性。
- 照片文件名保持相机原始名，**不要为了标注改名**：`capture_meta.json` 里记的是原名，
  改名等于让位姿对不上。
- 病害 id 形如 `D001`、`D002`（三位，从 001 起，**只增不改**：删掉的 id 不回收，
  否则历史报表与标注包对不上）。

## 3 每处病害拍几张、怎么站位

| 要求 | 数值 | 理由 |
|---|---|---|
| 同一处病害的**有效视角数** | ≥ **3**（推荐 5） | 少于 3 时多视图票决退化成单视图硬投影——那个坑的记录是「整件都判成有病害」 |
| 视角之间的**最大夹角** | ≥ **40°** | 同一机位连拍三张不算三个视角（脚本会算，不靠自觉） |
| 相机到病害的**法向夹角** | 每张 ≤ **60°**（cos>0.5） | 斜视太厉害的掩膜边界不可信 |
| 相邻视角**重叠** | ≥ **60%**（以病害为中心看） | 票决要能对上同一纹素 |
| 病害在画面里占比 | ≥ **1/8 短边** | 太小的话 `pixel_scale` 换算后不足 10 个纹素 |

**站位提示**：把病害放在画面中央，绕它走小弧（像拍人脸特写），别站在一个点变焦。
深腔/内侧病害必须补低机位或俯拍——俯拍补不到的东西，后面谁也算不出来。

## 4 标注文件格式（`labels.json`）

```json
{
  "schema": "h3d-damage-labels/1",
  "item_id": "relic_002",
  "captured_at": "2026-11-07",
  "operators": ["张三"],
  "classes": ["crack", "detachment", "efflorescence"],
  "damages": [
    {
      "id": "D001",
      "class": "crack",
      "note": "口沿纵向裂隙，长约 3 cm",
      "views": [
        {"photo": "IMG_0012.JPG", "polygon": [[812, 455], [830, 461], [826, 610]], "difficulty": "clear"},
        {"photo": "IMG_0013.JPG", "polygon": [[540, 470], [556, 478], [551, 602]], "difficulty": "clear"},
        {"photo": "IMG_0018.JPG", "polygon": [[300, 520], [318, 525], [315, 640]], "difficulty": "unclear"}
      ]
    }
  ]
}
```

**字段**

| 字段 | 必填 | 说明 |
|---|---|---|
| `schema` | √ | 固定 `h3d-damage-labels/1`；不认识的版本直接拒 |
| `item_id` | √ | 必须等于所在目录名（脚本会核） |
| `classes` | √ | 出现过的类别，取自 §5 的白名单 |
| `damages[].id` | √ | `D` + 三位数字，唯一 |
| `damages[].class` | √ | 白名单里的英文键 |
| `damages[].views[]` | √ | ≥3 条 |
| `views[].photo` | √ | **原图文件名**（与 `00_photo/<item>/` 一致） |
| `views[].polygon` | √ | 原图**像素坐标**的多边形，≥3 点，闭合不必重复首点 |
| `views[].difficulty` | — | `clear` / `unclear`；统计时把 `unclear` 单列，别混进主指标 |

**为什么用多边形而不是掩膜 PNG**：多边形可读、可复核、可 diff，出错误一眼看得出；
掩膜 PNG 只能靠肉眼看图，十处以上就没法查了。管线读入后再栅格化，成本可忽略。

## 5 类别白名单（只收这四类）

| key | 中文 | 判读要点 | 不收的情形 |
|---|---|---|---|
| `crack` | 裂隙 | 线状、有深度阴影、跨材质连续 | 表面划痕、彩绘笔触、器形棱线 |
| `detachment` | 起翘 / 脱落 | 边缘有隆起或缺失，露出下层 | 单纯的颜色变浅（那是变色） |
| `efflorescence` | 泛碱 / 盐析 | 白色粉状或结壳，多在水线/接缝 | 高光、灰尘、补配材料 |
| `loss` | 缺失（结构性） | 整块形体缺失，边界锐利 | 局部剥落小块（归 `detachment`） |

**歧义处理**：拿不准的**不标**，或在 `note` 里写「存疑」。宁可少 2 处，
不要把「不确定」混进训练集——那等于教模型学噪声。

## 6 拍完自检（必跑，30 秒）

```bash
.venv_lab\Scripts\python.exe scripts\check_damage_labels.py <标注包根> --project <项目根>
```

脚本会核（每条都对应上面某一节）：

| 检查 | 不过的后果 |
|---|---|
| `labels.json` 版本 / 必填字段 | 拒绝加载 |
| `item_id` 与目录名一致 | 拒绝加载 |
| 每处病害视角数 ≥3 | 该处标记为**不足**，不进训练集 |
| 视角最大夹角 ≥40° | 该处标记为**同机位**（等于只有一个视角） |
| 每张 view 的照片存在、多边形在画幅内 | 硬失败 |
| 每张 view 在 `capture_meta` 里有位姿 | 硬失败（否则反投影做不了） |
| 每类 ≥10 处、≥3 类 | 报告「样本不足」，给差距数 |

## 7 验收判据（能不能开工，看这张表）

| 判据 | 门槛 | 不达标怎么办 |
|---|---|---|
| 有效病害处数（视角足 + 有全部位姿） | ≥30 | 再拍 |
| 类别数 | ≥3 | 补拍缺的类别 |
| 每类处数 | ≥10 | 补拍该类 |
| 照片能跑通 S1（30/30 台可用） | 是 | 回 `采集规范-色卡与ArUco.md` §3 查光照/重叠 |

四项全过 → 可以开 S0。任何一项不过 → 开出来的模型只能做演示，不能写进论文。

## 8 与管线的对应关系

| 阶段 | 读什么 | 做什么 |
|---|---|---|
| M4 | `00_photo` + `capture_meta` | 位姿 / `pixel_scale` / Z-buffer（已有） |
| X3 无监督 | 图集 + 掩膜 | 出「待复核处数」（已有，**不是病害类别**） |
| X3 语义（待做） | `labels.json` + M4 位姿 | 多边形 → 反投影 → 逐纹素加权票决 → UV 类别图 → 按纹素积分 3D 面积 |

**目前 `damage/` 不进 `阶段成果/`**：标注是**外部输入**（和 `00_photo` 同级），
先把数据跑通再决定要不要并进 `paths.STAGE_DIRS`——并入要动目录清单与核验器
（23 项），在一条真实标注都没有之前不值得。

## 9 已知限制

- 本规范只管**单期**（一次采集）。时序追踪（X4）要两期，另议。
- 类别白名单刻意只收 4 类：类越多每类样本越薄，30 处撑不起 6 类。
- 多边形标注在**原图**坐标，与 `photos_small`（2400 长边）不同——管线读入时按
  `pixel_scale` 换算，不要手工缩放后存进去（那个坑的记录：直索引导致颜色全取
  左上角 53% 且无报错）。
