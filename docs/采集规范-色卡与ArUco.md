# 文物三维采集规范：色卡与 ArUco 标记

> 版本 r20 · 2026-11-02 · 适用于 H3D 1.1.14
> 本文的每个数字都来自代码，不是经验估计。引用位置标在括号里。

## 0. 这份规范解决什么问题

H3D 的色彩能力（X2 色差测量）与纹理质量（M4 融合、X3 异常筛查）全部卡在
**同一件事**上：照片之间色彩不统一。真机实测：

| 现象 | 数字 | 来源 |
|---|---|---|
| 同一纹素在不同相机下的颜色离散度 | `multiview_color_std = 32.67`（0~255） | 真机 M4 |
| 纹理上岛与岛之间明暗跳变 | 肉眼可见 | 裁图复核 |
| 把纹理抹平色调后 X3 异常 | **0.52% → 0.11%（降 79%）** | 判据探针 |

也就是说：**当前的「异常」里八成是色彩不统一，不是文物病害。** 逐相机曝光
归一化只能补 11%，剩下的是白平衡——**必须靠采集时校色**。

## 1. 器材清单

| 器材 | 规格 | 为什么必须这样 |
|---|---|---|
| 色卡 | **X-Rite ColorChecker Classic（24 色，4×6）** | 代码内建参考值是 24 色<br/>（`colour/__init__.py: COLORCHECKER24_SRGB`） |
| ArUco 标记 | **DICT_4X4_50，id = 1 / 2 / 3 / 4** | 字典与 id 写死在<br/>`checker_locator.py:38` |
| 打印基材 | 哑光相纸，**不反光** | 高光会让色块取值偏亮，ΔE 直接失真 |
| 直尺/卡尺 | 精度 1 mm | 量标记位置用（见 §2） |

标记**至少 3 个**能被检测到（`min_aruco = 3`），但**4 个才做透视校正**——
斜拍时 3 点只能做仿射，色卡边缘会偏。**按 4 个准备。**

## 2. 色卡与标记的几何（关键，别跳）

代码把 4 个 ArUco 标记的**中心**映射到色卡的**四个角**，再按 4×6 网格反投
取色。所以标记位置必须是**已知且固定**的，否则 24 个色块全部错位。

### 2.1 约定

```
        [1]                          [2]
         ●                            ●
              ┌──────────────────┐
              │ ▢ ▢ ▢ ▢ ▢ ▢      │
              │ ▢ ▢ ▢ ▢ ▢ ▢      │   4 行 × 6 列 = 24 色块
              │ ▢ ▢ ▢ ▢ ▢ ▢      │
              │ ▢ ▢ ▢ ▢ ▢ ▢      │
              └──────────────────┘
         ●                            ●
        [3]                          [4]
```

- **标记中心落在色卡外框外侧 `0.5 个色块宽` 处**（对角方向）。
  代码默认 `marker_margin = -0.5`（`checker_locator.py:24`，负号表示在外侧）。
- 设色块边长 `w`，则标记中心到最近的两个色卡边的距离各为 `0.5w`。
- **四个标记必须共面且贴平**（不能翘起），否则单应解出来是歪的。

### 2.2 为什么不能贴在色块上

看上去「贴在角色块中心」最省事，但那样会**遮掉 4 个色块**，剩下 20 个。
而代码要求 24 个（`colour/__init__.py:72` 会校验数量与内建参考值匹配）。
所以**只能贴外侧**。

### 2.3 id 顺序

`1 → 左上`、`2 → 右上`、`3 → 左下`、`4 → 右下`。

代码实际按**图像坐标**重新判定 tl/tr/bl/br（`argmin(sum)` 等），所以贴反了也能
自愈——但**不要依赖这个**：斜拍 + 贴反时，判定可能出错。按上图贴。

## 3. 拍摄设置（比色卡摆放更容易翻车）

| 项目 | 要求 | 原因 |
|---|---|---|
| **白平衡** | **手动锁定**（如 5000K 或 5500K），全程不变 | 自动白平衡会让每张图的色温不同，色卡只能校正一张 |
| **曝光** | **M 档固定**（光圈/快门/ISO 不变） | 自动曝光 = 每张亮度不同 = `multiview_color_std` 居高不下 |
| 自动 HDR / 美颜 / 畸变校正 | **全部关闭** | 会非线性改变像素值，色卡校不准 |
| 光源 | 全程同一组、同一位置，**不要中途开关灯** | 一次采集内光照必须稳定 |
| 偏振片 | 有则用（尤其釉面/漆面），并全程保留 | 去高光；中途取下会改变色彩 |

## 4. 色卡怎么摆、拍几张

### 4.1 位置

- 色卡必须与文物**处于同一光照平面**（同一组灯照到的位置，不放在阴影里）。
- 色卡**不能有镜面高光**，也不能被文物遮挡。
- 色卡在画面中的占比：**1/5 ~ 1/3**。太小取不到足够像素（代码取色半径只有
  4 px，`checker_locator.py:79`），太大会挤掉文物。

### 4.2 拍几张（两种方案，按你的采集条件选）

**方案 A：每个机位都放色卡**（推荐，最稳）

- 色卡每张都在画面边缘，占 1/5。
- 代价：每张照片的有效文物像素变少。
- 好处：逐张校准，任何光照漂移都能被吃掉。

**方案 B：每个「拍摄批次」拍一张色卡测试照**

- 「批次」= 同一组灯 + 同一相机设置 + 同一距离档位。
- 该批次其余照片**沿用完全相同的设置**（白平衡/曝光都不许变）。
- 好处：文物占满画面。
- 风险：如果中途有人调了灯或换了角度导致进光量变化，这批照片就没有校色依据。
  **换灯/换位置就必须重拍一张色卡照。**

> 判断标准很简单：**只要你调了相机或灯，就重拍一张色卡。** 没调就不用。

## 6. 采集后自检（30 秒，别等建模完才发现）

对任意一张带色卡的图跑：

```python
from h3d.colour.checker_locator import locate_colorchecker_robust
p = locate_colorchecker_robust("你的照片.jpg")
print("检测到色块：", None if p is None else p.shape)   # 要 (24, 3)
```

- 返回 `None` → 标记没检测全（数量/尺寸/对比度问题），**这张图不能用于校色**。
- 返回 `(24, 3)` → 把色块值贴到 `h3d.colour.run()` 看 `mean_de`：
  - `mean_de < 3`：色彩可信，可以做 ΔE 分析
  - `3 ~ 6`：可做趋势比较，但不能报绝对值
  - `> 6`：校色失败，检查高光/白平衡/标记位置

> 标定没做、或做了但 `mean_de` 大，**都不要用这批数据报 ΔE 数字**。
> ADR-0008 记过一次教训：那个看着像「色偏 21.42」的数，其实是单位错，
> 它稳定复现了 0.0007 的误差——错得很像真的。

## 7. 已知限制（这一版还做不到的）

1. **定位器没有在真色卡上验证过**。几何已在 2026-11-02 修正（格中心 `+0.5`、
   标记偏移参数化），但没拍过真卡，第一次实拍后要核对取色是否落在色块中心。
2. **只解决曝光与白平衡，不解决镜头渐晕**。画面边角的暗角会让同一色卡的不同
   位置读数不同；如发现边角色块明显偏暗，考虑采集时关闭机内暗角校正并在后期
   单独处理。
3. **不做反射率恢复**。严格的光谱重建需要分光测色仪，本系统只做 sRGB 空间的
   相对校准，用于「不同批次之间的可比性」，不是绝对色度测量。
4. **灰卡不在流程里**。若你有 18% 灰卡，可作为额外的曝光基准，但当前代码不读它。
