# 方法学：让自动化系统的数字可信

> 2026-11-01 至 2026-11-03 的三天里，H3D 全部改动都不是"加功能"，而是让已经到了
> 1.1.13 版本、测试全绿、报表齐全的系统**不再输出似是而非的数字**。
> 本文把这三天里被真机数据推翻的判断逐条记下来，作为论文「方法」与「讨论」两章
> 的素材。文中每个数字都来自 `docs/adr/` 与 `CHANGELOG` 的记录，可复查。

## 1 问题的性质

自动化建模系统的危险不在于"跑不起来"——跑不起来会立刻被发现。危险在于
**跑起来了、报表齐全、数字看着合理，但数字与事实无关**。

本文记录的五个案例都属于后者，且有一个共同特征：**错的那一版比对的更容易让人相信**。

## 2 五种失效模式（均有真机证据）

### 2.1 自报指标与事实不符

`align_points_to_mesh` 返回的 `rmse_after = 0.0968` 看着漂亮，实际把几何推离了
50 倍（中位距离 0.036 → 1.917）。原因是这个残差：①只统计 p90×2 以内的对应
（本身被截断）；②算的是**变换前**的距离（滞后一步）；③无法区分"收敛到正确答案"
与"两边一起漂到一个自洽的错误位置"。

**纪律**：自报指标不能作为验收依据，必须有外部可核对的量。

### 2.2 单位与坐标系约定错

- X2 的色差报 `ΔE = 21.42`：`colour.run` 要 sRGB 0~1，调用点喂 0~255，全部被
  钳成纯白。标准值 ×255 落在同一路径上报 21.4193——**错得很稳定，误差 0.0007**。
- `capture_meta.json` 存的是原生 COLMAP 格式（`R_co` + `tvec`，前方 +Z），
  管线按「`t` = 相机中心、前方 −Z」读，等于把 `tvec` 当成相机位置。

**纪律**：单位与约定必须由**数据本身**判定，不能靠"读文档时记得"。后者的判据是
用 COLMAP 自己的 `points3D.txt` 试投：原生解释 30/30 台 95.6%、管线解释 5.25%。

### 2.3 判据在垃圾数据上触发

这是最隐蔽的一类。位姿读错后，30 台相机里 19 台一条纹素都投不上，剩下 11 台
**偶然**投上，于是 `in_frame_fraction` 报出 86.7%——「几何已在画幅内，无需对齐」
这道闸门**正当放行**。判据逻辑完全正确，输入是垃圾。

后果是一整串"合理"的数字：coverage 56.81%、岛内填充 87.64%、X3 异常 0.31%/4 处。
全部作废。

**纪律**：任何以 X 为输入的判据，都必须先验证 X 本身可信。位姿类预检尤其如此。

### 2.4 候选可用性随机

对齐走「控制点优先、失败才回退自动 ICP」。而分支取决于**磁盘上有没有文件**：
一次成功的 ICP 会把控制点导出到 `00_ctrl/`，下次运行就走控制点那条（实测解出
90° 旋转错）。于是同一输入连跑三次，`normal_visible` = 0.96 / 0.69 / 0.58。

**纪律**：候选的生成必须是无条件的。判据再好，没有可比对象也等于没有。

### 2.5 误诊文案把排查引向错误方向

`normal_visible_fraction` 偏低时，日志断言「网格法线**局部方向不一致**（常见于
碎块化重建）」。实测：相邻面法线反向只有 **0.08%**，网格法线是全局一致的；
真正原因是对齐把几何搬错了位置。

**纪律**：诊断文案必须能被数据证伪。现在加了 `normal_flip_fraction` 作为配套
判据，文案按它分三支，会直接说出「法线是好的，问题在对齐」。

## 3 四条判据纪律

1. **外部可核对量优先于自报量。** 包围盒对角线比、源→目标单向中位距离、
   COLMAP 稀疏点的可投射性、纹理图集的着色率——这些都不依赖被测组件自己的说法。

2. **判据要能区分"像"与"对"。** `in_frame_fraction` 只判「投影落在画幅矩形内」，
   不判「落在文物上」，因此它区分不了 0° 与 90° 的旋转误差（两者都报 1.0）。
   能区分的是「对齐后有多少面能被相机正面看到」：0.98 vs 0.69。

3. **多候选 + 显式判据 > 单候选 + 事后闸门。** 闸门只能拦"离谱"，拦不住
   "看着合理但错"。三天里三次撞上同一模式：0.43 倍尺度、90° 旋转、
   精化阶段 0.52 的塌陷——每一个都通过了当时所有的闸门。

4. **先量再改，对照实验不可省。** 三天里五次"先量"，其中四次推翻了我自己
   之前的判断（见第 5 节）。有一次没量就动手（填岛内空洞），做完对目标贡献为 0。

## 4 一次典型的错误链条

以「M4 覆盖率只有 21%」为例，它被三层误判套住：

```
位姿读错（19/30 台投空）
  └─ in_frame 报 86.7% → 「已在画幅内，跳过对齐」
       └─ 覆盖率 21% 被归因为「采集不足 / 法线问题」
            └─ 修法选错（去查法线、去填洞）
```

修正第一环（位姿约定）之后，后面三环自动消解：对齐成为必需且可解，
`normal_visible` 0.72 → 0.96，覆盖率 0.5865。

**上游一个约定错误的传播成本，远高于它本身。**

## 5 五次"先量后推翻"

| # | 我原本的判断 | 实测结果 | 处置 |
|---|---|---|---|
| 1 | X1 的 177 mm 是尺度问题 | 合成已知形变标定线性度 1.000，尺子一直对；根因是两源混为一期（互最近邻中位 5541 mm） | 加两期同源闸门 |
| 2 | 岛间色调跳变 = 缺色卡 | 19 台相机根本没投上、11 台又是错位姿；修正后 `color_std` 32.67 → 14.42 | 归因改为「先保证位姿，再谈光度」 |
| 3 | 减少 UV 岛数能降 X3 噪声 | 调 xatlas 参数岛数只动 ±15%；把网格做粗岛数 −69% 但 X3 **差 4 倍** | 不改（ADR-0015） |
| 4 | X3 图斑是 UV 岛边界伪影 | 图斑在岛边界上的富集 **0.8×**（反富集），0 处落在碎岛 | 假设排除（ADR-0016） |
| 5 | 填岛内空洞能改善 X3 | 填掉 12 万纹素，X3 数字**一模一样** | 保留功能但明确不是解药 |

## 6 修复前后的可比数字（同一件文物、同一套输入）

| 指标 | 修复前 | 修复后 | 备注 |
|---|---|---|---|
| `projected_cameras` | 11 / 30 | **30 / 30** | 位姿约定修正 |
| `cameras_blind` | 19 / 30 | **0 / 30** | 同上 |
| `normal_visible_fraction` | 0.7188 | **0.9617** | 对齐多初值 + 择优 |
| `coverage_ratio` | 0.6332 | 0.5865 | 下降是**变好**：不再靠背面补色 |
| `island_fill_ratio` | 0.9998 | 0.9207 | 同上 |
| `multiview_color_std` | 18.81 | **14.42** | 30 台相机全部参与 |
| X3 异常面积 | 0.6874% / 14 处 | **0.3294% / 7 处** | σ 15.65 → 14.78 |
| 同输入三次运行 | 0.96 / 0.69 / 0.58 | **逐位相同** | 候选无条件生成 |

注意 `coverage_ratio` 与 `island_fill_ratio` 的下降：修复前那 0.9998 是靠
「按 -n 补色」堆出来的（把看不见的地方也用反法线填上颜色），修复后要求真有
相机能看到。**数字变低而质量变高，是这类系统里最常见的修复形态。**

## 7 可写进论文的三条

1. **"测试绿"不构成交付依据。** 本版 1295 项单元测试在三个真机缺陷存在期间
   始终全绿——因为它们测的是"函数按我理解的方式工作"，而错误发生在
   "我的理解"这一层。

2. **口径必须写成可复查的断言，而不是注释。** 例如 `rmse_scope` 三态、
   `units_plausible`、`pose_convention`——它们让"这个数字能不能引用"成为
   机器可判的事实，而不是读者的判断。

3. **误诊的成本高于没有诊断。** 一条断言"法线不一致"的日志，让我按错误方向
   查了一整轮。现在这条日志会先说"法线是好的（反向 0.00%）"，再指向对齐。
