# 方法学：让自动化系统的数字可信

> 2026-11-01 至 2026-11-04 的四天里，H3D 全部改动都不是"加功能"，而是让已经到了
> 1.1.13 版本、测试全绿、报表齐全的系统**不再输出似是而非的数字**。
> 本文把这些天里被真机数据推翻的判断逐条记下来，作为论文「方法」与「讨论」两章
> 的素材。文中每个数字都来自 `docs/adr/` 与 `CHANGELOG` 的记录，可复查。

## 1 问题的性质

自动化建模系统的危险不在于"跑不起来"——跑不起来会立刻被发现。危险在于
**跑起来了、报表齐全、数字看着合理，但数字与事实无关**。

本文记录的九个案例都属于后者，且有一个共同特征：**错的那一版比对的更容易让人相信**。

前五例（2.1–2.5）来自第一程：判据、单位、约定层面的错。后四例（2.6–2.9）来自
第二程，性质略有不同——**代码逻辑都是对的，错在"谁来说"和"什么时候说"**：
来源靠猜、数字不定种子、结论说在决策点之后、单指标被读反。

## 2 九种失效模式（均有真机证据）

### 2.1 自报指标与事实不符

`align_points_to_mesh` 返回的 `rmse_after = 0.0968` 看着漂亮，实际把几何推离了
50 倍（中位距离 0.036 → 1.917）。原因是这个残差：①只统计 p90×2 以内的对应
（本身被截断）；②算的是**变换前**的距离（滞后一步）；③无法区分"收敛到正确答案"
与"两边一起漂到一个自洽的错误位置"。

**纪律**：自报指标不能作为验收依据，必须有外部可核对的量。

### 2.2 单位与坐标系约定错

- X2 的色差报 `ΔE = 21.42`：`colour.run` 要 sRGB 0~1，调用点喂 0~255，全部被
  钳成纯白。标准值 ×255 落在同一路径上报 21.4193——**错得很稳定，误差 0.0007**。
- `capture_meta.json` 存的是原生 COLMAP 格式（`R_co` + `tvec`，前方 +Z），
  管线按「`t` = 相机中心、前方 −Z」读，等于把 `tvec` 当成相机位置。

**纪律**：单位与约定必须由**数据本身**判定，不能靠"读文档时记得"。后者的判据是
用 COLMAP 自己的 `points3D.txt` 试投：原生解释 30/30 台 95.6%、管线解释 5.25%。

### 2.3 判据在垃圾数据上触发

这是最隐蔽的一类。位姿读错后，30 台相机里 19 台一条纹素都投不上，剩下 11 台
**偶然**投上，于是 `in_frame_fraction` 报出 86.7%——「几何已在画幅内，无需对齐」
这道闸门**正当放行**。判据逻辑完全正确，输入是垃圾。

后果是一整串"合理"的数字：coverage 56.81%、岛内填充 87.64%、X3 异常 0.31%/4 处。
全部作废。

**纪律**：任何以 X 为输入的判据，都必须先验证 X 本身可信。位姿类预检尤其如此。

### 2.4 候选可用性随机

对齐走「控制点优先、失败才回退自动 ICP」。而分支取决于**磁盘上有没有文件**：
一次成功的 ICP 会把控制点导出到 `00_ctrl/`，下次运行就走控制点那条（实测解出
90° 旋转错）。于是同一输入连跑三次，`normal_visible` = 0.96 / 0.69 / 0.58。

**纪律**：候选的生成必须是无条件的。判据再好，没有可比对象也等于没有。

### 2.5 误诊文案把排查引向错误方向

`normal_visible_fraction` 偏低时，日志断言「网格法线**局部方向不一致**（常见于
碎块化重建）」。实测：相邻面法线反向只有 **0.08%**，网格法线是全局一致的；
真正原因是对齐把几何搬错了位置。

**纪律**：诊断文案必须能被数据证伪。现在加了 `normal_flip_fraction` 作为配套
判据，文案按它分三支，会直接说出「法线是好的，问题在对齐」。

### 2.6 「有输入」被当成「有基准」

M5 判「坐标有没有米制语义」只靠一句：

```python
metric_units = bool(task.raw_paths)
```

`00_raw` 里**有个文件**就被当成**有激光基准**。于是报表印「激光扫描 / 中误差
3.21 mm」，这个数进 5 mm 毫米门，然后被抄进论文。可那个文件完全可能是**别的软件
照片重建**出来的（Metashape / RealityCapture 导出）——坐标是任意单位，那个「mm」
不成立。

之前补过两个自证检测（`laser_unverified` / `dual_source_duplicate`），但它们都是
**事后推断**：必须同时存在 SfM 稠密模型才判得出。而用户自己知道 `00_raw` 里放的
是什么——界面上却没有地方说。

后果实测（`batch3`，同一份数据只改一个声明，`scripts/probe_data_source.py` 可复现）：

| 声明 | 中误差列 | 口径列 |
|---|---|---|
| `auto`（默认，按有文件即米制） | 87.4019 | 不判门（单位存疑） |
| `photogrammetry`（用户声明照片重建件） | **N/A** | 无量纲（用户声明照片重建件） |

注意这里的 87.4019 与 87.42 是两个层次的东西：后者是**修复前**某一次运行的读数
（下一次可能读到 87.01，见 2.7），前者是定种子之后**可复现**的那个值。
同一张表里混用两种口径，正是本文要治的病。

修法不是"加一个开关"，而是把**判断权交回用户**，同时钉一条硬红线：
**证据压过声明**。声明 `laser` 而 M1 判出 `raw_looks_like_sfm`（00_raw 与 SfM
稠密近乎重合）时，仍不主张米制，并落 `declared_source_conflict` + WARN。

**纪律**：缺省猜测必须能被用户声明覆盖；但声明不能覆盖证据——否则勾一下就能把
自证数据包装成米制结果，比没有这个功能更糟。

### 2.7 数字不可复现：小于 1% 的漂移

同一份输入、同一个分支、连跑三次，M5 的中误差是 **86.7811 / 87.4155 / 87.0148**。

根因：`mesh.sample_points_uniformly(n)` **没有 `seed` 参数**（Open3D 0.19 的签名
就只有 `number_of_points` 与 `use_triangle_normal`），它用进程级随机源。每次重
采样到不同的表面点，最近邻距离分布就变。

这个坑 **2026-11-03 已经踩过一次**（对齐精化的 `_REFINE_SEED`），当时只修了那一条
路径。M5 这条因为「差异 < 1%」被漏掉——而**小于 1% 的漂移恰恰是最危险的一档**：
小到不会触发任何断言，又大到让两天前的报表对不上。

修法不是"在 M5 里也调一下种子"，而是把入口收敛成一个函数：

```python
h3d.io.sample_surface(mesh, n, seed)   # 「定种子 + 采样」绑死，没法只做一半
```

修后 `auto` 与 `laser` 两个等价分支**逐字相同**（87.4019），跨进程重跑也相同。

一天后再扫源码，还剩四处「先定种子、后自己采样」的两语句形式。其中
`alignment_quality` 里那行种子调用**是空的**——那里用的是 `np.linspace` 索引抽样，
根本不碰 Open3D 随机源，换多少次种子结果一字不差。它让读者以为「这段依赖随机
采样，别动种子」。

**纪律**：不可复现的数值不能作为结论。「看起来有约束、实际没有」比缺失更糟——
下一个人会为了保护一个不存在的约束而绕路。

### 2.8 时序错位：说清楚了，但说晚了

`00_raw/<件>/` 只有一份点云时，M2 走**单站直通**（恒等落盘、十几毫秒），日志写
「M2 完成」，界面灯变绿。**用户的结论是「配准成功」**——而 FPFH + RANSAC + ICP
一次都没跑过。

报表侧早就写清了这件事（`identity` + `identity_reason=single_scan` →「配准节点在
本件没有被执行过」）。但那是**跑完之后**才读得到的东西；人是在**开跑前**形成印象的，
很少有人会回头翻报表去推翻自己刚才的印象。

单站本身不是缺陷：中小型文物常只有一站扫描（真机 `relic_001` 与 `batch3` 三件
**全部是 1 份几何**）。要修的只是「没说」，所以措辞落在「这是正常终态，但精度
不能由本件背书」，不是「出错」。

**纪律**：结论要在**决策点之前**说。事后文档再完整，也替代不了事前一句提示。

### 2.9 单一指标会被读反

报表里的 `multiview_color_std`（多视角色差）看起来是个"越小越好"的质量指标：

| 情况 | `multiview_color_std` | 实际 |
|---|---|---|
| 10 台相机，色调一致 | 小 | 真·多视图融合，稳 |
| **1 台相机**硬投影 | **恒等于 0** | 没有任何冗余，接缝/漏色无从缓解 |

两种情况的色差都是"小"，意义完全相反——**最该报警的情况恰好是这个指标最漂亮的
情况**。而能配对的那个量（纹理重叠度）在设计书 §17.3 里写着，代码里一直是
`"overlap": None`，挂了几个版本。

补上之后真机（`D:/h3d_relic_test`，30 张照片 / 11 台可用）才读得出真问题：

| 指标 | 值 |
|---|---|
| `texture_overlap` | 5.77 台/纹素 |
| `texture_multi_view_ratio` | 98.4% |
| `multiview_color_std` | 40.44 |

重叠度很高（98.4% 的纹素有冗余），色差照样 40.44 —— 说明**不是"看不到"，而是这
11 台相机之间色调差得太多**。只看色差会去调融合权重；加上重叠度就知道根子是
可用相机太少（19 台位姿无效，2.2 节的老账）。

**纪律**：任何"越大越好 / 越小越好"的单指标，都要有一个**反向情形同样满足它**的
配对量，并且两个数必须一起出现在报表上。

## 3 六条判据纪律

1. **外部可核对量优先于自报量。** 包围盒对角线比、源→目标单向中位距离、
   COLMAP 稀疏点的可投射性、纹理图集的着色率——这些都不依赖被测组件自己的说法。

2. **判据要能区分"像"与"对"。** `in_frame_fraction` 只判「投影落在画幅矩形内」，
   不判「落在文物上」，因此它区分不了 0° 与 90° 的旋转误差（两者都报 1.0）。
   能区分的是「对齐后有多少面能被相机正面看到」：0.98 vs 0.69。

3. **多候选 + 显式判据 > 单候选 + 事后闸门。** 闸门只能拦"离谱"，拦不住
   "看着合理但错"。三天里三次撞上同一模式：0.43 倍尺度、90° 旋转、
   精化阶段 0.52 的塌陷——每一个都通过了当时所有的闸门。

4. **先量再改，对照实验不可省。** 第一程五次"先量"，其中四次推翻了我自己
   之前的判断（见第 5 节）。有一次没量就动手（填岛内空洞），做完对目标贡献为 0。

5. **指标要配对读。** 见 2.9：`multiview_color_std` 小既可能是"融合得稳"，也可能是
   "只有一台相机在看"。凡是"越大越好/越小越好"的单指标，都必须有一个**反向情形
   同样满足它**的配对量，且两个数一起进报表。同类还有：`coverage_ratio` 与
   `island_fill_ratio`（后者高而前者低 = 岛划分碎）、`rmse_mm` 与 `rmse_reliable`
   （后者 False 时前者的毫米数没参与判门）。

6. **同一个判定只许有一处实现。** 本项目六类"副本"全部漂过：阶段清单（八份）、
   阶段目录名（登记表之外散落 147 处）、`accuracy.csv` 列名（表头与核验器各一份）、版本号（三处）、
   测试夹具（自己写一份假的）、口径文字（`quality.run` 与 `build_report` 各写一遍）、
   采样入口（四处直调）。

   而**漂移方向不是随机的**：总是往「该报的不报」「数字好看」那边漂。
   阶段清单少一个 X3 → 完成率分母少一个而不报错；口径文字漏一档 → 报表把"用户
   声明"写成"系统推断"；采样漏一处种子 → 数字悄悄变一点点。

   纪律的落点是**守卫测试**，不是文档：`tests/test_stage_dirs_single_source.py`、
   `tests/test_sampling_single_source.py`、`tests/test_version_single_source.py`。
   写在 ADR 里的纪律只约束写 ADR 的那个人；守卫约束所有人——包括三个月后的自己。

## 4 一次典型的错误链条

以「M4 覆盖率只有 21%」为例，它被三层误判套住：

```
位姿读错（19/30 台投空）
  └─ in_frame 报 86.7% → 「已在画幅内，跳过对齐」
       └─ 覆盖率 21% 被归因为「采集不足 / 法线问题」
            └─ 修法选错（去查法线、去填洞）
```

修正第一环（位姿约定）之后，后面三环自动消解：对齐成为必需且可解，
`normal_visible` 0.72 → 0.96，覆盖率 0.5865。

**上游一个约定错误的传播成本，远高于它本身。**

## 5 八次"先量后推翻"

| # | 我原本的判断 | 实测结果 | 处置 |
|---|---|---|---|
| 1 | X1 的 177 mm 是尺度问题 | 合成已知形变标定线性度 1.000，尺子一直对；根因是两源混为一期（互最近邻中位 5541 mm） | 加两期同源闸门 |
| 2 | 岛间色调跳变 = 缺色卡 | 19 台相机根本没投上、11 台又是错位姿；修正后 `color_std` 32.67 → 14.42 | 归因改为「先保证位姿，再谈光度」 |
| 3 | 减少 UV 岛数能降 X3 噪声 | 调 xatlas 参数岛数只动 ±15%；把网格做粗岛数 −69% 但 X3 **差 4 倍** | 不改（ADR-0015） |
| 4 | X3 图斑是 UV 岛边界伪影 | 图斑在岛边界上的富集 **0.8×**（反富集），0 处落在碎岛 | 假设排除（ADR-0016） |
| 5 | 填岛内空洞能改善 X3 | 填掉 12 万纹素，X3 数字**一模一样** | 保留功能但明确不是解药 |
| 6 | 报表里的 87.0 mm 是个"精度结论" | 同一输入同一分支连跑三次：86.78 / 87.42 / 87.01 | 入口定种子（ADR-0020） |
| 7 | `batch3` 是有激光基准的米制数据 | 声明为照片重建件后，中误差列从 86.78 mm 变 **N/A**——它本来就不该有毫米 | 声明 + 证据压过声明（ADR-0020） |
| 8 | `color_std` 40.44 说明多视图融合做得差 | 同件 `texture_overlap` 5.77、`multi_view_ratio` 98.4%——融合有充足冗余，根子是可用相机只有 11/30 | 补重叠度，两数配对读（ADR-0022） |

第 6–8 条的共同点：**错不在算法，在于我没区分"数字是多少"和"这个数字能不能引用"**。

## 6 修复前后的可比数字（同一件文物、同一套输入）

| 指标 | 修复前 | 修复后 | 备注 |
|---|---|---|---|
| `projected_cameras` | 11 / 30 | **30 / 30** | 位姿约定修正 |
| `cameras_blind` | 19 / 30 | **0 / 30** | 同上 |
| `normal_visible_fraction` | 0.7188 | **0.9617** | 对齐多初值 + 择优 |
| `coverage_ratio` | 0.6332 | 0.5865 | 下降是**变好**：不再靠背面补色 |
| `island_fill_ratio` | 0.9998 | 0.9207 | 同上 |
| `multiview_color_std` | 18.81 | **14.42** | 30 台相机全部参与 |
| X3 异常面积 | 0.6874% / 14 处 | **0.3294% / 7 处** | σ 15.65 → 14.78 |
| 同输入三次运行 | 0.96 / 0.69 / 0.58 | **逐位相同** | 候选无条件生成 |
| M5 同输入三次运行（mm） | 86.78 / 87.42 / 87.01 | **逐位相同（87.4019）** | 采样入口定种子 |

注意 `coverage_ratio` 与 `island_fill_ratio` 的下降：修复前那 0.9998 是靠
「按 -n 补色」堆出来的（把看不见的地方也用反法线填上颜色），修复后要求真有
相机能看到。**数字变低而质量变高，是这类系统里最常见的修复形态。**

## 7 可写进论文的五条

1. **"测试绿"不构成交付依据。** 缺陷存在期间，1200–1400 项单元测试始终全绿——
   因为它们测的是"函数按我理解的方式工作"，而错误发生在"我的理解"这一层。
   第二程的四类缺陷（2.6–2.9）更是如此：它们的共同点是**代码逻辑正确、
   语义错位**，测试再密也测不出来，只有把两次运行的数字逐字比、或者把同一份
   数据换个声明再看一遍，才会浮出来。

2. **口径必须写成可复查的断言，而不是注释。** 例如 `rmse_scope` 三态、
   `units_plausible`、`pose_convention`、`metric_units_reason`——它们让"这个数字
   能不能引用"成为机器可判的事实，而不是读者的判断。

3. **误诊的成本高于没有诊断。** 一条断言"法线不一致"的日志，让我按错误方向
   查了一整轮。现在这条日志会先说"法线是好的（反向 0.00%）"，再指向对齐。

4. **判断权交回用户，但证据压过声明。** 系统不可能知道 `00_raw` 里放的是什么，
   所以来源必须可声明；但声明一旦能覆盖证据，它就成了绕过检查的后门。这条张力
   在 2.6 里表现为一个具体开关，在更一般的系统里表现为"人机分工"。

5. **纪律的载体是守卫测试，不是文档。** 写在 ADR 里的纪律只约束写 ADR 的那个人。
   本项目把四条纪律变成了可执行的守卫（阶段目录名、版本号、采样入口、报表列名），
   其中采样那条在加守卫的**当天**就抓出四处残留——包括一处"看起来有约束、
   实际没有"的空种子调用。人眼扫过的那几遍都没看见它。
