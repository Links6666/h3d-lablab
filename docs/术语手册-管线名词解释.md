# H3D 管线术语手册

> 面向非专业读者。收录本管线里真实出现过、且不容易靠字面猜出意思的名词——
> 计算机、软件工程、摄影测量、三维几何、统计与算法各占一部分。
> 每一条都写三件事：**它是什么**（尽量用日常类比）、**在这个管线里干什么**
> （落到具体阶段或指标）、**有多难**（见下）。术语全部来自 `GLOSSARY.md`、
> `docs/adr/` 与 `src/h3d/` 的实际实现，没有为了凑数编的词。

## 0 怎么用这份手册

### 0.1 难度标记

| 标记 | 含义 | 读法 |
|---|---|---|
| ★★ | 名字唬人，一说就懂 | 看一眼即可 |
| ★★★ | 需要一句话解释 | 本手册给的就是那一句 |
| ★★★★ | 需要专业背景，光知道定义不够 | 建议连着「为什么这么设计」一起读 |

**星多不代表更重要。** 比如「包围盒对角线」只有 ★★，但管线上几乎所有阈值都按它
折算；反过来「齐次变换矩阵」是 ★★★，多数时候你只需要知道它是个 4×4 的表。

### 0.2 三条通用约定

1. **凡是带尺寸的阈值，都按包围盒对角线的比例给**，不写死毫米。因为管线要处理
   5 cm 的小件和 30 cm 的大件，写死 0.02 m 在一个件上能用、在另一个件上必然失准。
2. **凡是有两个名字的阶段，以报表上的名字为准**（见 14.2）。你按指南写论文，
   代码里叫什么不影响结论。
3. **凡是「看起来合理」的数字都要问一句前提**。这套管线里绝大多数返工不是因为
   算法算错，而是因为数字算对了但前提不成立（见第 10 章）。

## 1 三维数据的基本形态

M1–M3 处理的都是「点」和「面」。这一章的名词在报表里不一定出现，但读日志一定会撞上。

| 术语 | 它是什么 | 在这个管线里干什么 |
|---|---|---|
| **点云** ★★ |（Point Cloud）一大堆只有坐标的点，没有面、没有厚度。像撒了一把沙子，每粒沙子记一个位置| 全流程的**输入形态**。激光扫描仪、照片重建出来的都是点云，存在 `00_raw/`，由 M1 清洗 |
| **三角网格** ★★ |（Triangle Mesh）顶点 + 三角形面片，组成一张有表面的「皮」。像给那堆沙子绷上一层薄膜| M3 的产物，M4 把照片贴在这层皮上。所有交付格式（PLY/OBJ/GLB）本质都是它 |
| **顶点 / 面片** ★★ |（Vertex / Face）顶点是一个角点（三个数 x,y,z）；面片是三个顶点围成的三角形| 贴图按面片逐块光栅化；配准按顶点算距离 |
| **法线**（Normal）★★★ | 每个点或面「朝外」的方向，是个单位向量。相当于在表面插一根垂直于表面的小针 | 三处关键用途：①泊松重建要知道哪边是外；②贴图要判断相机是否正对；③配准要判断方向有没有被解反（第 2 章） |
| **法线定向** ★★★★ |（Orient Normals）让所有法线**一致地**指向外侧。原始点云的法线符号是乱的，一半朝里一半朝外| M3 重建前必做。不做的话泊松会把模型「翻里朝外」，表面还在但内外反了 |
| **质心**（Centroid）★★ | 所有点的平均位置，一个点 | 判断「法线是否朝外」时以它为参考；绕轴翻转也绕它转 |
| **包围盒**（AABB）★★ | 能把这个模型装进去的最小长方体（边与坐标轴平行） | 给所有阈值提供尺度基准；也是判断「这个模型有多大」的唯一稳定量 |
| **对角线** ★★ |（bbox diagonal）包围盒两个对角的距离| **整个管线的尺子**。`voxel_down_sample`、`fpfh_radius`、`icp_distance` 都是「对角线 × 系数」 |
| **体素**（Voxel）★★★ | 三维的「像素」：把空间切成小方块，每个方块只留一个点 | 体素降采样把几百万点压到几十万，让配准跑得动且密度均匀 |
| **KD-Tree** ★★★★ | 一种空间索引结构，能把「找最近的 k 个点」从逐个比变成二分查找 | 最近邻查询全走它（Open3D 内部封装）。没有它，一次配准要跑几小时 |
| **最近邻 / 双向互最近邻** ★★★ | 前者是「离我最近的点」；后者要求「你是我最近的，我也是你最近的」才算一对 | X1 判定两期是不是同一件文物时，用的就是**双向**互最近邻的中位距离（单向会被单向偏移骗） |
| **点间距**（spacing）★★★ | 相邻点之间的典型距离。点云疏密不同，这个数差很多 | 判断「点云够不够密」；给滤波器定半径；也是尺度自适应的输入之一 |
| **飞点 / 离群点**（Outlier）★★ | 孤零零飘在主体外面的点，通常是反光、灰尘、边缘噪声造成的 | 必须清掉：一个飞点能把包围盒对角线从 6.19 撑到 47.83，让所有比例阈值同时失效 |
| **统计离群点去除**（SOR）★★★ | 按「每个点到它 k 个邻居的平均距离」排序，把明显偏大的删掉 | M1 默认降噪。参数是邻居数 20、标准差倍数 2.0 |
| **半径离群点去除**（ROR）★★★ | 在半径 r 内邻居少于 n 个的点，删掉 | SOR 的补充。对「稀疏的片状残留」更有效，M1 也提供但默认关 |
| **密度分位裁剪** ★★★ |（density_ratio）泊松重建会给每个面片一个「支持密度」，把支持度最低的 5% 面片裁掉| M3 的默认后处理。不裁的话，模型外面会挂一层薄薄的「雾面」 |

## 2 变换、配准，以及"对没对"

配准（M2）是这套管线里最容易出错、也最难自证的一步。这一章的名词必须分清，
因为「贴合得好」和「方向对」是两件事。

| 术语 | 它是什么 | 在这个管线里干什么 |
|---|---|---|
| **刚体变换**（Rigid）★★★ | 只旋转 + 平移，不改变形状和大小。像把一件东西拿起来转个方向放下 | 两站点云配准的目标：求一个刚体变换，把 A 站搬到 B 站的位置 |
| **相似变换** ★★★★ |（Similarity）刚体变换 + 一个统一的缩放系数，共 7 个自由度（3 旋转 + 3 平移 + 1 尺度）| 照片重建件与激光件之间**尺度不同**，必须允许缩放，否则永远配不上 |
| **齐次变换矩阵**（4×4）★★★ | 把旋转、平移、缩放装进一个 4 行 4 列的表，乘一次就完成整个变换 | 代码里所有位姿都是它。最后一列的前三行是平移量，左上 3×3 是旋转 × 尺度 |
| **尺度因子**（scale）★★★ | 相似变换里那个「放大几倍」的数。1.0 = 不用缩放 | 报表里的 `scale=0.672107` 就是这个数——照片件比激光件小了三成 |
| **SVD / Umeyama 闭式解** ★★★★ | 已知 N 组对应点时，用奇异值分解直接算出最优变换，不用迭代 | 控制点约束（X2）用它。有对应点就必须用闭式解，迭代法在对应点少时会乱跑 |
| **配准** ★★★ |（Registration）把两次测量的坐标系对齐，让同一件文物在两份数据里重合| M2 的全部工作。输出一个变换矩阵 + 一组质量指标 |
| **粗配准 / 精配准** ★★★ | 粗配准先给个大概位置（差几厘米也能救），精配准再逐点磨到贴合 | M2 的两段：FPFH+RANSAC 给初值，ICP 精修 |
| **RANSAC**（随机抽样一致）★★★★ | 随机抽最少数量的点算一个模型，数一数有多少点支持它，重复很多次取支持最多的。像投票选最靠谱的假设 | 粗配准的核心。它抽的是「对应点对」，所以**必须定随机种子**，否则同一份数据两次结果不同（ADR-0024） |
| **内点 / 外点** ★★★ |（Inlier / Outlier）符合当前模型的点叫内点，不符合的叫外点| 所有配准质量指标的分母都是内点。报「内点 8 万」比报「误差 2 mm」更说明问题 |
| **fitness** ★★★ | 内点数 ÷ 总点数。0~1，越大说明重叠越多 | 配准可信度的第一指标。但它**只说明贴不贴，不说明方向对不对** |
| **inlier_rmse** ★★★ | 内点上对应点距离的均方根。越小说明贴得越紧 | 与 fitness 配对读：fitness 高 + rmse 低 = 真配上了；fitness 高 + rmse 大 = 只是重叠多 |
| **FPFH**（快速点特征直方图）★★★★ | 给每个点算一个「周围几何长什么样的指纹」，用来在另一片点云里找它的对应点 | 粗配准的特征描述子。半径取 0.02 m 量级时对中小型文物有效，太大就糊成一片 |
| **特征描述子** ★★★ |（Descriptor）把「局部形状」压成一个向量，方便比较。像给每个点发一张身份证| FPFH 就是其中一种。要求：同一处从不同角度看，指纹要接近 |
| **ICP**（迭代最近点）★★★★ | 反复做两件事：找最近点当对应、算让距离最小的变换。十几次后收敛 | 精配准。对初值敏感，初值差 30° 就可能收到错的局部极小 |
| **点到面 ICP** ★★★★ |（Point-to-Plane）比「点到点」更聪明：算的是点到**对面切平面**的距离，沿表面滑动更快| 本管线默认用它（`point_to_plane=True`）。收敛快、对采样密度不敏感 |
| **多初值** ★★★ |（Multi-start）从好几个起点各跑一次 ICP，挑最好的那个| 防局部极小。本管线用 RANSAC 解 + 绕两个主轴各转 180°，共 3 个起点 |
| **180° 翻转解** ★★★★ | 因为文物近似轴对称，「转 180° 再放回去」在几何上几乎一样贴，但方向反了 | 真实发生过的故障：120° 注入实验里 17 次有 3 次解出 179° 翻转解。**距离类判据全部放行** |
| **主轴 / PCA** ★★★ | 主成分分析：找出数据「最长的方向」。三维里就是长、宽、高三个轴 | 生成翻转候选时绕主轴转 180°；也用来判断物体是否近似轴对称 |
| **法线一致性** ★★★★ |（normal_agreement）配准后，把两片点云的法线逐点比方向，取点积的平均值。+1 完全同向，−1 完全反向| 专门抓翻转解的量（ADR-0025）。真机：正解 +0.98，翻转解 −0.37~−0.60 |
| **外向归一** ★★★★ | 比较之前，先把两片点云的法线各自调成「整体朝外」。因为原始符号可能整片相反 | 不做这一步，正确解会被算成 −0.98，判据直接反号。这是踩过的坑 |
| **单站直通** ★★★ |（identity / single_scan）只有一份点云时，配准无事可做，直接原样传下去| M2 的合法分支。缺点是日志写「M2 完成」会被人读成「配准通过了」——所以现在会显式说明 |
| **恒等变换**（Identity）★★ | 什么都不做的变换（对角线为 1，其余为 0） | 对齐被拒时**回退**到它。宁可不动，也不能把几何搬错 |
| **控制点** ★★★ |（Control Point）人工在两地数据上各指同一个物理点，形成硬约束| 尺度与朝向的最后手段（X2）。要求：至少 3 个不共线，且人工确认 |

## 3 从点云到模型

M3 要把几十万个散点变成一张连续的面。这一步的选择会直接决定后面贴图好不好看。

| 术语 | 它是什么 | 在这个管线里干什么 |
|---|---|---|
| **泊松表面重建** ★★★★ |（Poisson Reconstruction）把所有点当成「表面在空间里的采样」，解一个方程求出最平滑的那张面。数学上是在解泊松方程| M3 的主算法。优点是闭合、抗噪；缺点是会把不存在的地方也「补」出来（所以要裁密度） |
| **八叉树深度** ★★★ |（octree depth）重建时把空间一分为八、再分八，分几层就是深度。层数越多越细，也越慢越吃内存| `poisson_depth` 默认 8。8–10 对千万级点云较稳；调到 11 会开始出现虚假细节 |
| **孔洞填充** ★★ |（fill_holes）把网格上的小洞补上| M3 的可选项。相机拍不到的背后、镂空处会留洞，补之前要想清楚「补出来的是猜的」 |
| **网格简化 / LOD** ★★★ | 在尽量保持外形的前提下减少三角形数量。LOD = 细节层次，同一件出几个不同精度的版本 | `simplify_quadric_decimation` 用它，`lod_levels` 指定生成几档。交付大文件时必备 |
| **二次误差简化** ★★★★ |（Quadric Decimation）每次合并两个顶点，选「让外形变化最小」的那一对。误差用二次型度量| 上述简化的具体算法。比随机删面好得多，形状基本不塌 |
| **DBSCAN 聚类** ★★★★ | 一种按密度分组的算法：挨得够近的点归一类，孤立的点算噪声。不需要预先指定分几类 | M1 剔背景时用它保留「主体那一坨」，把四周零散的杂物丢掉 |
| **平面剔除** ★★★ |（segment_plane）用 RANSAC 找一张最大的平面，把落在它上面的点删掉| 桌面、转台、地面这些「支架」会被 IMU 级当成模型的一部分，必须剔。默认关闭（`bg_max_planes=0`） |
| **尺度自适应** ★★★ |（scale factor）先量出这件东西多大，再按比例缩放所有算法参数| 让同一套配置能吃 5 cm 和 30 cm 的件。没有它，参数只能按单一尺寸硬编码 |

## 4 摄影测量与 SfM

S1 阶段调 COLMAP 从照片反推相机位置。这一章的名词是「照片怎么变成三维」的全过程。

| 术语 | 它是什么 | 在这个管线里干什么 |
|---|---|---|
| **SfM**（运动恢复结构）★★★★ | 从一堆不同角度的照片，同时反推「相机在哪」和「场景长什么样」。像闭着眼转圈拍照，事后算出你走过的路线 | S1 的全部工作。它给出的是稀疏点 + 每张照片的位姿，不是模型 |
| **COLMAP** ★★★ | 一个开源 SfM/MVS 软件。本管线把它当外部命令调用，不重写 | S1 的后端。命令行参数由 `sfm_solve` 段配置（matcher、max_features 等） |
| **稀疏重建 / 稠密重建** ★★★ | 稀疏 = 只算特征点（几万个）；稠密 = 每像素都算深度（几百万点） | 稀疏用于定位相机，稠密用于出点云。后者慢十倍以上，也可能失败 |
| **特征点**（Keypoint）★★★ | 图像里「有辨识度」的小块，比如角点、斑点。平坦的地方没有特征 | 特征太少就配不准。真机 30 张照片只出 13,990 个点、轨迹长度 3.95，属于偏弱 |
| **特征匹配** ★★★ | 判断「这张图里的这个点」和「那张图里的哪个点」是同一个物理位置 | 匹配错了后面全错。所以要用几何约束（基础矩阵）把明显错的剔掉 |
| **轨迹长度** ★★★ |（track length）一个三维点被多少张照片同时看到。3 表示平均被 3 张看到| 衡量重建质量的关键数。小于 3 说明重叠不足，几何会很脆 |
| **内参** ★★★ |（Intrinsics）相机自己的参数：焦距、主点、像素尺寸。跟拍到什么无关| 内参错 → 整个尺度错。所以写死 `single_camera 1` 只在「所有照片同一台相机同一镜头」时成立 |
| **外参 / 位姿** ★★ | （Pose，即 R 与 t）相机在哪个位置（t）、朝哪个方向（R） | 贴图全靠它：知道相机在哪，才知道某个纹素该取哪张照片的哪个像素 |
| **针孔相机模型** ★★★ | 把成像简化成「一个小孔 + 一张平面」，用投影公式算「三维点落在图像哪个像素」 | 所有投影计算的数学基础。内参 + 外参 + 这个模型 = 一个像素坐标 |
| **径向畸变** ★★★★ |（SIMPLE_RADIAL）真实镜头会让画面边缘弯曲（直线拍成弧线）。用一两个参数把弯曲掰回来| COLMAP 的畸变模型。换镜头就必须换模型，否则边缘的贴图会错位 |
| **重投影误差** ★★★★ |（Reprojection Error）把算出来的三维点重新投回照片，看它离「当初看到的那个像素」差多少（单位：像素）| SfM 自评的核心指标。一般要求 <1 像素；它衡量的是「模型和照片自洽」，不是绝对精度 |
| **MVS / PatchMatch** ★★★★ | 多视图立体：已知相机位置后，逐像素找它在别的照片里的对应，算出深度 | COLMAP 稠密重建的算法。内存消耗大，所以有 `dense_max_pixels` 限制 |
| **深度图** ★★★ |（Depth Map）一张「每个像素离相机多远」的图| MVS 的中间产物。它再融合成点云，就是 `fused_dense.ply` |
| **单相机假设** ★★★ |（single_camera）假设所有照片共用一套内参| 打开时多机位拍的照片会被错误合并成一台。混用两台相机就必须关掉 |
| **capture_meta**（采集元数据）★★ | 记录「这张照片对应哪台相机、位姿是多少」的 JSON | M4 的真实输入。没有它，贴图只能靠像素硬猜 |
| **位姿约定** ★★★ |（pose convention）「世界到相机」还是「相机到世界」，转置一下就是另一个。两者混用会整体错位| ADR-0013 踩过的坑。管线里现在有显式字段标明，不再靠默认理解 |
| **ArUco 标记** ★★★ | 一种黑白方块码，能在照片里被自动识别并给出精确角点 | 用来：①标定色卡位置；②给多张照片提供共同参照。贴几个、贴哪里本身是个待定规范 |
| **色卡** ★★ |（ColorChecker24）24 个已知颜色的方块，用来校正照片的颜色| X2 色差评估的基准。没有它，「颜色变了」和「灯变了」分不开 |
| **白平衡 / 色温** ★★★ | 让「白的东西拍出来还是白的」。灯光偏黄，照片就整体偏黄 | 多相机色调不一致的主因之一。真机 11 台相机之间色差 40.44，量的就是这个 |
| **偏振 / 侧向硬光** ★★ | 偏振片压掉反光；侧光让表面凹凸产生阴影、显出细节 | 采集建议。釉面反光会毁掉特征点，细裂隙在正面光下几乎拍不出来 |

## 5 UV 展开与照片贴图

M4 是这套管线最自研的一块：把三维表面「摊平」成一张图，再把照片上的颜色搬进去。

| 术语 | 它是什么 | 在这个管线里干什么 |
|---|---|---|
| **UV 展开** ★★★ |（UV Unwrap）把三维表面像剥橘子皮一样摊平到一张二维图上，每个顶点分到一个 (u,v) 坐标| M4 的第一步。摊得越平，贴图浪费越少、接缝越少 |
| **UV 岛**（Island）★★★ | 摊平后图上的每一块独立区域。橘子皮摊平必然要剪几刀，每一块就是一个岛 | 图集由很多岛拼成。**关键后果：图上相邻的两个纹素，在实物上可能完全不挨着** |
| **图集**（Atlas）★★★ | 把所有岛拼进一张大图（比如 2048×2048） | 最终贴图就是这张图。纹素总量决定细节能有多细 |
| **xatlas** ★★★ | 一个开源的 UV 展开库 | M4 用它做展开。参数调岛数效果有限（±15%），岛数主要由网格形状决定 |
| **纹素**（Texel）★★★ | 纹理图上的「像素」。它不是屏幕像素，是贴图上的一个格子 | 所有贴图质量指标的分母。面积、覆盖率、异常都是按纹素算的 |
| **光栅化** ★★★ |（Rasterization）把三角形「填」成格子：算出这个三角形盖住了哪些纹素| M4 逐三角形光栅化到 UV 空间，才知道每个纹素该取哪张照片 |
| **Z-buffer**（深度缓冲）★★★★ | 每个像素记「目前最近的深度」。后来的如果更远，就不画 | 判断「这个纹素有没有被别的东西挡住」。实现上存的是一张最小值深度图 |
| **遮挡** ★★★ |（Occlusion）被模型自己的其他部分挡住，相机其实看不见| 必须降权或剔除，否则会把背面/内侧的颜色贴到正面 |
| **可见性判定** ★★★ | 两个条件：①相机大致正对这个面（夹角够小）；②投影真的落在画幅内 | 两个条件分开算、分开报。只报一个数会把「几何搬错了」误判成「拍得不全」 |
| **正向可见率 / 入画率** ★★★★ | `normal_visible_fraction` 只看夹角；`in_frame_fraction` 只看有没有投进画面 | 两者差 40 个百分点以上，基本可以断定几何被搬错位置了 |
| **多视图加权采样** ★★★ | 一个纹素可能被好几张照片看到，按「角度好、清晰、曝光对」加权平均 | M4 的核心采样策略。`top_k` 控制最多用几张，`samples_per_tri` 控制采样密度 |
| **法线投票** ★★★★ | 用「相机看在眼里的是哪一面」来决定法线朝里还是朝外 | 只靠几何一致化不够（68% 会反向），必须让相机投票 |
| **接缝**（Seam）★★★ | 两个 UV 岛的交界，或者两个视角的过渡处。颜色对不上就是一条线 | 图集质量的直观判据。成因是不同照片的色调/曝光差异 |
| **bleed**（边缘外扩）★★★ | 把岛边缘的颜色往外多涂几圈，防止采样时采到岛外的空白 | 必做。不做的话，模型边缘会出现黑边或白边。外扩必须零边界平移，不能拉伸 |
| **pixel_scale**（像素换算）★★★★ | 「照片上的 1 像素 = 原图的几像素」。因为 SfM 用的是缩小过的图，贴图用的是原图 | 实测 1.874 倍。不做这个换算，颜色会全部取到左上角 53% 的区域，而且不报错 |
| **纹理重叠度** ★★★★ |（texture_overlap）平均每个纹素有**几台**相机参与着色| 抓「只有一台相机硬投影」的情况。必须与色差配对读，否则会读反（见 10.3） |
| **多视角色差** ★★★ |（multiview_color_std）同一个纹素上，几台相机给的颜色的标准差| 小 = 融合稳；但也可能小得可疑——只有一台相机时它恒等于 0 |
| **顶点色** ★★ |（Vertex Color）不摊平、不做贴图，直接给每个顶点一个颜色| 快速预览用（`paint_mode=vertex`）。比贴图省事，细节上限受顶点数限制 |
| **图集利用率 / 岛内填充率** ★★★ | 前者 = 有内容的纹素占整张图的比例；后者 = 岛内部被填满的比例 | 前者低是正常的（岛之间有缝）；**后者低才是真问题**（法线、遮挡、位姿错了） |
| **图集缓存**（两级键）★★★★ | UV 级缓存按几何指纹；纹理级缓存再加上法线、位姿、照片哈希、参数 | 第二次跑同一件几乎瞬间完成。键集合变了必须升 `CACHE_VERSION`，否则新指标永远是空 |

## 6 颜色与色差

这一章只有做「颜色有没有变」时才需要。核心难点是：**照片里的颜色不等于物体的颜色**。

| 术语 | 它是什么 | 在这个管线里干什么 |
|---|---|---|
| **sRGB** ★★★ | 最通用的彩色图像编码方式。注意它是「非线性」的，为了照顾人眼和 8 位存储 | 照片的默认色彩空间。所有颜色计算的第一步都是「先转成线性或 Lab」 |
| **线性 RGB / gamma** ★★★★ | 物理上正确的颜色表示（光强翻倍就是数值翻倍）。sRGB 到它要开 2.4 次方 | 做加权平均、乘系数时必须在线性空间，否则暗部会被系统性压低 |
| **CIE Lab** ★★★★ | 一种「按人眼感觉」排布的颜色空间：L 是明度，a/b 是两个色度轴 | 算色差用它，因为它的距离近似等于人眼看到的差异 |
| **ΔE**（CIE76）★★★★ | 两个颜色在 Lab 空间里的距离。经验值：ΔE≈2.3 是刚能看出来的差别 | X2 色差评估与 X4 跨期比对的判据。门限 5 表示「明显可见」 |
| **色度**（chroma）★★★★ | 颜色偏离灰色的程度。中性灰的 chroma = 0 | 区分「残存彩绘」与「露胎」：彩绘的 chroma 明显高。注意 Lab 里中性点是 128，不是 0 |
| **分位仿射对齐** ★★★★ | 用两张图的 10% 分位、90% 分位和中位数，各自拉成一样，抵消整体亮度/对比度差异 | X4 两期比对前必做。真机实测：整体提亮 +25 时，稳定区的 ΔE 从 9.80 降到 0.00 |
| **8 位量化** ★★★ | 颜色只有 256 级。暗部两级之间可能差好几个 ΔE | 这是「对齐后残差不可能为 0」的原因之一。暗部实测留 1~2 ΔE 的下限 |
| **饱和裁切**（clipping）★★★ | 光太强，像素值到 255 就上不去了，细节永久丢失 | 曝光过度的区域无法通过任何算法恢复。所以采集时宁可欠曝一点 |
| **白平衡 / 色温** ★★★ | 同第 4 章。这里的作用是：不同批次采集的色温不同，会让「颜色变了」变成假阳性 | 跨期比对必须固定光源色温，或者靠色卡校正 |

## 7 时间维度：形变与两期比对

X1 要回答「这件东西和上次比，哪里动了、动了多少」。难点不在算差值，在**证明这两份数据真的可以比**。

| 术语 | 它是什么 | 在这个管线里干什么 |
|---|---|---|
| **时相 / 期次**（Epoch）★★ | 一次采集形成的一整套数据。同一件文物可以有多个时相 | 档案层的基本单位。跨期比对就是「拿两个时相比」 |
| **基准期 / 复测期** ★★★ | 基准期定坐标、定图集、定尺度；复测期一律单向对齐到基准期 | 禁止链式对齐（A→B→C），误差会累积。这也是图集继承存在的理由 |
| **M3C2** ★★★★ | （多尺度模型对模型点云比对）一种专门比两片点云的方法：沿法线方向找两片点云的「平均位置」，相减得到距离，并给出显著性 | X1 的主算法。比直接算最近点距离稳，因为它考虑了点的分布范围而不是单个点 |
| **法向距离** ★★★ | 沿表面法线方向量出来的距离，不是直线距离 | 判断「鼓起来多少」用它。斜着量的距离会把切向滑动误算成变形 |
| **位移场** ★★★ | 每个点一个位移向量，合起来就是「哪里往哪动了多少」 | X1 的输出。可视化成一圈箭头或一张热力图 |
| **同源闸门** ★★★★ | 算差值**之前**先核对：这两份数据是不是同一件文物的两期 | 判据：包围盒对角线之比在 0.9~1.1，且双向互最近邻中位距离 ≤ 对角线 2%。不通过就不出数 |
| **已知形变标定** ★★★★ | 造一份「我知道答案」的合成数据（球面上均匀外移 3 mm），看算法报不报 3 mm | 验证尺子本身。实测线性度 1.000/0.998/1.001，说明算法没系统偏差 |
| **线性度** ★★★ | 报出的值 ÷ 真值。理想是 1.000 | 上面那项标定的判据。偏离 1 说明有系统性缩放错误 |
| **稳定区 / 参考区** ★★★ | 假定「这些地方肯定没动」的区域，用来对齐两期 | 没有稳定区就只能靠整体配准，而整体配准会被真实变形带偏 |
| **LOD**（细节层次）★★★ | 同一件模型的多个精度版本 | 跨期比对要选同一 LOD，否则「点少了」会被误算成「变薄了」 |

## 8 统计、异常与"可疑"

X2（代码里叫 X3）做的是**无监督离群筛查**：它只说「这里和周围不一样」，不说「这是裂隙」。
这一章的名词决定你能不能正确读那张热力图。

| 术语 | 它是什么 | 在这个管线里干什么 |
|---|---|---|
| **无监督** ★★★ |（Unsupervised）算法事先不知道「什么算病害」，只能自己找「和大多数不一样的」| X2 的全部前提。它不需要标注数据，所以现在就能跑 |
| **离群 / 异常** ★★ |（Outlier / Anomaly）偏离大多数样本的个体| X2 输出的就是它。注意「异常」不等于「病害」，也可能是图案边缘 |
| **局部中位数背景** ★★★★ | 用周围一圈纹素的**中位数**当作「本底」，看当前纹素偏离本底多少 | X2 的核心。**不能用均值**：病变占满窗口 36% 时，均值被拉偏，多数派反而成了离群者 |
| **鲁棒尺度**（MAD 家族）★★★★ | 一种不被极端值带跑的「波动大小」估计。这里用 `q75(绝对残差)/1.1503` 近似标准差 | 决定「偏离多少才算异常」。用中位数当尺度会在双峰分布（条纹、织纹）上归零，导致整条纹理都被报异常 |
| **分位数**（p90/p99）★★★ | 把数据排序后取第 90%、99% 位置的值。比最大值稳，比平均值抗极值 | 尺度初始化用 99% 分位而不是最大值，否则一个飞点就能把尺度撑大 8 倍 |
| **稳健 z 分数** ★★★ | （当前值 − 背景）/ 尺度。就是「偏离了几个波动单位」 | X2 的分数就是这个。阈值通常取 3~5 |
| **连通域标记**（label）★★★ | 把挨在一起的「可疑纹素」归成一个编号，每个编号是一个斑块 | X2 从「一张热力图」变成「N 处待复核」就靠它 |
| **图斑**（Region）★★ | 一个连通的异常斑块，带面积、位置、形状 | 报表里「图斑数」就是这个。它对应人眼要复核的「一处」 |
| **IoU**（交并比）★★★ | 两个区域的重叠面积 ÷ 合并面积。1 = 完全重合 | 验证算法找得准不准。也可以比两期的同一处斑块是否对应 |
| **增量 IoU** ★★★★ | 只看「注入之后**新增**的报警」与真值的 IoU，把原本就有的报警扣掉 | 整图 IoU 问的是「这图干不干净」，增量 IoU 才问「这一处找得准不准」。灵敏度验证必须用它 |
| **灵敏度 / 可检下限** ★★★★ | 能稳定检出的最小异常尺寸，通常用「面积小于多少纹素就检不出」表示 | X2 现在的可检下限约 80 纹素。写论文必须报这个数，否则「检出了 12 处」没有意义 |
| **假阳性** ★★★ |（False Positive）报了但实际上不是。这里是「判异常但只是图案边缘」| 单期筛查的主要误差来源。要靠跨期比对或人工复核排除 |
| **双峰分布** ★★★ | 数据分成两堆（比如深色条纹和浅色底），不是一团 | 它是「按岛归一化」和「鲁棒尺度」存在的理由。当成单峰处理必然大批误报 |
| **按岛归一化** ★★★★ | 每个 UV 岛先减去**它自己的**中位数，再和同岛的其他纹素比；跨岛不比 | 不是优化而是必须：图集是拼出来的，图上相邻的两个纹素在实物上可能隔了半米 |

## 9 AI 语义分割（A0，尚未开工）

这一章的名词在你拿到「病害形态明确的文物」之后才会用到。**现在开工没有意义**，
因为现有数据里没有可分的东西（残存彩绘只占 1.89%）。

| 术语 | 它是什么 | 在这个管线里干什么 |
|---|---|---|
| **语义分割** ★★★ |（Semantic Segmentation）给每个像素贴一个类别标签（这是裂隙、那是胎体），不区分个体| A0 的目标形态。输出是一张「类别图」 |
| **实例分割** ★★★ |（Instance Segmentation）在语义分割基础上再区分「这是第 1 条裂隙、那是第 2 条」| 需要数「有几处」时用它。比语义分割难，样本要求更高 |
| **SAM** ★★★★ |（Segment Anything）一个「你指哪它切哪」的通用分割大模型。给一个点或一个框，它返回物体轮廓| 用它把「大概可疑的区域」切成**边界干净**的图斑，减少人工描边 |
| **MobileSAM** ★★★ | SAM 的轻量版，模型小很多，速度更快，精度略降 | 本机 4 GB 显存能跑。选它是为了不为了一个阶段去买显卡 |
| **提示**（Prompt）★★★ | 给模型的「指路信息」：一个点、一个框、一段文字 | 半自动标注的核心操作：点一下可疑处，让它自己长边界 |
| **YOLOv8n-seg** ★★★ | 一个又小又快的检测+分割模型（n = nano） | 有监督阶段的候选。需要几十处标注样本才能训 |
| **微调** ★★★ |（Fine-tune）拿一个已经在大数据上训好的模型，用你自己的小数据集再训几轮| 样本少时的标准做法。比从零训练省几十倍数据 |
| **few-shot** ★★★ | 每一类只给几例就想让它学会 | 30 处样本量级只能做 few-shot 演示，写不进论文的「定量评估」 |
| **多边形标注** ★★★ | 用一串点把目标轮廓圈起来，存坐标而不是存图片 | 本管线的标注格式（`labels.json`）。可读、可 diff、可复核 |
| **mIoU** ★★★★ | 所有类别的 IoU 取平均，衡量分割整体准确度 | 报结果的主指标。**必须先报「人工标注一致性」作为上限**，否则 mIoU 0.6 是高是低没法判断 |
| **标注一致性** ★★★★ | 同一个人隔天重标、或两个人各标一次，两者之间的 IoU | 它给出「这个任务可达到的上限」。模型分数只能跟它比 |
| **类别不平衡** ★★★ | 一类样本远多于另一类（比如胎体占 90%，裂隙占 1%） | 直接训练会让模型「全猜胎体」也有 90% 准确率。必须看每类 IoU，不能只看总体准确率 |

## 10 "这个数字能不能引用"

这一章是整套管线的**方法论核心**，也是论文最该写的一章。其余章节讲「怎么算」，
这一章讲「算出来的东西什么时候不算数」。

| 术语 | 它是什么 | 在这个管线里干什么 |
|---|---|---|
| **RMSE / 中误差** ★★★ | 一组误差的均方根。可以理解成「平均每个点差多少」 | M5 的精度主指标。单位是米或毫米，前提是坐标真的是米 |
| **相对中误差**（rmse_rel）★★★ | RMSE ÷ 包围盒对角线，一个无量纲的百分比 | 单位不确定时唯一能引用的精度口径。真机 relic_001 是 9.07% |
| **中误差三态** ★★★★ |（rmse_scope）每个 RMSE 必须标明属于哪一态：实测判门 / 不判门（参考稀疏）/ 不判门（单位存疑）/ 无量纲| 防止「把不能比的数放一张表里」。报表里每一行都带这个标注 |
| **metric_units** ★★★★ | 「这份数据的坐标是不是米」。是布尔值，但判断依据很脆 | 早期实现是「`00_raw` 里有文件就算米制」。照片重建件放进去也会被判成激光锚定，于是毫米级结论全是假的 |
| **units_plausible** ★★★★ | 自称米制，但算出的对角线是 0.02 m 以下或 3.0 m 以上 → 自相矛盾 | 中小型文物不可能有 8 米对角线。触发时不改数值，只降级表述并退出毫米判定 |
| **数据来源声明** ★★★★ |（data_source）用户明确声明这是激光件还是照片重建件：`auto` / `laser` / `photogrammetry`| **证据压过声明**：声明 laser 但算法判定「这看起来像 SfM 产物」，仍然不主张米制，并记一条 WARN |
| **同源自证** ★★★★ |（dual_source_duplicate）两路数据其实是同一份（照片重建的产物被当成「第二路激光」）| 判据：新信息比例 < 15% 且有原始输入。一旦命中，配准/精度/覆盖率三项全部不可引用 |
| **口径**（scope）★★★ | 一个数字成立所依赖的全部前提：数据来源、单位、是否判门、哪次运行 | 写论文时每个数字后面都该跟一句口径。混用两个口径的数 = 学术不端 |
| **精度 vs 准确度** ★★★ | 精度 = 每次结果彼此接近；准确度 = 离真值近 | 定种子能让结果「精确」（每次一样），但不会让它更「准确」。两件事别混 |
| **置信度** ★★★ |（low_confidence）算法自己觉得这个结果不牢（fitness < 0.55），但还不到判失败| 不拦，但必须在报表上可见。隐掉它等于假装没问题 |
| **PASS / WARN / FAIL** ★★ | 核验的三档结论。WARN = 能交付但有问题要人看 | `h3d verify` 的输出。交付前必须看这三个数，不能只看「跑完了」 |
| **拒答** ★★★★ |（refuse to answer）条件不成立时宁可不给数，也不给一个带假前提的数| 这是本管线相对通用工具链的核心差异。全篇有十几处这样的闸门 |

## 11 软件工程：架构、契约与测试

这一章的名词不影响算法结果，但决定了「改一处会不会悄悄坏另一处」。

| 术语 | 它是什么 | 在这个管线里干什么 |
|---|---|---|
| **分层架构** ★★★ | 把代码按职责分层，上层只能调下层。本项目：core 底座 → io 适配 → 业务层 | 业务层禁止直接 `import open3d`。要换三维库时只改 io 层 |
| **适配器模式** ★★★ | 在「我们的接口」和「第三方库的接口」之间加一层翻译 | `h3d.io` 就是。所有 Open3D 调用收敛在这里，业务代码只认 `sample_surface` 之类的名字 |
| **契约**（Contract）★★★ | 两个模块之间约定好的输入输出与保证，写下来就不是「默契」 | 例：`sample_surface(mesh, n, seed)` 保证「同 seed 同结果」 |
| **单一真源** ★★★ |（Single Source of Truth）一件事只有一个定义处，其余地方都来读它| 阶段清单、图斑列顺序、口径文字都做过收敛。曾经有八份手写副本，其中四份不认识某个阶段 |
| **幂等** ★★★★ |（Idempotent）同样的操作做一次和做十次，结果一样| 建档、图集登记、缓存都必须幂等。否则重跑一次就多一条记录 |
| **原子写** ★★★★ |（Atomic Write）先写临时文件再改名，避免「写到一半断电」留下半个坏文件| 所有 JSON/状态落盘都走它。半截文件比没有文件更难查 |
| **内容哈希 / 指纹** ★★★★ |（content_key）把「输入数据 + 参数」算成一个哈希值，作为这份结果的身份证| 断点续跑、缓存复用的判据。输入变了哈希就变，自然重算 |
| **缓存键** ★★★ |（Cache Key）决定「这份缓存还算不算数」的那组字段| 漏一个字段 = 改了参数还用旧结果。图集缓存分 UV 级和纹理级两种键 |
| **版本冻结** ★★★★ |（AtlasFrozen）图集一旦登记就不可改；要改只能建新版本，旧版保留| 否则历史对比链会断：昨天和今天的两张图集不是同一套坐标系 |
| **断点续跑**（resume）★★★ | 中断后从上次完成的地方继续，不重头跑 | 判据是「状态 + 输入指纹」，不能只看状态。改了参数但状态是 done，必须重算 |
| **force_rerun** ★★★ | 强制无视缓存全部重算 | 验证「新指标到底算没算」时的唯一可靠手段 |
| **manifest 账本** ★★★ | 记录每个阶段、每件文物的执行状态与全部指标 | 报表、交付核验、断点续跑都读它。它是「这次到底跑了什么」的唯一记录 |
| **五态终态** ★★★★ | `done` / `fail` / `skipped` / `disabled` / 键不存在（未执行） | 分母 = 件数 × 阶段数 − 未启用。「全跳过」是正确终态，不是失败 |
| **失败隔离** ★★★ |（fail_isolation）一件失败不影响其他件继续跑| 批量处理时开着它，一件坏数据不会让整批停摆 |
| **异常体系** ★★★ | 自定义的异常类层次（输入错、只读违规、配准失败……） | 让「哪种错」在日志里一眼可辨，而不是全是 `Exception` |
| **守卫测试** ★★★★ |（Guard Test）不测功能，测「规矩有没有被破坏」的测试| 例如：源码里除一个文件外不许出现 `sample_points_uniformly`。它抓到过 4 处违规，其中一处是「假种子」 |
| **回归测试** ★★★ | 改完代码重跑一遍，确认没把原来对的改坏 | 每次改动的底线。当前 1400+ 条 |
| **flaky test** ★★★★ | 时好时坏的测试。多数是没定种子或依赖执行顺序 | 它比失败更危险：会训练人「红了就重跑」，久了没人看结果 |
| **冒烟测试** ★★★ |（Smoke Test）只验证「主流程能跑通」的最快检查| 打包后跑 `--version` 和几处 `verify`，几分钟内确认成品没坏 |
| **静默降级** ★★★★ | 出错时不报错、悄悄换个弱方案继续跑 | 明令禁止。兜底必须同时写指标 + WARN，否则等于把问题藏起来 |
| **手写白名单** ★★★★ | 从上游几百个指标里人工挑几十个写进下游 | 本项目栽过多次：上游算得再对，没写进白名单就等于没算，而报表照样正常 |

## 12 随机与可复现

这一章只有一个问题：**同样的输入，跑两次，结果一样吗。** 看起来是小事，实际是这套系统
返工最多的地方。

| 术语 | 它是什么 | 在这个管线里干什么 |
|---|---|---|
| **随机种子**（seed）★★★ | 随机数其实是「按种子算出来的一串固定数」；种子相同，数列就相同 | 全系统所有随机算法都必须定种子。`RANSAC_SEED=20261105` 这类常量就是它 |
| **RNG**（随机数发生器）★★★ | 产生随机数的函数。分「全局」和「局部」两种 | 全局的那种最危险：任何一处调用都会改变后面的数列，导致「改无关代码影响了结果」 |
| **全局随机源** ★★★★ | 一个进程里所有代码共用的那一个随机数发生器 | Open3D 的采样和 RANSAC 都吃它。所以「定种子」必须和「用随机」在同一个文件里，中间不能插别的事 |
| **确定性** ★★★ |（determinism）同输入 → 同输出，与运行次数、顺序、机器无关| 报表可引用的前提。两次跑出 86.78 / 87.42 的差别虽小，但两天前的报表就对不上了 |
| **跨进程差异** ★★★★ | 同一次运行内一致，但换个进程就变 | 最隐蔽的一种不确定性。M1 平面剔除曾跨进程差 1 个内点——小到不触发任何断言 |
| **并行归约** ★★★★ |（parallel reduction）多线程各算一部分再合并。合并顺序不固定时，浮点结果会有末位差| 泊松重建因此默认单线程（`n_threads=1`）。速度让位给可复现 |
| **浮点末位**（1e-32 量级）★★★★ | 双精度只有约 16 位有效数字，累加顺序一变，最后几位就不同 | 判断「结果是否相同」要用容差（`atol=1e-12`），不能用逐位相等。逐位相等会天天红 |
| **可复现性** ★★★ |（reproducibility）别人拿着你的输入和参数，能得到同样结果的能力| 论文的底线要求。也是「报告里的数字敢不敢引用」的前提 |

## 13 界面与打包

GUI 与安装包的名词。它们不影响算法，但决定了别人能不能用起来。

| 术语 | 它是什么 | 在这个管线里干什么 |
|---|---|---|
| **Qt / PySide6** ★★★ | 一套跨平台界面库。窗口、按钮、表格都来自它 | GUI 的全部。选 PySide6 是因为它的开源授权（LGPL）适合开源项目 |
| **QThread / 信号槽** ★★★★ | Qt 的多线程机制：耗时任务放后台线程，算完通过「信号」通知界面更新 | 不加它会「点一下按钮整个界面卡住」。也是「连点两次就崩」这类 bug 的来源 |
| **模态对话框** ★★ | 弹出来必须处理完才能操作主窗口的对话框 | 单站提示这类「必须让人知道」的信息用它 |
| **DPI 缩放** ★★★ | 高分屏上界面元素按比例放大（125%/150%） | 不处理的话，150% 缩放下按钮会互相压住。是已知未覆盖的测试项 |
| **文本省略**（elide）★★★ | 文字太长时显示成「前半段…」而不是把布局撑破 | 路径很长时用。它有个坑：控件没构造完就被问宽度会抛异常 |
| **PyInstaller** ★★★ | 把 Python 程序打成单个 exe，别人不用装 Python | 出安装包的环节。打包版和源码版必须行为一致，所以要跑同一批 `verify` |
| **onefile / windowed** ★★★ | onefile = 打成一个文件；windowed = 不弹黑色控制台窗口 | 两者一起用的代价：**没有 stderr**。日志写不出去时你什么都看不到 |
| **hiddenimports** ★★★★ | PyInstaller 静态分析看不到的动态导入，必须手工列出来 | 新增一个子模块忘了列，打包版就 `ModuleNotFoundError`，而源码版一切正常 |
| **Inno Setup** ★★★ | 一个做 Windows 安装程序的工具，把 exe 包成「下一步下一步」的安装包 | 最终交付形态。需要签名的场景还得额外处理 |
| **stderr 为 None** ★★★★ | windowed 程序没有控制台，`sys.stderr` 是 None | 任何「出错时打印到 stderr」的代码在打包版里会二次崩溃（静默）。这是踩过的坑 |

## 14 文件格式、报表与交付

| 术语 | 它是什么 | 在这个管线里干什么 |

| **base64 data URI** ★★★ | 把图片编码成一长串字符直接塞进 HTML，不额外存文件 | 报表的图表就是这么嵌的。副作用：在那串字符里搜关键字会搜到假结果 |
| **交付核验** ★★ | （verify）交付前自动检查：文件齐不齐、报表有没有每件、数字口径对不对 | `h3d verify <项目>`。输出 PASS/WARN/FAIL 三项计数 |
| **迁移闸门** ★★★★ |（looks_like_project）搬动目录前先确认「这真的是一个项目」，否则不动| `output` / `report` 是通用名字。不加闸门会把仓库的 `output/` 整棵搬走（真发生过） |

### 15.2 八组最容易混的词

| 容易混的两组 | 区别 | 为什么重要 |
|---|---|---|
| **异常 ≠ 病害** | 异常是「和周围不一样」，病害是「有病理形态的一类东西」 | X2 只能报「N 处待复核」，不能写「N 处裂隙」。写成后者就是错的 |
| **精度 ≠ 准确度** | 精度是「每次一样」，准确度是「离真值近」 | 定种子提高的是精度。它不会让 9.07% 变成 1% |
| **覆盖率 ≠ 填充率** | 覆盖率是整张图有内容的比例；填充率是岛内部填满的比例 | 覆盖率低很正常（岛之间有缝）。填充率低才是法线/遮挡/位姿出了问题 |
| **分辨率 ≠ 精度** | 分辨率是「多细」，精度是「多准」 | 一张 4K 贴图可以又细又错。分辨率高不代表几何准 |
| **配准通过 ≠ 数据可用** | 配准只说明「两份几何像不像」 | 单站直通也报「配准完成」，但一次变换都没做 |
| **贴图完成 ≠ 颜色对** | 有图不等于颜色可信 | 没有色卡时只能说「相对变化」，不能说「ΔE 变了 6」 |
| **中位数 ≠ 平均值** | 中位数是「排在中间的那个」，不受极端值影响 | X2 全靠中位数。换成均值，病变占 36% 时整个判据就翻了 |
| **图集 v1 ≠ 图集 v1** | 图集版本号是项目内的命名空间 | 两个项目的 `atlas-v1` 不是一回事，跨项目引用必须带文物前缀 |

### 15.3 八个常见误解

| 误解 | 实际情况 |
|---|---|
| 「测试全绿 = 可以交付」 | 1400+ 条测试在三个真机缺陷存在期间始终全绿。它们测的是「按我的理解工作」，错在「我的理解」这一层 |
| 「报表有数 = 数能用」 | 大量数字带前提。`rmse_mm` 那个 767.04 连毫米门都进不了，可引用的只有 `rmse_rel` |
| 「跑完没报错 = 没问题」 | 最危险的错是静默降级：不报错、换个弱方案继续跑、报表照样齐全 |
| 「点云越多越准」 | 密度够用即可。百万点和二十万点在配准精度上可能没差别，但时间差 5 倍 |
| 「模型越精细越好」 | 八叉树深度调高会开始「编造」不存在的细节，看起来更精致、实际更假 |
| 「自动配准通过就不用管了」 | 近似轴对称物上，翻转解能骗过所有距离类判据。要靠法线一致性这类**方向**判据 |
| 「AI 接上就能识别病害」 | 没有形态明确的样本，AI 只能学会「彩绘 / 胎体」这种域分类，不是病害 |
| 「换个工具就能出毫米精度」 | 毫米精度要求输入本身是毫米可信的（激光或控制点）。照片重建件给不出毫米结论 |
