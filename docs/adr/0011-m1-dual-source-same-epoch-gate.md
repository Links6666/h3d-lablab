# ADR-0011：M4 覆盖率 21% 的根因是 M1 把异源几何合并了

- 状态：已接受
- 日期：2026-11-01
- 关联：ADR-0009（对齐验收）、ADR-0005/0006（X1 的两期同源闸门）

## 背景

上一轮把 M4 的对齐修好之后（拒绝把几何搬出视野的对齐），coverage 从 1.16% 回到
**21.22%**，但这仍然低得可疑：`atlas_utilization` 68%（UV 正常）、
`normal_visible_fraction` 63%（法线方向基本对）、`in_frame_fraction` **14.54%**。

两个可见性指标差 48.7 个百分点——项目记忆里这条判据指向「几何搬错」。但恒等
（不对齐）时也只有 14.5%，说明问题不在那一次对齐。

## 一、用一把尺子量四个几何

`in_frame_ratio`（顶点口径的「投进至少一台画幅」比例）逐个量：

| 几何 | in_frame | 包围盒对角 | 说明 |
|---|---|---|---|
| `00_raw` 原始激光 | **100.00%** | **6.70** | 与相机尺度一致 |
| `10_clean` M1 清理后 | 66.75% | **16.32** | 尺度已被撑大 |
| `30_dense` M3 泊松 | 45.81% | **20.97** | 壳包住了两个物体 |
| `10_dense` 照片重建 | 11.71% | 13.71 | 另一套坐标系 |

规律极其干净：**对角线越大，投进画幅越少**。原始的 6.70 是 100%，被撑到 21 就只剩
45.8%。这不是旋转/平移问题，是**几何被撑成了别的东西**。

## 二、撑大它的是 M1 的双源合并

`10_clean` 里有 **16 个簇**，前两簇是两个不同的物体：

| 簇 | 点数 | 对角 | 中心 |
|---|---|---|---|
| 0 | 25856 | 6.28 | (2.59, −0.25, −4.79) ← **激光件**（与 raw 中心一致） |
| 3 | 13407 | 5.51 | (−0.15, 3.55, 0.70) ← **照片重建的 fused_dense** |

而 `00_raw/test111.ply` 本身是干净的（2 簇，主体 67074 点、对角 6.54）。

真机 M1 的 `points_in = 1,591,094`（= 激光件 6.7 万 + `fused_dense` 152 万），
`points_out = 41,654`。M1 读取 `10_dense/<件>/fused_dense.ply` 作为「P3 双源融合」
的补充几何，把两块合并进了第一站。

### 为什么原有的 `novel` 判据没拦住

`dense_novel_ratio` 问的是「dense 点距既有几何有多远」，本意识别**冗余**。但两源
坐标系不同时它整个失效：

- 激光件中心 (2.6, −0.1, −4.8)，照片重建中心 (−0.1, 3.1, 0.6)，**相距约一个对角线**
- 于是每个 dense 点都"远离"激光件 → `online_novel_threshold` 的 Otsu 切出
  **novel = 27.19%** > 15% 阈值 → 判「有增量信息」→ 合并

**novel 在异源场景下量的是「两个物体的间距」，不是「新覆盖率」。** 这是判据语义
失效，不是阈值调错。

## 三、干净输入重跑的对照

造一个只有激光件、没有 `10_dense` 的项目，重跑 M1→M3：

| | 30_dense 对角 | in_frame |
|---|---|---|
| 脏链路（合并了 dense） | 20.97 | 45.81% |
| **干净链路** | **6.78** | **100.00%** |

链条闭合：**21% 覆盖率 = 合并 → 壳膨胀 → 投影落到画幅外**。

## 决策

### D1：合并前先问「同不同系」，用**最近邻中位距离的数值**

新增闸门（`M1` 双源合并前）：

```python
_pre = already_aligned(base_points, dense_sample_50k)
rel = _pre["norm_median"]              # 最近邻中位距离 / 对角线
same_epoch = rel <= 0.5
if outputs and (not same_epoch or novel < _DENSE_MERGE_MIN_NOVEL):
    # 不合并；dense_reject = "different_epoch" | "redundant"
```

**用数值，不用 `already_aligned` 的 `aligned` 布尔**。那个布尔容差是 1% 对角线，
只回答「是否已经严丝合缝」——双源互补的合法场景（上半球 + 下半球）中位距离是
**19% 对角线**，会被它判成异源，把该融合的 dense 丢掉（那是数据损失）。

数值本身的区分度很好（都是实测）：

| 场景 | `norm_median` | 判定 |
|---|---|---|
| 互补半球（同物体两面） | **0.19** | 合并 ✓ |
| 真机：激光件 vs 照片重建 | **0.92**（0.9277） | 不合并 ✓ |
| 平移 20 m 的另一个球 | **5.58** | 不合并 ✓ |

阈值 0.5：超过半个对角线就是两个物体，不是同一件的两面。

这把尺子和 ADR-0005/0006 里 X1 用的是同一个（中位距离 / 对角线），这是它在
M1 的第二次应用。

### D2：判定不出来时**不拦**

`already_aligned` 抛异常 → `same_epoch=True`（按可合并处理）+ WARNING +
`metrics["dense_same_epoch"]=None`。理由是保守方向：拦错了会把本来该融合的
dense 丢掉，那是**数据损失**；放行了至少还留着原有的 novel 判据兜底。

### D3：动作与判据必须都进 metrics

`dense_same_epoch` / `dense_epoch_median_rel` / `dense_reject` 三个键进 manifest，
报表能看到「为什么没合并」。只打日志等于没留证据（r16 的教训）。

## 验证

真机跑 M1：

```
M1 跳过 dense 合并：relic_001 的 SfM 稠密几何与激光件**不在同一坐标系**
（中位距离 93% 对角线，容差 1%）
merged=False  reject=different_epoch  same_epoch=False   中位 0.9277
10_clean 对角 13.8 → 6.34，点数 64467（纯激光件）
```

测试 3 项锁住：异源 dense 不合并、不合并时 10_clean 尺度仍等于激光件、
**同系时不被新闸门误拦**（拦错方向同样是缺陷）。

## 追加：重跑 M3 后暴露的第二道闸门（对齐预检）

修完 M1 后重跑 M3→M4，M4 却**降级成了顶点色**：`UV 光栅化为空`，日志里
`invalid value encountered in cast`（UV 有 NaN）。

排查顺序与结论：

| 检查 | 结果 |
|---|---|
| 新网格三角形质量 | 零面积 0、极小 0.01% —— 不是退化 |
| 独立跑 `load_mesh → unwrap_mesh → 光栅化` | **完全正常**（2719074 纹素，util 0.6483） |
| 清空 `99_runs/atlas_cache` 重跑 | 仍失败 —— 不是缓存错配 |
| **关掉 `icp_align` 重跑** | **正常** —— 是对齐那一步动的 |

也就是说：ADR-0009 D3 加的「对齐被拒 → 回退恒等」**没有真正恢复到可用状态**。
日志说「回退原坐标系」，但顶点/法线已经脏了，UV 展开拿到 NaN。

### 更根本的问题：本来就不该对齐

`in_frame_ratio(10_clean, 30 台相机) = 86.7%` —— 这件文物的几何**已经与位姿同系**。
再跑一次对齐是纯损失。

新增 **投影级预检**（比 `already_aligned` 更本质，后者比的是「几何 vs 稀疏点云」）：

```python
def alignment_needed(in_frame: float, threshold: float = 0.5) -> bool:
    return in_frame < threshold      # 一半以上顶点已在画幅内 = 同系
```

在四条对齐路径**之前**判一次，取不到就按需要对齐处理（保守方向）。

### 效果（真机，同一份输入）

| 指标 | 修前 | 修后 |
|---|---|---|
| `coverage_ratio` | 21.22% | **56.81%** |
| `island_fill_ratio` | 31.13% | **87.64%** |
| `in_frame_fraction` | 14.54% | **86.71%** |
| 对齐 | rejected（回退失败） | `skipped / already_in_frame` |

两条修复叠加（M1 不合并异源 + 对齐预检），覆盖率 **21% → 56.8%**，岛内填充
**31% → 87.6%**。这也是决定 X3 图斑是否可信的前置条件。

## 未决

- 真机 `30_dense` / `50_tex` 仍是基于旧 `10_clean` 的产物，要与新 `10_clean` 一致
  需重跑 M3→M4。旧 `10_clean` 备份在 `output/_build/bk_10clean`。
- **`novel` 判据本身没有修**：它在异源时失效这件事现在被前置换闸门挡住了，但如果
  将来出现「部分重叠 + 坐标系略偏」的情形，novel 仍可能给出误导性的数。要彻底
  解决需要在 `online_novel_threshold` 里显式区分「因为坐标系偏」与「因为覆盖新区域」。
- 覆盖率从 21% 提到多少，要重跑 M3→M4 才知道。in_frame 100% 是代理指标，
  真实 coverage 还要看 UV 岛内填充。
