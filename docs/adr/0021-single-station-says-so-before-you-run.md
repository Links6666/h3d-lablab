# ADR-0021：单站直通不是缺陷，但必须说出来

- 状态：已实装（2026-11-04）
- 相关：ADR-0011（双源同源闸门）、ADR-0017（交付核验）
- 代码：`h3d.gui.items.raw_station_counts`、`h3d.gui.constraints.ConstraintsDialog`、
  `h3d.gui.app._log_station_caution`
- 触发：r24 收尾时清点「已知但未做」的条目

## 现象

`00_raw/<件>/` 只有一份点云时，M2 走**单站直通**：把输入原样落一份到
`20_registered/`，`registered=False` / `identity=True` /
`identity_reason=single_scan`，耗时十几毫秒。

界面上看到的是「▶ M2 开始 → √ M2 完成」，灯变绿。**用户的结论是「配准成功」。**
事实是 FPFH + RANSAC + ICP 一次都没跑过。

## 这不是 bug

中小型文物常只有一站扫描（`D:/h3d_relic_test` 的 `relic_001` 就是，
`batch3` 三件也都是）。恒等直通是**正确终态**：没有两份几何，就没有"配准"这件事
可做；强行报失败会让正常项目跑不完。

r21 起报表侧已经写清了：`identity` / `identity_reason` 进 manifest，HTML 里那段
「配准节点在本件没有被执行过，其精度无从判断——路由一口径验证需至少两份错位的
同源几何」。

**问题在时序**：那些文字要跑完、打开报表才读得到。人是在**开跑前**形成印象的
（「我点了生成，它说 M2 完成了」），很少有人会回头翻报表去推翻自己刚才的印象。

## 决定：开跑前说一句，措辞落在「正常」而不是「出错」

| 位置 | 形式 |
|---|---|
| 约束确认框 | 长版（3 行）：说清现象 + 「这是正常终态（不是缺陷）」+ 怎么才能验证 |
| 界面日志 | 一行版：每次开跑都写；对话框关掉之后这是唯一留痕 |
| 「上次已确认 → 不弹框」路径 | 也写日志。回访用户走的正是它，只提示对话框等于对最常走的路不提示 |

`0` 份**不提示**：那是纯照片件（几何来自 SfM），与「单站」是两回事，混在一起报
就是误报——而误报会让用户学会忽略这类提示。

## D1：份数口径复用 runner 的发现规则，不另写

`raw_station_counts` 直接调 `runner.batch_processor.discover_items`。

自己写一份「数 `00_raw/<件>/` 下的文件」看起来更简单，但那条规则里有一条
**不能省**的细节：目录内可以再嵌套采集批次 / 设备子目录
（`00_raw/r1/batchA/s1.ply` + `00_raw/r1/batchB/s2.ply` 是**两站**）。只看第一层
会把两站数成 0 站，而这恰好是「该报的不报」——错在安全侧，所以更难被发现。

这是本项目第 N 次同一个错误：**手写副本必然漂，而且只往一个方向漂**。

## D2：顺带修掉 `ElidedLabel` 的不可重入

跑 GUI 测试时 stderr 一直有：

```
Error calling Python override of QLabel::sizeHint(): AttributeError:
'ElidedLabel' object has no attribute '_min_chars'
```

Qt 会在构造尚未完成 / 析构途中询问 `sizeHint`，那时 `_min_chars` 还没赋值。
它**不会让任何断言变红**，只是喷栈——而打包 windowed 版 `stderr=None`，
等于彻底静默。已改为 `getattr` 兜底，并加测试钉住（`tests/test_gui_widgets.py`）。

## D3：界面文字里的 markdown

第一版提示写成 `直通——**不发生任何配准变换**`，QLabel 是纯文本，截图里原样印出
星号。文档里写惯 markdown，搬到界面上就会忘。加了守卫测试：提示文字里不许出现
`**` 或 `<b>`。

**顺带一条纪律**：GUI 文案改完要截图看一眼。上面两个缺陷（星号、喷栈）都不会
在断言里出现，只有看图才发现。

## 没做的事

- **不把单站升级成 WARNING**（CLI 侧）。它每天都会出现，改成 WARNING 就是训练
  用户忽略警告；GUI 侧那一次提示已经足够，且报表里本来就有结论。
- **不在 M2 里改状态文案**。「M2 完成（单站，无需配准）」已经足够准确，问题从来
  不是日志写错了，而是没人会在开跑前读日志。
- **不给 CLI 加中断式确认**。命令行用户的预期就是「给参数就跑」，加中途提问会
  毁掉批量脚本。
