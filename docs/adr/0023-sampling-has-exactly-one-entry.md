# ADR-0023：采样入口只能有一个，用测试钉住

- 状态：已实装（2026-11-04）
- 相关：ADR-0020（数据来源声明 + 采样定种子）、ADR-0014（ICP 多初值）
- 代码：`h3d.io.sample_surface`（唯一入口）、`tests/test_sampling_single_source.py`（守卫）
- 触发：r24 收尾时自问「这条纪律除了写在 ADR 里，还有别的东西拦着吗」

## 背景：r24 只修了「当时发现的那几处」

ADR-0020 定的纪律是：

> 新代码不要再直接调 `mesh.sample_points_uniformly`。

当时改了 M5 的覆盖率/中误差、X1 的点云转换、`hausdorff_distance`，并把
`geo_align._seed_random` 改成委托。**其余调用点靠自觉。** 而这条纪律的失效方式
恰恰是最难发现的那种：代码能跑、数能出、测试全绿，只有把两次运行的数字逐字
比一遍，才看出 `<1%` 的漂移。

所以这次不看调用点，直接问源码。

## 守卫抓出的四处（其中一处是"假种子"）

| 位置 | 情况 |
|---|---|
| `geo_align._icp_similarity_once`（循环内 ×1 + 收尾 ×1） | `_seed_random(...)` 后紧跟采样 —— 能跑，但"定种子"和"采样"是两个语句 |
| `geo_align.align_points_to_mesh`（粗对齐初值） | 同上 |
| `ctrl_points.refine_mesh_to_points` | 同上 |
| `geo_align.alignment_quality` | **种子调用是空的**：这里用的是 `_sample_surface`（`np.linspace` 索引抽样），根本不碰 Open3D 随机源 |

最后一条是最有信息量的。那行 `_seed_random(_SAMPLE_SEED)` 是上一版实现的遗留，
它告诉读者「这段代码依赖随机采样，别动种子」——**而实际换多少次种子，结果一字
不差**。这种"看起来有约束、实际没有"的代码比缺失更糟：下一个人会为了保护一个
不存在的约束而绕路。

## 决定

### D1：四处全部改成 `io.sample_surface(mesh, n, seed=...)`

种子作为参数进同一个调用，中间插不进别的语句。三个 `_seed_random` 调用随之消失。

### D2：种子不许裸设

`o3d.utility.random.seed(...)` 只允许出现在 `io/mesh_io.py`。
留下「先定种子、后自己采样」的两语句形式，就等于留了一个只做一半的入口。

### D3：删掉 `io.seed_sampling`

它是 r24 为"老调用点"加的逃生舱。四处收敛后**没有任何使用者**——留着就是
D2 想禁的那种用法，只是穿了个体面的名字。删。

### D4：守卫豁免注释与文档字符串

守卫只看代码行：本项目大量注释在解释「为什么不要直接调它」。守卫要是把注释
也算上，就会逼人删掉解释——那比不设守卫更糟。

（实现上做了个朴素的行级状态机跳过 `"""` 块。它不追求完备的 Python 词法分析：
误报会立刻暴露（测试红），漏报则由「代码行里必然带 `.` 和 `(`」兜住。）

## 等价性证据（重构不能改数字）

改的是调用形式，不是算法。四条证据，从弱到强：

1. **构造等价**：`sample_surface(mesh, n, seed)` 的实现就是
   `o3d.utility.random.seed(seed)` + `mesh.sample_points_uniformly(n)`。
   实跑比对：旧写法与新入口**逐点相同**（`np.array_equal` → True）。
2. **单测**：`tests/test_geo_align.py` 的 7/30/90/120/180° 旋转恢复 ≤0.02°，
   断言的是**具体角度**，不是"大概对"。
3. **真机 M4 复算**（`D:/h3d_relic_test` 副本，force_rerun）：

   | 指标 | 重构前 | 重构后 |
   |---|---|---|
   | `texture_overlap` | 5.77 | **5.77** |
   | `texture_multi_view_ratio` | 0.9839 | **0.9839** |
   | `coverage_ratio` | 0.5114 | **0.5114** |
   | `island_fill_ratio` | 0.8264 | **0.8264** |
   | `multiview_color_std` | 40.44 | **40.44** |

   五个数一字不差。
4. **真机对齐确定性**：`align_points_to_mesh`（76197 个稀疏点 ↔ 36781 顶点网格）
   连跑两次，`scale=0.672107`、`accepted=True`、返回值逐位相同。

## 没做的事

- **不做「采样点相等」的运行时断言**。那要在生产代码里存一份上次结果，代价远大于
  收益；确定性是这个入口的**契约**，由测试守，不由运行时守。
- **不把 `SAMPLE_SEED` 变成配置项**。换种子会让所有历史数字作废，而"想要不同样本"
  不是用户需求——需要更密的表面就加 `samples`。
- **不动 `quality.coverage_k_mps` 那类"按 MPS 自适应"的参数**。取样点数与判据阈值
  是两件事，这次只收敛入口。
