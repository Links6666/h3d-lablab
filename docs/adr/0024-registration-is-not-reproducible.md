# ADR-0024：M2 的配准结果不可复现（RANSAC 没定种子），且低可信解不被拦截

- 状态：**部分实装**（定种子已做；「拦截」留作待决，见 D3）
- 相关：ADR-0014（ICP 多初值 + 尺度夹带）、ADR-0020（采样定种子）、ADR-0023（采样入口唯一）
- 代码：`h3d.io.rng.seed_rng`、`h3d.register.run`
- 触发：给论文写「5.2 配准算法验证」时，想把 7/30/90/120/180° 那张表重跑一遍留底

## 发现

按 ADR-0014 的记录，修复后 7/30/90/120/180° 的旋转恢复误差应 ≤0.02°。重跑时
120° 这一档**直接失败**：

```
结论：FAIL    旋转角误差：179.19°（阈值 2.0°）
             配准后中位间距：0.75% 对角线（阈值 2.0%）  ← 间距判据放行了
             fitness=0.5243, low_confidence=True, icp_init=ransac
```

中位间距只 0.75%——**几何贴合得很好**，只是**方向反了 179°**。这正是 ADR-0014
描述的「近似轴对称物体的翻转解」，只不过这次没有被多初值救回来。

## 第一步先排除自己：这不是 r24–r27 引入的回归

`git worktree` 检出 r23（`f2471b3`，即 r24 之前）跑同一用例：

| 代码版本 | 120° 注入的结果 |
|---|---|
| r23（`f2471b3`） | 0.04° / 0.04° / 0.04° / 0.03° — 4 次全对 |
| 当前 | 179.26° / 27.01° / 0.04° — 3 次里 2 错 |

看像回归。但把样本量加到 10 次：

| 运行 | `icp_init` | fitness | 旋转误差 |
|---|---|---|---|
| 1 | flip180_axis2 | 1.0000 | 0.04° |
| 2 | ransac | **0.5216** | **179.26°** |
| 3–10 | — | 1.0000 | 0.04° |

再回头看 r23 的 4 次里也有一次 `icp_init=ransac`。**两边都是随机的**，只是
r23 那 4 次运气好。合并统计：**17 次运行里 3 次解出 179° 翻转解（≈18%）**。

**教训**：判断"是不是回归"时，3 次样本不够。这个项目的失败率就在 10–20% 这一档——
最容易被小样本放过的那一档。

## 根因

`register.run` 从来没有定过种子。RANSAC
（`registration_ransac_based_on_feature_matching`）用 Open3D 的**进程级随机源**
采样对应点对，初值因此随机；而翻转候选是从 RANSAC 解派生的
（`_rotation_about(...) @ init`），初值一歪，三个候选一起歪，最终按 fitness
择优时就是「0.52 的翻转解」对上「更差的其它解」。

与 r24 修的 M5 采样、r27 扫出的四处直调，是**同一类病的第三个消费者**：
随机算法 + 结果进报表 + 没有种子。

## D1（已做）：RANSAC 定种子

```python
# h3d/register/__init__.py
_RANSAC_SEED = 20261105
seed_rng(_RANSAC_SEED)      # h3d.io.rng —— 系统里唯一碰 Open3D 随机源的地方
```

`h3d.io.rng.seed_rng` 是 r24 那个 `seed_sampling` 的**替代品**，不是复活它：
上次那个名字承诺"让采样可复现"，实现只设种子（采不采、采几次不管），是典型的
半成品入口。这次分清楚：

| 入口 | 负责 |
|---|---|
| `io.sample_surface(mesh, n, seed)` | 表面采样（自带种子，不用先设） |
| `io.seed_rng(seed)` | 不经过我们采样函数的随机算法（RANSAC） |

守卫 `tests/test_sampling_single_source.py` 的白名单从 `io/mesh_io.py`
**收紧到 `io/rng.py`**：现在全系统只有一处能碰 `utility.random.seed`。

## D2（已做）：可复现到什么程度，如实说

| 断言 | 结果 |
|---|---|
| 同一进程内两次 `run()` 的变换矩阵 | `max|ΔT| = 2.5e-32`（浮点末位，非"结果不同"） |
| `icp_init` / `fitness` | 相同 |
| 脚本路径 120° 注入 ×5 | 5 次全部正确（0.04° / 0.00°） |

但**不能说"完全消灭"**：

- 5 次样本不足以宣称失败率归零（原来是 3/17）；
- 5 次里有 1 次选中 `ransac` 而非 `flip180_axis2`（旋转都对，0.00° vs 0.04°），
  说明**被选中的初值标签仍有进程间差异**——RANSAC 内部的并行归约顺序没有被
  种子完全约束。

所以本文的措辞是：**定种子后错解未再复现（5 次），但"逐位可复现"只做到
变换矩阵 1e-12 以内，初值选择仍有不确定性。**

## D3（未做，待决）：低可信解要不要拦？

现在 `fitness < 0.55` 只落 `low_confidence=True` + WARNING，**仍然返回 DONE**。
ADR-0014 当初就是这么定的，理由是"真实低重叠场景确实存在"。

这次的反例说明这条规矩有代价：**fitness 0.52 的 179° 翻转解会被下游当成正常
结果**（M3 稠密重建会按错位姿合并点云，ADR-0011 记录过这类灾难）。

但升级成 FAIL 也有代价：两站只重叠 40% 的真机数据，fitness 就是 0.4–0.5 ——
那是**合法的难**，不是错。用绝对阈值一刀切会把正常项目判死。

**这条不该由实现者单方面定**，因为它是"宁可失败"和"宁可出结果"之间的产品取舍：

| 方案 | 好处 | 代价 |
|---|---|---|
| A. `fitness < 0.55` 判 FAIL | 错解进不了下游 | 部分重叠的正常数据被拒 |
| B. 保持"只标不拦" | 不误杀 | 错解照样进下游，只靠人看 WARNING |
| C. 加朝向判据（翻转检测） | 精准拦错解、不误杀 | 要新增一个可验证的判据；轴对称物上仍可能判不出 |

倾向 C，但 C 需要先想清"用什么量判朝向"——**这本身是一个新的研究点**，不该在本轮
仓促落地。已记入论文骨架 §2.2「不可引用」与 §4 答辩预案。

## 没做的事

- **没有为了"5 次都过"去换种子**。换一个种子让失败消失，就是拿随机性掩盖缺陷；
  种子值本身不该是被调出来的。
- **没有改 `_MIN_FITNESS = 0.2` 这道硬失败门**。它是"重叠严重不足"，与 0.55 那道
  "可信度"是两个语义。
- **没有动 `--noise` 注入口径**。0.2% 对角线的噪声模拟"两站独立扫描"，是原文的
  设定；换成无噪会让失败不复现，也就测不出问题。
