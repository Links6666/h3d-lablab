# ADR-0013：`capture_meta` 位姿约定用「稀疏点投影」判定，不用 `det(R)`

- 日期：2026-11-03
- 状态：已实装（`normalise_pose_convention`）
- 触发：`projected_cameras = 11/30` 一直没解释；查出 **19 台相机一条纹素都投不上**

## 现象

真机 `90_meta/relic_001_capture_meta.json` 30 条位姿，M4 报
`projected_cameras = 11`。逐台量「能看到多少纹素」：

| | 能看到多少纹素 | 投影区亮度 |
|---|---|---|
| 11 台 | 6 % ~ 83 % | 91~155（看着采到了文物） |
| **19 台** | **一个都没有** | — |

不是权重问题（「看得到却不被选」的是 0 台）。查 `R`：都正交、`det=+1`、
内参一致——不是格式损坏。

## 根因：文件是 2026-09-15 修复**之前**的老格式

`parse_images` 的注释记着那次修复：COLMAP 的 `images.txt` 存
`X_cam = R_co·X + tvec`（前方 **+Z**），而管线统一成
「`t` = **相机中心**、前方 **−Z**」：

```
C = -R_co^T · tvec      # 相机中心
R = -R_co               # 前方变为 -Z
```

真机文件里存的是 **`R_co` 和 `tvec` 本身**（逐条对比 `images.txt` 确认：
`R_json = -R_parse`、`t_json = R_parse @ C_parse`）。管线按新约定读它，
等于把 `tvec` 当成了相机位置。

**决定性验证**：用 COLMAP 自己的 `points3D.txt`（方位与之同系，三角化出来
的点必须能投回画幅）：

| 解释 | 稀疏点入画 |
|---|---|
| 当原生 `(R_co, tvec)` 读 | **95.6 %，30/30 台** |
| 按管线 `(R, C)` 读 | 5.25 % |

所以文件是对的，**读法错了**。

## 为什么 `det(R)` 不能当判据

第一版我用 `det(R)`：新约定 `R = -R_co` ⇒ det 差一个符号，看起来精确。
写完测试才发现它**会误伤合法文件**——`R` 与 `-R` 给出**完全相同的 u/v**，
只翻转 z 的符号；一个手写的位姿完全可以 `det=+1` 而完全正确（
`tests/test_texture/test_atlas_delivery.py` 里就有这样一个合成位姿，被这个
判据判成「原生格式」而读坏）。

判据必须来自**数据**，不能来自矩阵的形状。

## 实装

`normalise_pose_convention(images, cameras, probe_points)`：

1. 用 SfM 稀疏点当探针（与位姿同系，M4 本来就要读它做对齐）；
2. 两种解释各投一遍，算「落在任一台画幅内的点比例」；
3. 转换后更高且过阈值 → 就地转换并 WARNING；否则原样；
4. **判不出来（两边都达不到阈值 / 没有探针）→ 报 `unknown` 且不动**。

第 4 条是刻意的：猜错方向与不猜是两种损失，前者更糟——它会把本来正确的
位姿改坏，而且改完仍然"能跑"。

调用点在 `texture_mesh_from_photos` 里、**任何投影之前**（含对齐预检）。
metrics 新增 `pose_convention` / `pose_probe_as_is` / `pose_probe_converted`。

`CACHE_VERSION` 2 → 3：位姿改了会改变参与采样的相机集合，图集内容随之变化，
旧缓存会把「用错位姿算出来的图集」当命中复用——那是**错误的纹理**。

## 这次修复推翻了之前的几个结论（重要）

修完重跑 M4：

```
pose_convention      colmap_raw
pose_probe_as_is     5.25% → 100.00%
coverage_ratio       0.0000        （之前 0.5681）
cameras_blind        30/30         （之前 19/30）
island_fill_ratio    0.0000        （之前 0.8764）
```

也就是说：**之前那个 57 % 覆盖率、87.6 % 岛内填充、X3 的 0.31 %/4 处，
全部建立在读错位姿的基础上**。那 11 台「能投上」不是真对齐——`in_frame`
只判「落在画幅矩形内」，不判「落在文物上」。这条和 ADR-0009 D3 的教训是
同一条：**判据要能区分「像」与「对」**。

更要紧的是它骗过了一道闸门：ADR-0011 加的「几何已在画幅内 → 跳过对齐」
在错位姿下算出 `in_frame = 86.7 %`，于是正当放行——判据在垃圾数据上触发，
产出看着合理。**任何以位姿为输入的预检，都必须先确认位姿本身可信。**

## 未决

- 位姿修正后，激光网格与 SfM 模型确实不是同一个坐标系（`10_dense` 100 %
  入画，激光件 0 %），必须靠对齐把它们拉到一起。
- 当前自动 ICP **被拒**：`对齐后源点云包围盒是网格的 0.43 倍（允许
  0.70~1.30）`。两边 99 % 分位对角线本来只差 3 %（6.04 vs 6.20），尺度估计
  却掉到 0.43 —— 相似变换没收敛，这是下一个要查的点。
- 真机 `capture_meta.json` 应重跑 S1 重新生成（现在这条会 WARNING 并自动
  纠正，但文件本身仍是老格式）。
