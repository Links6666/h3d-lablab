# ADR-0025：朝向判据 —— 用「法线一致性」拦翻转解，而不是拿 fitness 一刀切

- 状态：已实装（2026-11-06）
- 相关：ADR-0024（配准不可复现 + 低可信解不拦）、ADR-0014（多初值）
- 代码：`h3d.register.evaluate.normal_agreement`、`h3d.register.run`、
  `h3d.runner._stage_register`
- 触发：ADR-0024 D3 把「该不该拦翻转解」留成 A/B/C 三方案，用户选 C

## 三方案的问题在哪里

ADR-0024 记录：`fitness < 0.55` 只标记不拦截，于是 179° 翻转解能进下游。

| 方案 | 问题 |
|---|---|
| A：`fitness<0.55` 判 FAIL | 误杀「只重叠六成」的**正确**解 |
| B：保持只标不拦 | 错解照样进下游 |
| C：加朝向判据 | 要先回答「用什么量判朝向」 |

A 的误杀不是假设。实测（真机 `test111.ply`，按平面把 target 切到 60% 模拟部分重叠）：

| 场景 | fitness | 法线一致性 |
|---|---|---|
| 正确解，target 完整 | 1.0000 | **+0.978** |
| **正确**解，target 只剩 60% | **0.2329** | **+0.847** |
| 翻转解（ICP 到收敛） | 0.10–0.21 | **−0.52 ~ −0.60** |
| **真机 179° 翻转解**（ADR-0024 现场） | **0.52** | **−0.369** |

第二行就是 A 会杀掉的那类：fitness 掉到 0.23（离 0.2 硬门一步），但它是**对的**。
而第三、四行说明：**fitness 与"对错"不单调**（0.52 的错解与 0.23 的对解重叠），
法线一致性却以 0 为界把它们分开。

## D1：判据定义

```
normal_agreement = mean( <R·n_s , n_t[idx]> )   在 ICP 内点集合上
```

1. 把 source 按候选变换搬到 target 坐标系；
2. 找最近邻，**只取内点**（`d <= icp_distance`，与 fitness 同一口径）；
3. 两边法线各自先归一到「整体外向」约定，再逐点求点积取均值。

内点少于 50 个返回 `None`（"没量出来"≠"方向一致"）。

### 为什么必须先做「外向归一」

`orient_normals_consistent_tangent_plane` 只保证**各自内部**一致，不保证两朵云
之间一致。实测同一件文物的 source=+1、target=**−1**（符号整体相反），
不归一的话正确解会算出 **−0.98**，判据直接反号。

`outward_sign()` 用「法线与（点−质心）同向的比例过半」定符号。对闭合/环扫件成立；
单面扫描时这个量本来就弱，所以它**只用来归约符号**，不单独当质量指标。

## D2：闸门是**两个条件同时成立**，不是单看方向

```python
if na is not None and na < -0.2 and fitness < 0.55:
    raise RegistrationError("配准方向相反…")
```

| 情形 | 处置 | 依据 |
|---|---|---|
| fitness 低 + 方向反 | **判失败** | 真机 0.52 / −0.37：贴不牢又反了，就是翻转解 |
| fitness 低 + 方向正 | 只标 `low_confidence` | 实测 0.23 / +0.85：合法的低重叠 |
| fitness 高 + 方向反 | **不拦** | 物体近似对称，翻转与正解不可区分；拦了也只是二选一 |

第三行是这条判据的**已知边界**：近凸/近轴对称的物体上，翻转解在几何上与正解
等价（合成球体实测翻转后一致性仍 +0.9），判不出来——但那种情况下也**没有更好的
解可选**，拦掉只是把可用的结果扔掉。

### 为什么是 −0.2 而不是 0

这个量是逐点法线点积的均值，在小型/近球状合成点云上会在 0 附近抖。第一版取
`< 0` 当门，端到端测试因此**偶发误杀**（bumpy sphere 夹具上一次 −0.369 的翻转解
其实 fitness 0.95，属于"分不清"）。真机翻转 −0.37~−0.60、正解 +0.85~+0.98，
中间留 0.2 的死区只损失"明确性"，不损失"判定力"。

## D3：三处同步（这里最容易漏）

`register.run` 算出来之后，必须：

1. 进 `metrics["normal_agreement"]`（诊断可见）；
2. 进 `_stage_register` 的**手写白名单**（`normal_agreement_s02` + 顶层）——
   第一版漏了这一步，脚本跑出来 metrics 里根本没有这个键，闸门成了摆设；
3. 闸门在 `run()` 里，抛 `RegistrationError` → 走失败隔离（不进 M3）。

第 2 条是 r16 那个坑的第三次复现（阶段清单、`manifest_metrics`、M2 metrics
都是手写挑选）。**上游算得再对，不写进白名单就等于没算。**

## 真机验证

定种子 + 朝向闸门之后，`scripts/verify_registration_e2e.py` 五档全过：

| 注入 | 旋转误差 | fitness | `normal_agreement` |
|---|---|---|---|
| 7° | 0.03° | 1.0000 | +0.978 |
| 30° | 0.04° | 1.0000 | +0.978 |
| 90° | 0.00° | 0.9999 | +0.978 |
| 120° | 0.04° | 1.0000 | +0.978 |
| 180° | 0.00° | 0.9999 | +0.978 |

**没有一次被闸门误拦**——这是 C 相对 A 的全部意义。

## 没做的事

- **没在合成夹具上断言"翻转必为负"**。近凸团块上翻转的正解与错解在几何上等价，
  写那种断言只会骗自己（第一版写了两条，删了）。判据的分辨力由上面的**真机实测表**
  背书，闸门接线由 monkeypatch 单测覆盖——两者分开测，各自可信。
- **没改 `_LOW_CONFIDENCE_FITNESS`**。它仍是"可信度"的界，只是现在多了一个
  「且方向反」的升级条件。
- **没给 `normal_agreement` 加报表列**。它是 M2 的诊断量，先保证进 metrics 与
  失败文案；报表要不要显示等真机两站数据出现再定（现在所有真机件都是单站）。
