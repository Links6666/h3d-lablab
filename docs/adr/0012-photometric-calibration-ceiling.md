# ADR-0012：纹理色调问题的「代码上限」已经探到底

- 状态：已接受
- 日期：2026-11-02
- 关联：ADR-0008（X2 缺色卡）、ADR-0011（M1 双源 + 对齐预检）

## 背景

M4 融合出的纹理有肉眼可见的**岛间色调跳变**，X3 把它当成异常。已经确认的链条：

```
X3 的 9 处图斑 ← 岛间色调跳变 ← 同一纹素在多视角下颜色不一致
```

已做的两步与效果：

| 措施 | 效果 |
|---|---|
| 逐相机灰度归一化（`balance_exposure`） | `multiview_color_std` 32.67 → 29.06（−11%） |
| 岛内强平滑（仅作判据，不可用于交付） | X3 异常 0.5179% → 0.1086%（−79%） |

11% 与 79% 的巨大差距说明：**剩下的 68 个百分点不是"亮度均值的系统性偏移"**。
于是去问：更**强**的模型——多视图光度校准——能不能吃掉它？

## 一、光度校准的理论上限（实测）

标准做法把观测建模为「真实颜色 × 相机增益」，在对数域是双向固定效应：

```
log c[i,k,ch] = mu[i,ch] + g[k,ch] + 噪声
```

交替估 `mu`（逐纹素）与 `g`（逐相机），固定一台相机为参考。校正后的残差就是
**这个模型能达到的下限**——不需要真值，也不需要改产品代码。

真机结果（6 万抽样纹素，86% 被 ≥2 台相机看到，平均 5.4 个视角）：

| | 视图间色散（log 域 RMS 中位） |
|---|---|
| 校正前 | **0.4028**（≈40% 亮度抖动） |
| 校正后 | **0.4038**（−0.2%，等于没降） |
| 各相机增益偏差 | 中位 **0.0%**，最大 15%（cam02 的 R 0.853） |

**校正无效的原因很直接：相机之间本来就没有多少可校正的东西。** 增益偏差中位
是 0.0%——大多数相机的响应几乎一致。既然"要校正的量"接近零，校正当然降不下来。

## 二、那 40% 的色散来自哪

既然不是相机响应，剩下的候选只有三个：

1. **局部光照不均**——同一盏灯照到物体不同部位照度不同，与相机无关；
2. **斜视**——`cos > 0.3` 允许到 72°，极端斜视下不同视角看到的是**不同的表面**
   （不是同一表面的不同颜色）；
3. **遮挡**——探针没有做 z-buffer 剔除（产品代码有），部分样本采到了对侧的颜色。

第 3 点说明探针的**绝对数值偏高**（产品内 `multiview_color_std=32.67`，
折算约 13%），但**不影响"D1 的增益很小"这个结论**——增益是按视角间差异估的，
遮挡噪声会让它**偏大**而不是偏小；偏大都没东西可校正，真实情况只会更少。

## 决策

### D1：不做多视图光度校准

上限已经实测：增益偏差中位 0.0%。投入半天做产品化，预期收益接近 0。
这一条写进 ADR 是为了**防止将来有人（包括我）再想起这个方向**。

### D2：色调问题的剩余部分归入「采集」，不再用代码追

1、2 两个来源都是采集问题：光源布置（消除局部照度差）与拍摄角度（减少斜视）。
它们与 ADR-0008 里 X2 缺色卡是**同一类问题的不同切面**——都是"照片本身的物理
条件不够好"，代码只能在事后猜测。

保留 `balance_exposure`（默认关）作为 11% 的免费改善；不再往这个方向投力。

### D3：这个结论本身要写进论文

「我们尝试了逐相机归一化（−11%）与完整光度校准（−0.2%，上限受限于增益本身
≈0），确认瓶颈在采集而非算法」——这比声称"我们的融合算法很先进"更有分量，
也是 ADR-0011 里"先量后判"方法论的又一个实例。

## 未决

- **探针没做遮挡剔除**：绝对色散值（40%）高于产品内实测（13%）。要做更精确的
  归因（光照 vs 斜视各占多少），需要在探针里加 z-buffer，并把样本限制在
  `cos > 0.7` 的准正视视角上。**但这只影响"归因比例"，不改变"代码到头"的结论**，
  所以本批不做。
- 局部光照不均可以在**采集侧**用更多、更均匀的光源解决，也可以在**算法侧**用
  逐纹素的照明补偿（把光照当作另一个自由度）——后者是研究课题，不是本轮范围。
