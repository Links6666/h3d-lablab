# ADR-0005：X1 真机首次验证的四个缺陷，与 S0 数据可行性探测

- 状态：已接受
- 日期：2026-11-01
- 关联：ADR-0003（X3 单期检测）、ADR-0004（X4 时序追踪）、
  《彩绘文物数字化管线 X1/X2 与语义·仿真·复原模块构建指南》第 2、3、4、8 章

## 背景

按指南 8.1 的路线图（P0 接口骨架 → P1 X2 → P2 X1 → **P3 S0** → P4 S1/S2），
P0/P1/P2 的代码都已完成，S0 是下一阶段。但两项事实必须先核清：

1. **X1 在真机上从未跑过**。1.1.12 的 manifest 里 X1 一直是 `disabled`，且
   `00_ref/`（参考期）不存在。24 项单元测试通过 ≠ 能在真实项目上出数。
2. **S0 需要标注数据**。指南 4.3 的流程是「MobileSAM 半自动标注 → 人工校对 →
   训练 YOLOv8n-seg」。没有可标注的病害实例，训练链路无从谈起。

本 ADR 记录这两项核查的结果。

---

## 一、X1：首次真机验证，发现四个缺陷

启用 X1（`runner.x1_enabled=true`）并造一份同源参考期（从当期网格采样），
用一个**可证伪的判据**跑：**两期同源 ⇒ `max_change_mm` 必须接近 0**。
实际跑了五次，每次都被这个判据打回：

| 次序 | 现象 | 根因 | 修法 |
|---|---|---|---|
| 1 | `skipped`（缺当期几何） | 硬拼 `10_dense/<件>/fused_dense.ply`，而那是 **COLMAP 稠密点云（场景②）**；激光件（场景①）的几何在 `30_dense/` | `_current_geometry()` 候选链：`10_dense` → `sfm_tmp` → `20_registered` → `10_clean` → `00_raw` → `30_dense` |
| 2 | `max_change=1181mm` | 网格 PLY 被 `read_point_cloud` 读成**顶点**（不报错）；泊松重建后顶点分布极不均匀，与参考期均匀采样的密度差一个量级 | `_load_any_as_cloud()` 先当网格读，**有三角面就均匀采样**；不靠「点数 ≥100」判断（小球的 114 个顶点刚好过关） |
| 3 | `max_change=nan`（1024 点全 NaN） | 核心点用 `regular_corepoint_grid` 铺在 **XY 平面**上（Z 是常量），立体文物上网格面与表面完全错开，M3C2 的圆柱里没有点 | `corepoint_grid()` 改成**从点云抽样**；判据用「核心点 Z 起伏 vs 点云 Z 起伏」 |
| 4 | `max_change=450mm` | `estimate_mps` 抽样到 2 万点后再算最近邻，测到的是**抽样后的间距**（放大 `sqrt(200k/20k)=3.16` 倍）。M3C2 的尺度全是 MPS 倍数 → 圆柱 48mm、max_distance 812mm，在凹槽处抓到隔面点 | 抽样后按 `sqrt(m/n)` 校正；判据用「MPS 不应随 `sample_limit` 变化」 |
| 5 | `max_change=177mm`（当时未达标） | **已定案（ADR-0006）**：不是尺度错，是候选链把 `10_dense/fused_dense.ply`（照片重建，与激光件差 **5541mm**）当成当期几何 | 两期同源闸门 `_epoch_consistency` + 候选链逐个过闸门；符号定向见 ADR-0006 发现 1 |

### 现状（必须随结论一起给出）

- X1 **已能真机跑通**：不再 skip、不再输出 `nan`，产出交付目录下的
  `<件>_X1_m3c2.json` 并并入 `accuracy.csv`。
- 第 5 项已由 **ADR-0006** 定案：`scripts/verify_x1_sensitivity.py` 用合成已知形变
  标定，三档线性度 1.000/0.998/1.001，同源两期报 0.000mm——**M3C2 的尺度本来就对**。
  当时的 177mm 来自「两种传感器的两份几何被当成同一件的两期」，不是 M3C2 的错。
- 现在的口径：`calibrated` 默认 `True`（尺度链路已验证），**但数字仍受输入约束**
  ——两期必须过同源闸门才出数，否则 `SKIPPED` 并留下每个候选的实测差距。
- 仍然**没有真实两期数据**，所以「检测能力」在真实风化/堆积上的表现无法评价，
  只能说「已知形变能被准确量到」。

### 下一步

已按第 2 条路走完（合成已知形变），结论见 ADR-0006。第 1 条路（CloudCompare
交叉验证）仍未做，本机未装；本次以合成真值替代，理由是合成真值比外部软件更硬
——它给了注入值与报出值的逐档对应表，而不只是另一套实现的数字。

## 二、S0：数据可行性探测——**这件文物标不出训练数据**

按「先验证前提，再上工具」的顺序，没装 MobileSAM/torch（约 2.5 GB），
先用现成产物回答一个问题：**1.1.12 上有没有可归类的病害实例？**

做法：取 X3 输出的 44 个 ≥24 texel 连通域里面积最大的 16 个，按 `crop_box`
裁出上下文（4×4 拼图），人工逐格判读；另附全图 1/4 缩略。

### 结果

| 观察 | 事实 |
|---|---|
| 16 个候选区的形态 | **全是「UV 岛边界 / 材质交界」**：浅灰白（胎体/粉底层）与深褐（土渍/残存彩绘）相接，边缘锐利 |
| 裂隙 | **未见**。16 格与全图缩略里都没有细长黑线形态 |
| 起翘 / 脱落 | **未见**。没有带阴影的翘边、没有胎体凹陷的明暗结构 |
| 残存彩绘占比 | **1.89%**（`chroma>15` 的面积比，ADR-0003 D15） |
| 全图印象 | 褐色 + 灰白的斑驳马赛克，无贯穿性缺陷 |

### 结论

**1.1.12 不适合做 S0 的训练数据。** 原因是数据层面的，不是代码层面的：

- S0 的价值在「病害**类别**」。而这件文物表面呈现的是「胎体/土渍/彩绘残迹」的
  自然斑驳，没有可供标注的异常形态。
- 若硬标，可用的类别只有「彩绘 / 胎体」——那是 ADR-0003 D15 已经做掉的**域分类**，
  S0 再做一遍没有增量价值。
- MobileSAM 只是标注的**加速手段**，不是前置条件。前置条件是**有东西可标**。

### 需要什么才能开 S0

一件**病害形态明确**的文物，至少覆盖 2~3 类：

| 类别 | 形态特征 | 1.1.12 上有吗 |
|---|---|---|
| 裂隙 / 开裂 | 细长黑线、有分支、跨多个面 | 无 |
| 起翘 / 脱落（掉彩） | 彩绘翘边带阴影、底层露出且边界不规则 | 无（彩绘仅 1.89%） |
| 污渍 / 变色 | 局部的、与底色不同的弥散区域 | **可能有**（深褐区） |
| 胎体残缺 / 孔洞 | 岛内出现真空洞（不是岛间空隙） | 待查 |

## 三、代码侧结论

- **S0 的接口与依赖现在就能开**（P0 已完成，4 GB 显存够 MobileSAM 9.66M +
  YOLOv8n-seg 3.4M，分时调度）。阻塞点纯在数据。
- **X1 的四个缺陷已修并各有回归测试**（`tests/test_runner/test_stage_x1_inputs.py`
  9 项），其中三个是「从未真机跑过」的直接后果——**这类缺陷只有真跑一次才会暴露**。
- X1 的第 5 个缺陷（M3C2 尺度标定）不应靠猜参数推进，要先有标定手段。

### 附带发现：X1/X2 排在 M6 之后，论文表永远慢一轮

`_reorder_ext_stages` 把 X1/X2 放在最后，而报表在 M5、论文表在 M6 生成——两者
都**读不到本轮**的 X1/X2 结果。实测：本轮 `accuracy.csv` 的 X1 列要跑**第二次**
才更新为「未标定」，第一次仍是上一轮的 177.33。

`accuracy.csv` 之所以能及时更新，是因为 `_append_x1_to_accuracy` 在 X1 阶段
**事后追加**；论文表没有这条补丁，所以滞后。

这与 ADR-0003 D8 是同一个病：X3 当初就是为它才被插到 M5 之前。X1/X2 同样应该
插到 M4 → P1 → X3 **之后、M5 之前**（它们的输入只到 M3/M4，不依赖 M5）。

本批**不动顺序**：改它要同步 `_reorder_ext_stages`、GUI `STAGE_ORDER`、两套进度
权重与相应测试，风险大于收益，且用户重跑一次即可。但这是必须在 S0 接线前解决的
——S0 的类别统计也要进同一批报表。

## 未决

- ~~X1 的 M3C2 尺度标定~~ → **已完成，见 ADR-0006**（合成已知形变，线性度 1.000）。
- **X1/X2 阶段顺序**：应移到 M5 之前（见上），否则报表与论文表永远慢一轮。
  移序前须先补 `report/html_export.py` 的 `_STAGE_ORDER`（只有 8 项、缺 X1/X2，
  而它是完成率分母 `len(items)*len(_STAGE_ORDER)` 的来源）——现在这两个阶段排在
  M6 之后、报表早已生成，漏算看不出来；一旦前移就会让分母与「件数×阶段数」的
  跨层契约对不上。
- **真实两期数据**（同一件隔期复扫，ADR-0006 未决首项）。
- `30_dense/relic_001.ply` 与激光件反向互最近邻 6895mm，疑似含激光件之外的几何
  （多件合并 / 未裁背景）——须先看清内容，否则同源闸门会把这类件一直挡成 SKIPPED。
- 第二件病害明确文物的采集；在此之前 S0 只能停在「接口就绪」。
- X2 色差阶段同样从未真机跑过（1.1.12 上 `x2_enabled=false`），且它依赖
  色卡照片的定位链路——需要同样做一次「可证伪判据」的验证。
