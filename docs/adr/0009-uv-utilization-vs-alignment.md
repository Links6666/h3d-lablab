# ADR-0009：UV 利用率是 68%（正常），真正的问题是对齐把几何搬走了

- 状态：已接受（诊断结论；修复待下一片）
- 日期：2026-11-01
- 关联：ADR-0002（配准：自报 rmse 不可信）、ADR-0005/0006（「先量真值再猜参数」）

## 背景

盘点真机 manifest 时发现两件怪事：

1. `output/run_manifest.json` 里 M4 只有 6 个指标键，`atlas_utilization`
   根本不存在——报表只能印 N/A；
2. 从 diffuse 图直接量，非黑像素只占 **0.92%**，看着像「UV 图集 99% 是空白」。

「UV 打包浪费 99% 分辨率」是个大结论（改 unwrap 参数、可能改 M4 架构），
所以在动手前先量清楚。ADR-0006 的纪律：**先造判据，再猜原因**。

## 一、UV 利用率是 68%，完全正常

用当前 `_rasterize_uv` 对真机模型（73751 面 / UV 范围 0~0.9995）重算：

| 口径 | 值 | 说明 |
|---|---|---|
| 光栅化覆盖纹素 | 2,852,678 | `len(flat)`，含重复 |
| 去重后不同纹素 | 2,852,678 | **与上一行相同**（岛间无重叠） |
| **UV 岛占比** | **68.01%** | 2048² 里 68% 被 UV 覆盖 |

**UV 打包没有问题，甚至偏好。** 「0.92% 非黑」不是 UV 的锅——那是**着色**的比例，
不是 UV 覆盖的比例。三个口径必须分开：

```
atlas_utilization   = UV 岛面积 / 图集面积        → 68.01%   （UV 展开/打包质量）
coverage_ratio      = 真正着色纹素 / 图集面积      → 见下     （投影覆盖质量）
island_fill_ratio   = coverage / utilization      → 见下     （岛内填满程度）
```

顺带发现一个计量瑕疵：`utilization = len(flat)/size²` 用的是**去重前**的覆盖点
（下一行才 `np.unique`）。本次因为岛间无重叠两者相同，但理论上会偏大。不影响结论，
记录待改。

## 二、真机那次跑的是旧版代码

真机 manifest 的 M4 只有 `coverage_ratio / texture_size / triangles /
projected_cameras / paint_mode / poisson_*` 六个键——不是白名单裁剪（M4 直接返回
全量 metrics），而是**那次运行的代码版本还没算这些指标**。与 X3 缺 mask 是同一个
根因（产物版本旧）。

用当前代码重跑真机 M4（`paint_mode=photo`，2 分钟内），指标齐全了。

## 三、真正的问题：`icp_align` 把几何搬到相机视野外

同一份输入，只改 `geometry_is_sfm` 一个变量：

| 配置 | `coverage_ratio` | `island_fill_ratio` | `in_frame_fraction` | `projected_cameras` |
|---|---|---|---|---|
| 跳过对齐（`geometry_is_sfm=True`） | **21.22%** | 31.13% | 14.54% | 20 |
| **走 `icp_align`**（激光件） | **1.16%** | 1.70% | **1.46%** | **3** |

**对齐之后比不对齐差 18 倍。** 相机数从 20 掉到 3，说明几何被搬到了一个大多数
相机都看不到的位置。

这正是项目记忆里那条硬约束的现场复现：

> 「合格」的对齐也可能不如「不做」：先问 `already_aligned`（中位距离 <1% 对角线跳过）。

`already_aligned` 预检没拦住它——因为**几何与 SfM 点云本来就不同源**（激光件 vs
照片重建，ADR-0006 量过互最近邻中位 5541mm），预检只会得出「需要对齐」，
而对齐本身失败了，失败结果被直接采纳。

### 两个可见性指标差 48.7 个百分点

`normal_visible_fraction=63.29%`（法线夹角）vs `in_frame_fraction=14.54%`
（真投进画幅）。代码自己的判据写在 `photo_texture.py:329`：

```python
elif in_frame_fraction < 0.85:
    log.warning("...只有 %.0f%% 纹素落在任一图像画幅内——问题在**几何与位姿的"
                "尺度/平移对齐**，不在法线；请核对 M4 的 icp_align 结果（accepted）与 "
                "scale.reference_diag")
```

判据是现成的，但它**只是 WARNING，不影响任何决定**——对齐照旧被采纳。

## 决策

### D1：UV 打包不动

68% 是正常值。**不要**因为「图集非黑比例低」去改 unwrap/xatlas 参数——那是在修
一个不存在的病。这个误判会浪费大量工作时间，所以写进 ADR 而不是只记日志。

### D2：`utilization` 改用去重后的纹素数

`len(np.unique(flat))`。当前因岛间无重叠结果相同，但口径要对。

### D3（待做）：对齐必须有**投影级**验收判据，失败回退恒等

`already_aligned` 只能回答「要不要对齐」，回答不了「对齐得对不对」。真正的验收量
是 `in_frame_fraction`——它直接量「几何还在不在相机视野里」。

方案（下一片刻意做成独立小步）：

1. 对齐前后各算一次降采样（2 万点）的 `in_frame_fraction`；
2. 对齐后明显低于对齐前 → **回退恒等**，`icp_align.status="rejected"` 并写明两个数；
3. 阈值不能拍脑袋，要用合成点云标定（同 ADR-0006 的方法）。

风险：M4 是核心阶段，回退逻辑写错会让原本能用的件变差。所以先有测试再有改动。

## 未决

- **D3 未实装**：本轮只诊断。在它实装前，激光件（`raw_paths` 非空）的 M4 覆盖率
  会一直偏低，且**用户看不出来**（旧版报表连 `in_frame_fraction` 都没有）。
- 真机 `rmse_mm=6940`（6.9 米）而 `status=pass` —— 与 `units_plausible` 有关，
  是另一条线的问题，本 ADR 不处理。
- UV 图集里 `_L1.0_mask.png` 缺失（旧产物）已由 ADR-0008 那批的 X3 修复记录在案。
