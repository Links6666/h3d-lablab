# ADR-0018：布局迁移要「搬账」—— 不然账本指向已经不存在的路径

- 状态：已实装（2026-11-03）
- 相关：ADR-0017（交付核验）、ADR-0007（阶段清单单一真源）、`paths.migrate_legacy`
- 代码：`src/h3d/core/paths.py`、`src/h3d/gui/app.py`、`h3d.delivery_verify`

## 怎么发现的

给 GUI 接「核验交付包」按钮后做真机冒烟：同一个项目，命令行 `h3d verify` 报
`PASS 23 / FAIL 0`，而在 GUI 里点按钮变成 `FAIL 1`——「manifest 有 13 个产物
不在磁盘上」。

原因不是按钮，是**打开项目时的自动迁移**：GUI 把旧布局的目录搬进 `阶段成果/`，
但 manifest 里记的是**绝对路径**，一条都没改。搬完的那一刻，账本全指向已经不
存在的位置。

## 三个缺陷，同一个病根：只搬东西，不搬账

### D1：迁移清单漏了三个**当前**阶段的目录

`_STAGE_CHILDREN` 是手写的迁移候选，缺 `10_clean` / `20_registered` / `60_qc`
——而 M1 / M2 / X3 就写在这三个目录里。真机现场：迁移后它们留在项目根，而
进程内 `stage_root()` 已指向 `阶段成果`，等于新布局里找不到 M1/M2/X3 的产物。

目录名散落在多处（`runner` 里 `os.path.join(task.root, "10_clean", …)`、
`cli.py` 的一张手写清单、这里的迁移清单），**每一处都是全集的副本**。这次是
迁移清单那份漂了。已补齐，并在注释里写明「新增阶段目录时三处都要对一遍」。

### D2：manifest 的绝对路径不重写

`90_meta/*.json` 与 `output/*.json` 里的 `outputs` 全是绝对路径。搬完目录，
它们集体失效 → 断点续跑全部重算（photo 模式每件 2 分钟）、`verify` 当场
FAIL 13 条。

`_rewrite_json_paths` 递归重写 dict/list 里的字符串，只替换**路径边界**匹配的
前缀（`/30_dense` 不该匹配 `/30_dense2`），并且：

- **原子写**（先 `.tmp` 再 `os.replace`）：派生状态写一半崩掉，manifest 会变成
  不可读的半截文件，比不改更糟。
- **按规范化斜杠比较**：真机上见过 `D:/proj\output\...` 这种混用分隔符的写法，
  按原样 `startswith` 会静默漏掉——**改了等于没改**。

### D3：半迁移的项目永远修不好

`legacy_dirs_present()` 有一道闸门：`<root>/阶段成果` 已存在就返回 `[]`。
这道闸门是必要的（`output` / `report` 是通用名，否则会把仓库 `output/` 整棵
搬走，踩过 167 个目录），但它带来一个副作用：**旧版本迁移过一次之后，项目就
卡在「目录新、账本旧」**，再也不会自动迁移。

所以重写账本不能只按「**本次**搬了什么」，还要**推断**：哪个旧根级目录已经
不存在、而新位置的同名目录存在。`_infer_moved_prefixes` 做这件事，判据是
「旧的不在 + 新的在」，不会误伤仍合法留在根级的同名目录。

### D4：`config.yaml` 里的 `runner.manifest` 同样会失效

它是绝对路径。失效后果比看起来严重：下次跑会**在旧位置新建**一份 manifest，
新旧两份并存（split-brain）——旧的记得哪些阶段已完成、新的从零开始，断点续跑
彻底失效。

迁移时一并替换（只替换刚搬走的那几个前缀，不做通用 YAML 重排，保留原 BOM）。

## 真机验证

`D:/h3d_relic_test` 是**被旧版本迁移过的半成品**，正好是 D3 的活标本：

| 步骤 | 结果 |
|---|---|
| 迁移前 | `verify` → `PASS 22 / FAIL 1`（13 个产物不在磁盘上） |
| 补齐三个目录 + 重写 6 份账本 | `verify` → `PASS 23 / WARN 0 / FAIL 0` |
| 重写 `config.yaml` | `runner.manifest` 指到 `阶段成果\output\run_manifest.json` |

## 未决

- 用户如果用的是**更早版本迁移过的**项目，需要手动跑一次
  `paths.migrate_legacy(项目根)` 才能修好账本（GUI 不会再自动触发，闸门在那里
  是对的）。没有为这件事加 CLI 子命令——`h3d verify` 会把症状报出来，但不该
  在没有用户确认时改写他的账本。
- 目录清单仍有三处副本（`paths._STAGE_CHILDREN`、`cli.py` 的 validate 清单、
  `runner` 里的字面量）。彻底收敛需要一个「阶段 → 目录」的单一真源，属于下一轮
  的重构，不是这次能顺手做的。
