# ADR-0027：对外口径用指南编号（X3 在报表里写作 X2）

- 状态：已实装（2026-11-06）
- 相关：GLOSSARY §2（代号映射）、ADR-0001（代码冻结）
- 代码：`h3d.report.html_export.public_stage`、`h3d.delivery_verify`、`h3d.cli`
- 触发：用户问「X3 到底是什么，我要的是 X1、X2 两条路径」

## 问题：代号有两套，只在 GLOSSARY 里对得上

代码里 `X2` 这个位置先被**色差评估**占了，于是指南的 `X2`（单期纹理异常检测）
只能顺延叫 `X3`。这条映射一直只写在 `GLOSSARY.md §2`，而**对话、报表、CLI 帮助
全都用代码编号**——用户按指南写论文，看到满屏「X3」自然对不上。

这不是技术问题，是**沟通通道里的名字不一致**。而它已经造成一次真实的困惑：
用户以为我要给他做别的东西。

## 决定：两套代号、指向一处

| 场景 | 写什么 | 理由 |
|---|---|---|
| 报表 / 界面 / 论文 / 对话 | **`X2`**（异常检测） | 用户按指南写作，对外不该要求他翻译 |
| CLI 帮助 | **`X2`**，首次可注「代码内部编号 X3」 | 命令行也是给人看的 |
| 日志 / manifest 键 / 配置项 / 测试名 | **`X3`**（不改） | 与账本一一对应；改了日志与 manifest 就对不上号 |

### D1：只在显示层映射，键名一个不动

`html_export.public_stage()` 是唯一实现：

```python
_STAGE_PUBLIC = {"X3": "X2 异常检测", "X2": "色差评估"}
```

**只映射会撞号的两个**。第一版顺手把 `S1`/`P1`/`X1` 也加了中文名，结果两条既有
测试（断言 `>S1<`）挂了——映射面越大，波及越不可控。M1–M6、S1、P1 本来没有歧义，
不动。

`X2`（色差评估）**必须一起映射**，否则状态表里会出现两个「X2」——那比原来的
困惑更糟。

### D2：核验器跟着改，否则交付关口会假红

`delivery_verify` 原有三项检查是 `stage in txt`（在报表里找裸 `X3`）。报表改用
对外名后，这三项会**永远找不到**——交付核验假红，比不核验更坏。

改成按 `public_stage(stage)` 找，并保留裸 id 作为兼容分支（旧报表仍能过检）。
这是"改产出口径必须同步消费方"的又一次复现（r16 那个坑）。

### D3：改口径时发现两个「判据靠噪声通过」

改完报表口径，核验器「HTML 覆盖 X3」立刻假红——顺手一查，发现两个更老的问题：

1. **在原始 HTML 里搜关键字会被内嵌图片骗过**。报表的图表是
   `data:image/png;base64,…`，随机 base64 串里出现 `X3` 不稀奇——
   batch3 的报表原文里有 **34 处**。所以这项检查**哪怕阶段行真的丢了也会 PASS**。
   已加 `html_text()`：先剥掉 data URI 再搜。

2. **「HTML 里有完成率/分母」这项一直是靠噪声通过的**。它的正则找
   `(\d+)\s*/\s*(\d+)`，而报表里从来没有 `N/M` 这种写法（只有
   「完成 18　失败 0　分母 21」）。剥掉噪声后它终于说出真话：报表没印完成率。
   已补一行 `完成率：18/21（85.7%）`；分母为 0 时印「—」而不是 0.0%。

这两个都是本项目的老病：**判据在垃圾输入上恒真**（方法学 2.3 那一类）。
它们能活这么久，正因为"绿着"——没人会去查一个通过的检查。

## 波及清单（都已核对）

| 位置 | 改动 |
|---|---|
| `report/html_export.py` | 新增 `public_stage()`；状态表两处构造 + 第三节脚注用它 |
| `delivery_verify.py` | 三项「HTML 覆盖 Xn」改按对外名找（兼容裸 id） |
| `cli.py` | `anomaly` 子命令帮助 + docstring |
| `GLOSSARY.md` | 新增 §2.1「对外口径」，含三行映射表 |
| `tests/test_report/test_stage_order.py` | 断言改用 `public_stage()`（原意图是"每个阶段都有行"，不是认字面） |
| `tests/test_report/test_public_stage_labels.py` | **新增 4 条**：报表不得出现裸 `X3`、`STAGE_ORDER` 仍含 `X3`、配置项仍叫 `x3_enabled`、GLOSSARY 有映射表 |

## 没做的事

- **没有改 stage id**。`STAGE_ORDER` 里的 `"X3"`、manifest 键、`runner.x3_enabled`
  全不动——那是账本，动了历史项目就崩。
- **没有把日志改成 X2**。日志标注的是 stage id，改了就没法跟 manifest 对照；
  折中是「两套代号 + 一张表」，而不是「处处都写两个名字」。
- **没有动 `accuracy.csv` 的列名**（「异常面积（岛内）」本来就不含编号）。
