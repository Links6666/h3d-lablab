## B2 切片 13：色度分域（D15）—— 「图案边缘」判据被数据否决
用户要「图案边缘」判据。**先量数据，前提被推翻**，改为色度分域。

- 三条几何量全分不开：真机 7 处最粗宽 **10.8~17.1**（中位 14.1）、密度 0.35~0.71；
  合成方斑块最粗宽 = 边长（12~120）、密度 1.00。**真机比方块还细**，密度方向还
  相反——「不规则 = 不是病害」这条方向是错的（掉彩本来就不规则）。
- 决定性的一列：7 处 Lab 中位 **a/b = 127~130**（中性点 128），环色度 2.9~10.2；

  真机上没有作用对象（不是不准，是样本不存在）。也反过来说明这 7 处不是掉彩

  **看环不看内部**——掉彩露胎本身是胎体色、周围才是彩绘，只看内部会正好判反
  （合成用例钉住）。阈值 15、环宽 8（≈ 真机图斑最粗宽的一半）。
- 真机：paint_ratio **1.89%**、7 处全 bare、彩绘区 0 处报警。三出口一致

- 三个坑：① 用**归零后**的 Lab 算色度 → 中性灰块算出 chroma=190 被判「彩绘」（必须用

## X1 M3C2 用「已知形变」标定 —— 177mm 定案（ADR-0006，提交 99d6c20）

### 方法
`scripts/verify_x1_sensitivity.py`：造解析可算的两期（球面 / 圆柱侧壁，沿法向注入
0/1/2/5/10/20mm，两期同一组采样方向）。判读用**距离场中位数**不是 `max_change_mm`
—— max 由一两个边缘核心点决定，拿它当「尺度对不对」的证据会把噪声当信号。
不引新依赖（numpy + 已有的 `h3d.change.run`），与 X3 的注入法同一套方法。

### 三个结论

1. **旧代码符号是反的**。第一次跑（修定向之前）逐档报 −1.000 / −2.004 / −5.003 /
   −10.002 / −20.010：绝对值精确到 0.05%，**符号全反**。根因是 `_corepoint_normals`
   那句注释「朝向正反只影响距离符号，不影响绝对值」——`detect_changes` 正拿符号判
   **堆积/风化**，结论会反，而只看 `|·|` 的判据完全放得过去。
   修法两步：`orient_normals_consistent_tangent_plane` 求局部一致（单点 PCA 符号随机，
   逐点翻会翻出锯齿）+ **整体**对齐「远离重心」（逐点用重心判据会在凹处翻错）。

2. **尺度一直都是对的**。修定向后三档线性度 **1.000 / 0.998 / 1.001**，同源报 0.000mm。
   若尺度错一半斜率会是 0.5，单位混了 mm/m 会是 1000 —— 都不在。ADR-0005 里
   「第 5 个缺陷＝尺度没调对」这个前提**是错的**。

3. **177mm 的根因是候选链把两种传感器当成同一件的两期**。真机探针：
   | 组合 | 正向中位 | 反向中位 |
   |---|---|---|
   | 激光件 vs `10_dense/fused_dense.ply` | **5541mm** | 5912mm |
   | 激光件 vs 激光件 | 0.000mm | — |
   | 激光件 vs `30_dense` | 25mm | **6895mm** |
   `10_dense` 是照片重建稠密点云，与激光件差 5.5 米（两个坐标系），而它是候选链
   第一顺位、**首个命中即用**。M3C2 对任何两份点云都成功返回，错配输入报的是坐标系
   间距，看起来完全正常还能进报表。

### 改动
- `_geometry_candidates()` 返回有序列表；X1 逐个过 `_epoch_consistency` 闸门
  （对角线比 ∈[0.9,1.1] + **双向**互最近邻中位 ≤ 对角线 2%），取第一个真同源的；
  全不过 → SKIPPED + `epoch_checked` 留每个候选的实测差距。
- **双向取大**：`30_dense` 正向 25mm 但反向 6895mm —— 单向小不代表同源（可能一份
  点云整个落在另一份覆盖范围内）。
- `ChangeConfig.calibrated` 默认改 **True**（尺度链路已验证），注释写清它**不代表
  单件数据可信**——那只由输入决定，由闸门负责。
- `epoch_source` / `epoch_median_mm` / `epoch_bbox_ratio` 进 metrics。

### 测试
1208 项绿（新增 13：9 项已知形变回归 + 4 项同源闸门）。侧壁容差按 **MPS** 表达
（`max(0.75, 0.6×MPS)`）不硬编码 —— 曲率 + `normal_radius=10×MPS` 的固有偏差 ≈0.4×MPS。

### 没做的
- 真实两期数据（唯一还缺的）。
- `30_dense/relic_001.ply` 反向 6895mm 的内容核对（疑似含激光件之外的几何）。
- CloudCompare 交叉验证（本机没装，本次以合成真值替代——比外部软件更硬，给了逐档对应表）。

### 顺带清理

## X2 色差首验 —— 那个 21.42 是单位错（ADR-0008，提交 088954e）

### 输入先查：这件文物没有色卡
30 张照片（DSC_0008…）逐个跑 ArUco + 亮框回退：**定位成功 0 张、含 ArUco 0 张**。
人工看图也确认：只有文物 + 白纸背景。X2 在这件上不可能测出色差。

### 三条缺陷

1. **单位没换算**。`colour.run` 要 sRGB 0~1，`_stage_colour_quality` 喂 0~255，
   `_prep()` 见越界就 clip 到 1.0 → 几乎全部像素钳成纯白。
   **决定性实验**：标准值 ×255 落同一钳位路径 → **21.4193**，与真机 21.42 差 0.0007。
   关校准是 **46.99** —— `use_calibration` 的线性拟合把 46.99 拉成 21.42，
   **校准掩盖了单位错**，让假数看起来更正常。这条最阴。
2. **没有色卡仍出数**（`texture-random`：随机采 24 个纹理像素 vs 色卡标准值）。
   测的是「文物颜色与色卡颜色的差」，两个不相干的量。
3. **定位几何错两处**：格点 vs 格中心（边缘偏 17%≈一格宽）；且
   「ArUco 中心=色卡角」这个假设**本身不成立**（标记对称，中心在角上必压色块）。
   合成理想色卡验证：现行 mean ΔE=27.42、首块灰色 [142,142,142]；
   改「格中心 + dst 到 [0..cols]」后首块对上 [94,75,59]。

### 改法
- 无色卡 → **SKIPPED**，reason 指路「采集时把 ColorChecker24 与文物同框」。
  与 X1 的 `calibrated=False` 不同：X1 那个数算的是真形变只是没标定；
  X2 的 texture-random 是**测错了对象**，给「不可引用的数」不如不给。
- 色块除 255；定位改用 `locate_colorchecker_robust`（鲁棒版写了从没被调用过）。
- 几何**不硬修**（D4）：修参数只是给错误假设打补丁，等真实色卡照片定采集规范。

### 验证
- 1222 项绿（新增 7：单位三态 3 + 无色卡 3；改 1 项打桩到 robust）。
- 真机跑 `_stage_colour_quality`：`skipped`，metrics 为空（没有假数）。

### 未决（阻塞）
色卡采集规范：贴几个 ArUco / 贴哪 / 色卡与文物相对位置 / 要不要灰卡做白平衡。
没这份规范，定位算法无法定标。另：实测端要避开 UV 图集空白区（真机纹理
`img[1024,1024:1029]` 全 `[0,0,0]`，是 UV 填充色不是文物颜色）。

## 查 UV 图集利用率 —— 结论和假设相反（ADR-0009，提交 b295dbb）

### UV 是好的，68%
对真机模型重算：光栅化 2,852,678 纹素、去重后同数，**岛占比 68.01%**。
三个口径必须分开，别再混：
```
atlas_utilization = UV 岛面积 / 图集面积  → 68.01%  （打包质量，好）
coverage_ratio    = 着色纹素 / 图集面积   → 21.22%  （投影覆盖质量）
island_fill_ratio = 两者之比              → 31.13%  （岛内填满程度）
```
「diffuse 非黑只有 0.92%」是第三口径的问题，**不是 UV 浪费**。所以本轮不改
unwrap/xatlas 参数——那是在修一个不存在的病。

### 顺手修：utilization 重复计数
`len(flat)/size²` 用去重前的点。铺满 UV 的正方形算出 **1.0156**、重复面算出
**2.03**（比值 >1 一定是错的）。它是 island_fill_ratio 的分母，虚高会把人
误判成「岛内没填满」→ 去查法线/遮挡。改成 `len(np.unique(flat))`。

### 真正的问题：icp_align 把几何搬出相机视野

## 对齐加投影级验收（ADR-0009 D3，提交 1d0e642）

### 做了什么
- `in_frame_ratio(verts, images, cameras)`：顶点口径「投进至少一台画幅」比例。
  与投影阶段的 `in_frame_fraction` 同一物理量（那里纹素、这里顶点），
  **对齐前后都在顶点域比**，口径一致。相机约定与投影阶段严格同一份
  （`pc = R@(p-t)`，`z<0` 在前方）。
- `alignment_regressed(before, after, min_keep=0.5)`：**相对**判据，掉一半才算变差。
  不用绝对阈值——「不对齐」的基线才 14.5%。拒绝=保持原坐标系=没做对齐，始终安全侧。
  `before<=0` 不拦（拦了等于永久禁止对齐）。
- 接入**两条路**：自动 ICP + 控制点两阶段。拒绝时回退 `verts0`、`accepted=False`、
  `reject_reason` 写两个比例、**不导出自动控制点**（错位对齐固化成控制点会传染后续每次运行）。

### 真机验证（同一份输入）
| | coverage | cameras |
|---|---|---|
| 修之前 | 1.16% | 3 |
| **修之后** | **21.22%** | **20** |

日志：`照片纹理两阶段对齐被判无效，回退原坐标系：投影覆盖 42.9% -> 1.5%`
**实际拦下的是控制点两阶段那条路**（`00_ctrl` 里是占位控制点），不是自动 ICP。

### 测试写法上的两个坑
1. 第一版测试相机用 `R=I` + 圆环布局 → 全部投不进（相机看向世界 -z，看不到原点）。
   必须构造 `look_at_origin` 旋转。
2. 「搬走 3 米」仍然 100% 在画幅内——相机看向原点时视锥很宽。要测「投不进」得用
   **视锥外**（x=50）或**相机背后**（z>0），不能用平移量。
   教训：**测试场景本身要能被验证**，否则红/绿都不可信（这两条一开始是"实现错"的假象）。

### 待办
`align_two_stage` 返回的 metrics 缺 `status` 键（只有 accepted/method），报表按 status
取会对不上。应统一 `applied/rejected/skipped`。

## 对齐结论三态 + 报表认三态（ADR-0009 D4，提交 ccbb76e / 345d76b）

### 问题
四条对齐路径各吐各的 metrics：`geometry_is_sfm`/`already_aligned` 给 `status=skipped`，
控制点两阶段只给 `method/n_control_points/scale_s/rmse_after`，自动 ICP 只给
`accepted/reject_reason`。报表按 `status` 取 → **两条真跑过的路都印空值**。
上一片加的投影验收写在 `accepted/reject_reason` 里，也传不到报表。

### 改法
`apply_align_status(metrics, applied)`：
- `True` → `status="applied"`, `accepted=True`
- `False` → `status="rejected"`, `accepted=False`
- `None`（没尝试）→ 保持 `skipped`，**不写 accepted**（没试过就没有接受/拒绝）

职责：**photo_texture 是唯一决定「应用没应用」的地方**，几何库只报自己的度量。

### 又逮到一个键名对不上
报表 `_align_text` 按布尔键 `rejected`/`accepted` 分支，`status="rejected"` 两者都不
命中 → **一路落到 N/A**。被拒绝的对齐在报表里印空白。已三态优先，且拒绝时直接
露出前后投影覆盖：「无效已回退恒等（投影覆盖 42.9% → 1.0%）」。`align_warn` 同步。

这条是 r16「手写清单/键名不同步」的第 N 次变体：**改了产出的键，忘了改消费方**。
以后改 metrics 键名，必须 grep 一遍 report/ 与 thesis_tables/。

### 验证
1252 项绿（+9）。真机：`status=rejected`、`accepted=False`、42.9%→1.0%、coverage 21.22%。

## M4 覆盖率 21% 的根因：M1 合并了异源几何（ADR-0011，提交 55f4f0a，已推送）

### 用 in_frame_ratio 量四个几何，规律干净
| 几何 | in_frame | 对角 |
|---|---|---|
| 00_raw 原始激光 | **100.00%** | 6.70 |
| 10_clean（M1 后） | 66.75% | 16.32 |
| 30_dense（M3 泊松） | 45.81% | 20.97 |
| 10_dense 照片重建 | 11.71% | 13.71 |

**对角线越大，投进画幅越少**。不是旋转/平移问题，是几何被撑成了别的东西。

### 追到 M1 的双源融合
10_clean 有 16 个簇，前两簇是两个物体：
- 激光件 25856 点 @(2.59,−0.25,−4.79)（与 raw 一致）
- 照片重建 13407 点 @(−0.15,3.55,0.70)（raw 里没有）

M1 的「P3 双源融合」把 `10_dense/fused_dense.ply` 并进了第一站。而 **novel 判据
在异源时语义失效**：两套坐标系差一个对角线 → 每个 dense 点都"远离"激光件 →
Otsu 切出 **27.19%** > 15% 阈值 → 判「有增量信息」。novel 量的是「两物体间距」，
不是「新覆盖率」。

### 决定性对照
干净输入（无 10_dense）重跑 M1→M3：**30_dense 对角 6.78、in_frame 100.00%**。

### 修法：合并前先判同系
用 `already_aligned` 的 **`norm_median` 数值**（不是 `aligned` 布尔，那个容差 1%
会把合法的双源互补判成异源）：
- 互补半球 0.19 → 合并
- 真机异源 0.92 → 不合并
- 平移 20m 5.58 → 不合并
阈值 0.5。判不出来时不拦（拦错 = 丢数据，放行还有 novel 兜底）。

真机验证：`reject=different_epoch`、中位 0.9277、**10_clean 对角 13.8 → 6.34**。

### 顺带修正一个语义错误的旧用例
`test_disjoint_dense_is_merged` 把球平移到 20m 外当作"覆盖新区域"——那是另一个
物体，不是互补。改成真正的互补（上半球 + 下半球，同球心）。

### 待办
真机 30_dense/50_tex 仍是基于旧 10_clean 的，需重跑 M3→M4 才知道 coverage
从 21% 提到多少。旧 10_clean 备份在 `output/_build/bk_10clean`。

倾向 1。因为「岛边界为什么会有 43% 没覆盖」还没查清——现在知道总覆盖率 57%，
但不知道剩下 43% 是因为没拍到、被遮挡、还是法线背对。

## 覆盖率账算清了：真实是 87.64%，56.81% 是被稀释的口径

### 三个指标不是相减关系
| 指标 | 值 | 含义 |
|---|---|---|
| normal_visible_fraction | **0.9005** | 至少一台相机 cos>0.3（不判画幅） |
| in_frame_fraction | 0.8671 | **cos>0.3 且** 落在画幅内（不是纯画幅！） |
| occluded_texels / texels | 13.9% | 被遮挡（降权不剔除） |
| coverage_ratio | 0.5681 | 全图集口径 |
| **island_fill_ratio** | **0.8764** | **岛内填充率 = 真实覆盖率** |

`coverage = atlas_utilization × island_fill` = 0.6483 × 0.8764 = **0.5681** ✓

**所以 56.81% 不是"43% 表面没纹理"，而是"UV 岛只占图集 65%"造成的稀释。**
岛内实际填充 **87.64%**，按项目自己的标准（<85% 才算问题）**已经达标**。

### 我上一轮的判断错在哪
我说"coverage 57% → 要往 80% 推"，是把 `coverage_ratio`（全图集）当成了
表面覆盖率。真判据是 `island_fill_ratio`。

| | 修 M1 前 | 修后 |
|---|---|---|
| coverage_ratio | 21.22% | 56.81% |
| island_fill_ratio（真判据） | **31.13%** | **87.64%** |

岛内填充从 31% → 88%，**覆盖率这条线已经通了**，不需要再"提覆盖率"。

### 我的独立探针为什么和 M4 差很多
- 纯画幅内（不判 cos）：**100%**
- cos>0.3（不判画幅）：**89.99%**
- 两者交集：92.27%
而 M4 的 `in_frame_fraction` = 86.71% —— **它同时要求 cos>0.3 和画幅内**，
名字有歧义（叫 in_frame 却含法线条件）。这条写进 ADR-0011 未决。

### X3 的伪影来自哪（新的方向）
岛内还有 **12.4% 没着色**（黑色空洞）。X3 的 9 处图斑正好落在这些空洞边缘。
`_bleed` 只做外扩，救不了岛**内部**的空洞 → 需要洞填充（邻域颜色插值），
或者让 X3 排除空洞边缘 N 纹素。

### 待办
- `anomaly_island_count` 报 None（岛数没算出来），指标缺失
- `projected_cameras` 只有 11/30（19 台从未成为任何纹素的最佳相机）—— 可能正常
  （环绕布光互相抢），也值得单独看一眼

## 填岛内空洞：做对了，但它不是 X3 伪影的主因

### 做了什么
`_bleed` 加 `limit` 参数（只在给定掩膜内扩散），M4 里用「岛内」掩膜填小洞：
- 岛外空白不填（那不是表面，填了等于伪造纹理）
- 岛内洞填 `hole_fill_px`（默认 4 px），大洞留黑并报数
- 新指标：`hole_texels_before` / `hole_texels_left` / `hole_fill_px`

真机：岛内空洞 **336136 → 216172**（填掉 12 万，占洞的 36%）；
`coverage_ratio` / `island_fill_ratio` **不变**（口径正确，用的是填充前的 pre_mask）。

### 但 X3 数字一模一样
`0.5179% / 9 处 / σ 15.648` —— 填洞前后**完全一致**。说明那 9 处图斑**不在洞里**。

重新裁图（`output/_build/region_crops_v3/`）：看到的是**岛与岛之间的色调跳变**
——相邻多边形块明暗不同、边界分明。不是黑洞，是**岛间颜色不连续**。

### 真正的根因：多视图颜色不一致
`multiview_color_std = 32.67`（0~255 尺度上很高）—— 同一纹素在 top-k 相机下的
颜色离散度大，即**不同照片之间的曝光/白平衡不一致**。融合后相邻 UV 岛用不同照片
组合 → 色调跳变 → X3 当成异常。

**闭环**：X3 伪影 ← 岛间色调跳变 ← 多视图颜色不一致 ← **缺色卡/白平衡校正**。

这正好回到 X2：没有色卡就做不了色彩校正。所以 **S0（AI 病害语义）的最终阻塞
是采集（色卡 + 统一白平衡），不是代码**。

### 填洞该不该留
该留。它消除了「黑洞边界」这一个次要噪声源，且指标可查、语义清晰（只填小洞、
大洞报数）。但它不是解药——不要再指望它改善 X3。

### 教训
「改善 X」之前先确认 X 的病因在不在你能改的地方。填洞的收益我事先说"可能糊住
真实细节"，实际收益是 0（对 X3 指标），代价是引入了一个默认值 4px 的行为变化。
**判断该先花 5 分钟量 X3 图斑的位置分布（是否落在洞里），再决定要不要写这个功能。**

## 色调假设验证 + 曝光均衡（11%），以及一个缓存键缺陷

### 先验假设（3 分钟的探针省了一次白工）
把纹理**岛内强平滑**（抹掉岛内色调台阶、保留岛间差异）后重跑 X3：
```
原始        0.5179% / 9 处 / σ=15.65
岛内平滑后  0.1086% / 4 处 / σ=15.65   ← 降 79%
```
**色调跳变确认是主因**（σ 不变、处数减半，说明不是噪声尺度变化）。

### 逐相机曝光均衡：只降 11%
`balance_photo_exposure`（灰度均值/标准差对齐到全局中位数）：
- `multiview_color_std` 32.67 → **29.06**（降 11%）
- X3 异常 0.5179% → **0.46%**（降 11%），处数仍 9

**所以曝光只占 11%，剩下 68 个百分点是白平衡（通道间比例）**——那要色卡，代码补不了。

功能留着，**默认关**（会改绝对色彩，X2 的 ΔE 需要真实颜色）。

### 顺带逮到一个缓存键缺陷（r16 同构）
第一次对比时 `color_std` **纹丝不动 32.67→32.67** —— 因为 `params_fingerprint`
里没有 `balance_exposure`，改了配置但**图集缓存命中**，复用旧纹理，一声不响。

已修：`params_fingerprint` 加 `balance_exposure` + `hole_fill_px`。

**纪律**：新增任何影响纹理像素的参数，**先加进 `params_fingerprint`，再加配置字段**。
漏一个就是「改了没反应且不报错」——这类缺陷最难查，因为没有任何错误信息。

### 今天的最终结论（三条线收敛到一点）
```
X2 的 ΔE 测不了  ─┐
X3 的岛间跳变    ─┼→ 都卡在「照片之间色彩不统一」
S0 的纹理不可用  ─┘   ← 缺色卡 / 缺统一白平衡
```
代码侧能做的已经做到头了。剩下的必须靠采集。
