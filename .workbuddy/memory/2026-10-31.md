# 2026-10-31　v1.1.13（r17）：配准链路两处硬缺陷 + 首次 M2 端到端验证

## 起因
用户按 r16 建议「对 00_raw 的 PLY 施加已知刚体变换再跑」，结果 M2 仍是
`registered=否 / identity=single_scan / 16 ms`。**只有一份文件 = 单站直通**，
施加变换不会让文件数变 2。同时 M4 覆盖率从 59.8% 掉到 35.9%。

## 查出的两处硬缺陷

### D1　M4 的相似变换把网格搬错了（coverage 35.92% / fill 57.49%）
- `align_points_to_mesh` 用**原始包围盒**做尺度初始化。COLMAP 稀疏点云带飞点：
  13990 点里几个远点把包围盒从 6.19 撑到 **47.83（7.82 倍）** → s0=0.12 →
  6 轮 ICP 收敛到 0.2467 → **对齐后包围盒仍是网格的 2.0266 倍**。
- 自报 `rmse_after=0.0968` 是假象：算的是**变换前**的距离（循环里 `d` 未更新，
  off-by-one）+ 只统计 p90×2 内对应 + 表面只采 3000 点。
- 后果：网格被放大 4 倍，纹素大面积投到画幅外。实测「夹角可见 92.25%」→
  「真投进画幅 44.61%」，差 47.6 个百分点。
- **三路对照（同几何同照片）**：跳过对齐 98.87% / 控制点两阶段 93.15% /
  自动 ICP 57.49%。结论反直觉——**这次"不做对齐"才是最优**（几何本就与
  sparse 同源，中位距离 0.64% 对角线）。
- 另一条链：旧实现会从**错误对齐**里自动导出 8 个控制点写进 00_ctrl，
  第二次运行靠这批"错出来的"控制点把结果救回 93%——靠错误自愈，必须堵死。

### D2　M2 大角度解出「翻转 180°」（30° 注入 → 恢复 166.58°）
- 近似轴对称造像在 RANSAC 里把点撞到**对侧表面**，fitness 0.336 越过
  `_MIN_FITNESS=0.2` 的失败门，一路判成功；配准后中位距离 1.9% 也"看着贴合"。
- 修：ICP **多初值**（RANSAC 解 + 绕两主轴各 180° 翻转解）取 fitness 最高；
  修复后 7/30/90/120/180° 全部恢复到 ≤0.02°、fitness 1.000、中位距离 0.21%。
- 同时加 `low_confidence`（fitness<0.55）**不判失败但必须留痕**。

## 教训（新增到长期记忆候选）
1. **相似变换必须有外部可核对的判据**：bbox 比、单向中位距离。
   自报 rmse 会骗人（off-by-one + 截断 + 稀疏表面采样三件事同时发生）。
2. **不要用 min/max 包围盒做尺度基准**：COLMAP 点云必带飞点，99% 分位才稳。
3. **「合格」的对齐也可能不如「不做」**：先问要不要对齐，再问怎么对齐。
4. **靠错误自愈的路径必须堵死**（错误对齐 → 导出控制点 → 下次"正常"）。
5. **施加刚体变换 ≠ 造两站**：单站语义看文件数，不看内容。
6. ICP 单一初值在轴对称物体上会解出翻转解，fitness 0.33 也能过 0.2 的门。

## B1 图集继承（跨项目烘到基准图集）
用户三问定调：**独立项目 + 跨项目引用** / **内核+CLI+GUI** / **合成自检（逐 texel）**。

调研先推翻了一个假设：`project_photos_to_texture(mesh, uv, faces, images, cameras, photo_dir)`
本来就吃外部 uv/faces → **B1 不需要重新展开 UV**，核心只在「复测相机搬进基准坐标系」
+「图集版本冻结」。真正的起点更靠前：**M4 从不落盘 UV 布局**，所以继承无从谈起。

**六片**（`docs/adr/0002`）
1. `archive/atlas.py`：`AtlasRecord` / `AtlasRegistry`（同版本同指纹幂等、不同指纹抛
   `AtlasFrozen`）/ `uv_digest`。版本号数值排序（v10 > v9）。
2. UV 布局落盘 `save_uv_layout`（npz：uv/faces/**verts/normals**）+ M4 无条件落盘。
3. `Similarity` / `transform_cameras`：`C'=sRC+t`、`R'=R·Rᵀ/s`。
4. `inherit_texture`：基准 mesh/uv/faces + 复测相机/照片 → 同一采样器。
5. `inherit_epoch`：跨项目编排、限定名 `relic_001@atlas-v1`、五条失败分流。
6. CLI `h3d archive inherit --base --from [--matrix]` + GUI「继承基准图集…」（QThread）。

**三个踩出来的坑**
- **uv/faces 属「展开后」拓扑**（xatlas 接缝拆点，顶点数 ≥ 原始 PLY）。只存 uv/faces
  时，继承端拿原始网格承接 → `index 880 out of bounds for size 762`。修法 = npz 里连
  展开后 verts/normals 一起存；旧布局回退 PLY 时必须校验面索引范围（越界要失败，
  因为换一个模型可能不越界 → 错得更隐蔽）。为此在 io 层加了 `make_mesh()`。
- **`R'` 含 1/s，不是正交矩阵**：投影只看 x/z、y/z 比值与符号，整体缩放不影响像素。
  去掉 1/s 等于视野缩放 1/s 倍。s=1 时退化为正交（有测试守）。
- **覆盖率不能当位姿判据**：球体各向同性，反向变换只把 in_frame 从 0.799 打到 0.717，
  而纹素中位差从个位数跳到 30+。判据必须是纹素差。
- 测试素材也踩了：纯**噪声照片**在 2 px 错位下就跳几百灰度，轻微抖动与完全弄反在
  数值上无法区分 → 改**渐变+棋盘**（空间连续），阈值才有推导依据（正向 <6、反向 >30）。

**GUI 交互缺陷**（全量测试才暴露，单文件跑是绿的）：`_on_inherit_done` 先写结论再
`emit(archive_changed)`，而刷新会 `apply()` 把说明行改回「档案已存在」→ 结论被覆盖。
修法：先 emit 刷新、再落结论。

**真机**（`E:/兵马俑照片`）：`--base 1.1.12 --from 1.1.11` → rc=1，消息「基准项目没有
atlas-v1 的图集记录（基准期可能跑的是不落 UV 布局的旧版本）」。这是**诚实结果**：
两个存量项目都是迁移建的档，确实没有图集记录。要跑通真机继承，第一步是让基准项目
重跑一次 M4（90 s），本批没做。

**未验**：真实第二期数据、真实尺寸（2048²/8 万面）耗时、`atlas_stale` 自动标记。
测试：1068 项（新增 61）。`--junitxml` 是沙箱下拿到失败清单的唯一稳手段（summary 行
会被 safe-delete 提示盖掉）。

## B1 切片 7：打通真机图集继承（16:00-16:40）

## B2：X3 单期纹理异常检测（`h3d anomaly`）

- **返工三轮才找对背景估计器**（都写进 ADR-0003 了）：
  ① 块级 16×16 均值 + 中位数/MAD → 真机 24 texel 覆盖率 1.00 但 IoU 0.14（掩膜只能落
     块格、外溢 7 倍），80 texel 反而漏检；上采样基线逐块常值 → 块边全是假残差。
  ② 裁剪均值 → 窗内 36% 污染时均值被拉偏 0.36ΔE，多数派残差与离群者只差 1.8 倍，
     3σ 筛不掉，等于没裁。
  ③ **局部中位数**（`cv2.medianBlur`，8 位量化 O(1)/纹素，2048² 核 201 实测 99 ms）→
     残差分布变成「斑块内≈ΔE、其余≈0」，边界回到纹素精度。
- 中途踩坑：**逐像素二分求局部中位数是错的**——每个像素各带阈值而窗口计数须同一阈值，
  计数恒为 0.538 不动，二分滑到边界、背景判成 ∓amp、全图 z 归零（`medianBlur` 核长
  上限 255，OpenCV 5.0 大核路径断言 `k<16`，传 401 直接抛）。
- 尺度用**块内 75 分位 / 1.1503**（中位数在双峰残差上落到 0 → 条纹图 6.3% 误报）；
  **脏块（>2× 邻域）用邻域值替换**而不是封顶（封顶只压到 2 倍，粗糙区 ΔE=120 只得 z=2）。
- 纹理通道：弃 LBP（popcount 丢方向，条纹/噪点分布重叠）→ 结构张量一致性+方向；
  三闸门（当前有结构 / 基线有健康证据 / 基线本身一致）；**基线要排除可疑区**，否则
  斑块两侧都判「方向变了」外糊 100 texel；纹理证据只在颜色没响应的位置补位。
- **注入方法本身会骗人**：`255-pixel` 在中间调上 ΔE 只有 14 → 变成「造一个几乎不可见的
  异常再怪检测器漏检」。改「L 推离中间调 80 + a/b 取反」并打印实际 ΔE。

## B2 诊断：80 texel 大斑块为什么漏（病因更正）
按 `diagnosing-bugs` 走：先造回路（`output/_build/diag_x3_bigpatch.py`，一条命令、
确定性、15 s），再定假设，最后改。**结论推翻了上一轮 ADR 里写的病因。**

- 回路读数（同一图集三处、同尺寸 80 texel、ΔE≈120，W=201 尺度）：
  (381,174) 残差 97 / σ_L 30.3 / z 3.21 → 漏；(1589,511) 残差 97~106 / σ_L 53.2~84.8 /
  z 1.82~1.25 → 漏；(1546,1720) 残差 100~113 / σ_L 15.7 / z 6.37 → 中。
- **斑块残差三处几乎相同（97~113），漏的原因全在分母**：σ_L 差 5 倍。上一轮 ADR
  猜的「脏块替换后邻域被抬过一轮」被否——窗口内跨 20~31 个 UV 岛，残差沿斑块内部
  仍均匀，跨岛没吃掉信号。
- 所以这是**低信噪比**，不是估计器缺陷。想靠「按面积累加证据」硬拉灵敏度，会在
  材质交界处炸出大片假阳性——σ 大到 53 的根源正是那些交界。**不动统计量。**
- 改为把可检下限变成数字：`sigma_median`（最粗尺度、岛内 σ_L 中位数，只取 L 通道
  ——取「最后一个通道」会永远等于地板 2.0，被测试抓到）→ `anomaly_sigma_median`
  → 三个出口。真机 1.1.12 = **14.5**（Lab），漏掉的两处是全件中位数的 2~3.6 倍，
  数字能直接对上结论。HTML 里与异常面积同格显示（`2.18% / σ_L≈14.5`），不加列。
- 模板里一度把 `σ_L≈14.5` 写死进脚注（等于给所有项目印同一个数），已改成
  「异常面积格内的 σ_L≈N 是本件…」。
- 全量 1120 项绿。

## B2 切片 6：图斑明细进 HTML（+ 一条方法论发现）

## B2 切片 7：按岛归一化（D11）
真机图集是 **3690 个 UV 岛**拼的马赛克，中位 69 texel、到岛边界距离中位 5 texel、
**最大 75.3** → 31 窗口能整窗落在同一岛内的纹素 10.3%、81 窗口 1.0%、**201 窗口 0.0%**。
「局部空间背景」不是不够好，是处处不成立。这是 D10 里「亮岛被暗岛包围」的根因。

- 做法：逐岛中位归零（**先归零再填充**，反过来岛边界会重新长台阶，原型误报 10.7%）
  + σ 取本岛自身离散度 `q75(|L−岛中位|)/1.1503`。
- 结果：真机 **2.181%/35 处 → 0.242%/7 处**、σ_L 14.52→12.17、**3.5 s→2.9 s**（更快）。
  注入灵敏度 9/11 不变（24/40 texel 增量 IoU ≥0.87）。
- σ 试了四版（同一图集同一批注入）：块分位数+池化 3.34%/71 处、命中 10/11；
  块分位数无池化 0.16% 但命中 8/11；**本岛原始离散度 0.242%/7 处、9/11（采用）**；
  本岛残差 q75 5.94%/93 处（岛内 25% 粗糙区把 q75 拉平 → 粗糙区整片误报）。
- 「块 σ > N×本岛尺度 → 替换」这条路**分不开**：真机块比值 p99=6.07，而 40 texel
  斑块填满块时只有 4.7（W=81 σ=89）。cap 2/4/6 → 1.88/1.22/0.80%，关掉时 60/120
  texel 注入 IoU 掉到 0.09/0.33，没有同时成立的取值 → 弃用脏块判据。
- 已知边界：岛内病变过半时中位数被病变带走（50% 击穿点估计器的固有限制）。真机中位岛
  69 texel，占半个小岛的斑块看不见。报表脚注已写。
- 两个 bug 被测试抓到：`score_max` 统计了岛外纹素；逐岛尺度取错通道（恒等于地板 2.0）。
- 测试：合成 16 项（+4：25 岛拼贴 21.16%→0.000%/0 处、岛内注入仍命中、开关真生效、
  σ_L 三档随纹理强度）；接线 +2（island_count 进白名单与报表）。全量 1127 项绿。

## B2 切片 8：k 重标定的评估（不改默认值，D12）
提出的方案是「默认 k 3.5 → 4.5，把待复核压到个位数」。**实测否掉了它**：
- k 扫描（`scripts/verify_x3_islands.py --k-sweep`，一条命令）：
  3.5 → 0.242%/7 处，24:4/4 40:3/4 80:2/3；4.5 → 0.125%/4 处，24:3/4 **80:1/3**；
  6.0 → 0.099%/3 处但 24:1/4。
- **被过滤的与要求检出的强度重叠**：80 texel 注入在 3.5 下覆盖 0.92，到 4.5 直接 0。
  提 k 不是「去掉噪声」，是把「待复核」换成「看不见」。
- 三条旁证说明 7 处不是细微起伏：|L−岛中位| 均值 55~101（ΔE=120 注入是 109~128）；
  「区内均匀度」也分不开（注入块 std 3.6~52.8 vs 图斑 6.9~27.0）；按面积连续分布。
- 决定：**默认 k 保持 3.5**；把实际 k 印进报表格内（`σ_L≈12.2 · k=3.5`）+ 脚注写
  「调高不会更准只会更钝」并给出 0.92→0 的证据；`--k-sweep` 进校验脚本。
- 教训：**先量再改参数**。这个方案在纸面上很合理（阈值高一点更干净），一量就塌。
  要真降误报得换判据（按岛自适应 k），且需要第二件文物交叉验证才不算过拟合。
