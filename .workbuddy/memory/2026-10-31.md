# 2026-10-31　v1.1.13（r17）：配准链路两处硬缺陷 + 首次 M2 端到端验证

## 起因
用户按 r16 建议「对 00_raw 的 PLY 施加已知刚体变换再跑」，结果 M2 仍是
`registered=否 / identity=single_scan / 16 ms`。**只有一份文件 = 单站直通**，
施加变换不会让文件数变 2。同时 M4 覆盖率从 59.8% 掉到 35.9%。

## 查出的两处硬缺陷

### D1　M4 的相似变换把网格搬错了（coverage 35.92% / fill 57.49%）
- `align_points_to_mesh` 用**原始包围盒**做尺度初始化。COLMAP 稀疏点云带飞点：
  13990 点里几个远点把包围盒从 6.19 撑到 **47.83（7.82 倍）** → s0=0.12 →
  6 轮 ICP 收敛到 0.2467 → **对齐后包围盒仍是网格的 2.0266 倍**。
- 自报 `rmse_after=0.0968` 是假象：算的是**变换前**的距离（循环里 `d` 未更新，
  off-by-one）+ 只统计 p90×2 内对应 + 表面只采 3000 点。
- 后果：网格被放大 4 倍，纹素大面积投到画幅外。实测「夹角可见 92.25%」→
  「真投进画幅 44.61%」，差 47.6 个百分点。
- **三路对照（同几何同照片）**：跳过对齐 98.87% / 控制点两阶段 93.15% /
  自动 ICP 57.49%。结论反直觉——**这次"不做对齐"才是最优**（几何本就与
  sparse 同源，中位距离 0.64% 对角线）。
- 另一条链：旧实现会从**错误对齐**里自动导出 8 个控制点写进 00_ctrl，
  第二次运行靠这批"错出来的"控制点把结果救回 93%——靠错误自愈，必须堵死。

### D2　M2 大角度解出「翻转 180°」（30° 注入 → 恢复 166.58°）
- 近似轴对称造像在 RANSAC 里把点撞到**对侧表面**，fitness 0.336 越过
  `_MIN_FITNESS=0.2` 的失败门，一路判成功；配准后中位距离 1.9% 也"看着贴合"。
- 修：ICP **多初值**（RANSAC 解 + 绕两主轴各 180° 翻转解）取 fitness 最高；
  修复后 7/30/90/120/180° 全部恢复到 ≤0.02°、fitness 1.000、中位距离 0.21%。
- 同时加 `low_confidence`（fitness<0.55）**不判失败但必须留痕**。

## 改了什么
- `geo_align`：`_robust_diag`(99% 分位) / `alignment_quality` / `already_aligned` /
  `align_points_to_mesh(quality_gate=True)` 拒绝时返回恒等 + `rejected` + 原因；
  `rmse_after` 用变换后点重算。
- `photo_texture`：同源预检 `skip_align`；对齐被拒则不动 mesh、**不导出控制点**；
  新增 `in_frame_fraction`（与 `normal_visible_fraction` 分开，谁低查谁）；
  `back_facing_texels` / `occluded_texels` 去重口径。
- `register`：`_icp_multi_init` / `_principal_axes` / `_rotation_about`；
  `low_confidence` + `icp_init` + `icp_trials`。
- `runner`：M2 落配准矩阵 `transformation_sNN` + `low_confidence`；
  M1 新增 `laser_unverified`（dense=false 时 novel 恒 None，旧逻辑静默失效）。
- `html_export`：M4 表加「画幅内可见 / 几何-位姿对齐」两列；`_align_text`；

## 教训（新增到长期记忆候选）
1. **相似变换必须有外部可核对的判据**：bbox 比、单向中位距离。
   自报 rmse 会骗人（off-by-one + 截断 + 稀疏表面采样三件事同时发生）。
2. **不要用 min/max 包围盒做尺度基准**：COLMAP 点云必带飞点，99% 分位才稳。
3. **「合格」的对齐也可能不如「不做」**：先问要不要对齐，再问怎么对齐。
4. **靠错误自愈的路径必须堵死**（错误对齐 → 导出控制点 → 下次"正常"）。
5. **施加刚体变换 ≠ 造两站**：单站语义看文件数，不看内容。
6. ICP 单一初值在轴对称物体上会解出翻转解，fitness 0.33 也能过 0.2 的门。

## B0 切片 5：内容指纹接入续跑（下午续）

**改掉一个真缺陷**：续跑判据原是「manifest 说 done + 产物还在」，**不看输入**。所以换照片、改参数
只要旧产物还在就被静默跳过；逃生口 force_rerun 是布尔整批生效（为一件重算，其余九件陪跑 M4 80s）。

`h3d/runner/fingerprint.py`：每阶段算输入内容键写进 manifest 的 `input_key`，续跑比对。
- 配置**用减法**（剔除 project/runner 两个执行控制段，其余全参与）；白名单式会在新增段时漏算
  —— 与 r16 手写 manifest_metrics 白名单同构。
- 上游键逐级累积（M4 的键含 M1→M3），任何一级上游变化自动传导。
- 旧记录无 input_key → 旧规则跳过 + 日志说明。**不能改成「无指纹就重跑」**（30 件要 40 分钟）。

真机（1.1.12）：升级后首跑 3.7s 全跳过；清主链记录重跑 90s 后新记录全带 key、档案登记 v2；
再跑 3.3s 全「输入未变化」；改 poisson_depth → M1/M3/M4 键全变；改 workers/project.name → 键不变。

坑：

  不生效 —— 之前没有任何提示，用户会以为续跑在工作。已补 WARNING，未修行为（要处理竞态）。
- disabled/skipped 的旧记录会走 resume 判定并打「↻ 重跑」，真机 P1/X1/X2 连打三行像出了事；
  改为只有 done/fail/running 才打 ↻，其余 debug。
