## 论文骨架：章节 ↔ 证据映射（`docs/论文骨架-章节与证据映射.md`）

### 为什么做这个
代码侧清空了、三个采集阻塞没解，唯一还能提高质量的是**论文**。但直接把 23 篇
ADR 甩给人"你自己组织"没有价值——真正的问题是：**论文里每句带数字的话，能指回
哪里？** 所以做的是一张映射表，不是一份写作指南。

### 结构
§0 一句话论点 → §1 章/节骨架（每节"要证明什么"+"证据落点"）→ **§2 可引用数字
台账（含前提列）** → §2.2 不可引用清单 → §3 三处空白与降级写法 → §4 答辩预案 →
§5 图表清单（含生成命令）→ §6 章节↔代码↔ADR 对照。

### 关键判断（写论文前必须知道的三件事）
1. **同一件文物有三套数字**：`relic_001` 跑 S1 + 位姿修正后是 `coverage_ratio
   0.5865 / color_std 14.42`（30/30 台）；复用既有 capture_meta 只有 11/30 台，
   得到 `0.5114 / 40.44`。**两套都是真的，前提不同**，混用就是学术不端。
   §2.0 专门写了"这批数对应哪一次运行"。
2. **原项目的账本不能引用**：`D:/h3d_relic_test/90_meta/run_manifest.json` 只有
   7 条记录、M4 `coverage_ratio` 0.0028、M5 `rmse` 6940 mm —— 那是探针留下的
   中间态（memory 里记过这件事，这次在真账本上又验证了一遍）。
3. **一件真机数据都没进毫米门**：全部"不判门（单位存疑）"或"无量纲"；M2 全部
   `single_scan`。所以论文的重心只能是**判据体系**，不能是"精度多高"。

### 写作顺序建议（写进 §1）
5.5 可复现 → 5.4 交付核验 → 6.1 失效模式 → 4.3 贴图 → 5.3 纹理 → 其余。
证据最硬的两节先写实，讨论章自然立得住。

## r28：配准 17 次里 3 次解出 179° 翻转解 —— RANSAC 一直没定种子（ADR-0024）

### 怎么发现的
想给论文 §5.2 重跑 7/30/90/120/180° 那张表留底，120° 直接 FAIL：**旋转 179.19°、
中位间距 0.75%**（间距判据放行了）。几何贴合得很好，方向反了。

### 先排除自己，差点误判成回归
用 `git worktree add $TEMP/h3d_pre_r24 317251d^` 检出 r23 跑同一用例：**4 次全对**；
当前 3 次里 2 错 → 看着像我 r24–r27 干的。把样本加到 10 次：9 对 1 错；回头看
r23 那 4 次里也有一次 `icp_init=ransac`。**两边都是随机的，r23 只是运气好。**

合并统计 **17 次里 3 次错（≈18%）**。
→ **教训：判断"是不是回归"时 3 次样本不够，尤其当失败率落在 10–20% 那一档。**
（worktree 已 `git worktree remove`。）

### 根因
`register.run` 从没定过种子。RANSAC 用 Open3D 进程级随机源采样对应点对；**翻转候选
是从 RANSAC 解派生的**（`_rotation_about(...) @ init`）——初值一歪，三个候选一起歪，
择优时就是「0.52 的翻转解」对上「更差的其它解」。

### 修法
- 新增 `h3d/io/rng.py::seed_rng`（唯一碰 `utility.random.seed` 的地方）；
  `sample_surface` 改为委托它。「定种子」与「采样」是两个入口、各管一件事
  —— r24 删掉的 `seed_sampling` 就是因为名字承诺两件事、只做了一件。
- `register.run` 在 RANSAC 前 `seed_rng(_RANSAC_SEED=20261105)`。
- 守卫白名单按**动作**拆：`sample_points_uniformly` → `io/mesh_io.py`；
  `utility.random.seed` → `io/rng.py`。

### 可复现到什么程度（措辞要小心）
- 同进程两次：`max|ΔT| = 2.5e-32`（浮点末位）、`icp_init`/`fitness` 相同；
- 120° ×5：5 次全对，但**其中 1 次选中 ransac 而另 4 次 flip180_axis2**
  → **初值选择仍有进程间差异**（RANSAC 内部并行归约不受种子完全约束）。
- 所以只能写"错解未再复现（5 次）"，不能写"完全消灭"。测试判据用 `atol=1e-12`
  而不是逐位相等，理由就写在测试里。

### 定种子后五档终表（论文可直接用）
7°→0.03° / 30°→0.03° / 90°→0.00° / 120°→0.04° / 180°→0.00°，
fitness 0.9999–1.0000，中位间距均 0.19% 对角线。
（真机 `test111.ply`，噪声 0.2% 对角线，30k 点，`--max-rot 2`）

### 没做：待用户决策
`fitness<0.55` 仍只落 `low_confidence` 不判失败 → 万一还解出翻转解，照样进下游。
升级成 FAIL 会误杀"两站只重叠 40%"的合法难例；加朝向判据更好但那是新研究点。
**已在 ADR-0024 D3 列成 A/B/C 三方案，交给人定。**
