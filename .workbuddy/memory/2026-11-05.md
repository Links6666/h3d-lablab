## 论文骨架：章节 ↔ 证据映射（`docs/论文骨架-章节与证据映射.md`）

### 为什么做这个
代码侧清空了、三个采集阻塞没解，唯一还能提高质量的是**论文**。但直接把 23 篇
ADR 甩给人"你自己组织"没有价值——真正的问题是：**论文里每句带数字的话，能指回
哪里？** 所以做的是一张映射表，不是一份写作指南。

### 结构
§0 一句话论点 → §1 章/节骨架（每节"要证明什么"+"证据落点"）→ **§2 可引用数字
台账（含前提列）** → §2.2 不可引用清单 → §3 三处空白与降级写法 → §4 答辩预案 →
§5 图表清单（含生成命令）→ §6 章节↔代码↔ADR 对照。

### 关键判断（写论文前必须知道的三件事）
1. **同一件文物有三套数字**：`relic_001` 跑 S1 + 位姿修正后是 `coverage_ratio
   0.5865 / color_std 14.42`（30/30 台）；复用既有 capture_meta 只有 11/30 台，
   得到 `0.5114 / 40.44`。**两套都是真的，前提不同**，混用就是学术不端。
   §2.0 专门写了"这批数对应哪一次运行"。
2. **原项目的账本不能引用**：`D:/h3d_relic_test/90_meta/run_manifest.json` 只有
   7 条记录、M4 `coverage_ratio` 0.0028、M5 `rmse` 6940 mm —— 那是探针留下的
   中间态（memory 里记过这件事，这次在真账本上又验证了一遍）。
3. **一件真机数据都没进毫米门**：全部"不判门（单位存疑）"或"无量纲"；M2 全部
   `single_scan`。所以论文的重心只能是**判据体系**，不能是"精度多高"。

5.5 可复现 → 5.4 交付核验 → 6.1 失效模式 → 4.3 贴图 → 5.3 纹理 → 其余。
