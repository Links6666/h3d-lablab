## r7.x 报告缺陷 + "3D 预览无颜色"根因修复（真实 30 张数据）

### 三处代码级根因（实测定位）
1. **投影主循环视线方向反号**：`view = p_c - cam_centers[k]`（= X-C），而法线自检
   用的是 `C-X`。两处不一致 → `cos>0.3` 判据变成"只在背面成立" → 采样落到器物背后
   的**背景**上。实机表现正是"有几何、无颜色且不报错"。改为 `cam_centers[k] - p_c`。
   单测 `test_upscaled_photo_yields_same_texture` 直接暴露（projected_cameras=0）。
2. **z-buffer 深度符号错**：`np.minimum.at(buf, key, z)` 里 z<0 为前方，越远越负，
   "最小值=最近"不成立 → 遮挡判据几乎恒为假（等价于遮挡关闭）。改为传入 `-z`
   （正值深度），`vis = -z <= buf[key] + tolv`。
3. **全局 ±1 法线翻转救不了碎块网格**：网格碎成 25 块时局部符号互不一致
   （实测正向 61.6% / 取反 79.9%，都不到 100%）。改为
   ①全局选"能看到更多纹素"的符号（而不是"<25% 才翻"）；
   ②残余纹素按 `-n` 再问一次，**但要求深度可见**（防穿透取到对侧颜色）。
   岛内填充率 55% → **94.5%**，覆盖率 33.7% → 58.0%，亮度 115 → 129。

### 几何：真正的"预览很糟糕"
- 主簇分析推翻"背景是一整块衬板"的假设：DBSCAN 最大簇 71.3%（42990/60258 点，
  extent 4.86×2.73×2.62、平面度 λ3/λ1=0.088）= **器物本身**；背景是被重建切碎的
  零散小片，把包围盒从 4.86 撑到 14.64 → 预览里器物缩成角落一个小点。
- 新增 `h3d/preprocess/background.py: remove_background()`：DBSCAN 主簇保留
  （`bg_keep_cluster_frac=0.25`）+ 可选平面剔除（默认 0 个，实测会误伤器物平面）
  + 双重安全网（平面跨度须≥50% 对角线；剩余 <20% 整体回滚）。
  M1 内只在**无激光锚点**（场景②）时调用，metrics 落 `background` 嵌套字典。
- 效果：60258 → 42990 点，重建出一件完整器物、取景正常（六视角渲染确认）。
