## 项目方向决策：管线覆盖范围从「造像类」扩展到「中小型文物」

用户明确提出：计划将管线覆盖的文物类型从造像类（大件）扩大到中小型文物。

### 数据契约梳理（实机测试输入）

项目根目录 / 文物编号（一个子目录 = 一件文物）：

| 目录 | 内容 | 必需性 |
|---|---|---|
| `00_raw/<编号>/` | 几何源：激光点云 / dense 点云，格式 ply/pcd/obj | 必需 |
| `00_photo/<编号>/*.jpg` | 照片（S1 位姿解算 + P1/M4 纹理） | 必需（至少 2 张，实测建议 30~80） |
| `00_ctrl/` | 控制点（两阶段对齐，可选） | 可选 |
| `00_ref/<编号>/*.ply` | 参考数据（X1 形变对比基准） | 可选（X1 用） |
| `90_meta/<编号>_capture_meta.json` | 相机位姿元数据（可替代 S1） | 可选 |

capture_meta.json 契约：
`{n_cameras, n_images, cameras: {"1": {fx,fy,cx,cy,...}}, images: [{name, R, t, cam_id}]}`
**t 必须是相机中心**（前方 -Z），COLMAP 的 tvec 需转换 `C = -R_co^T @ tvec`。

### 扩大到中小型文物的已知适配风险（待验证/待改）

1. **尺度参数全部是硬编码绝对值**（`preprocess.voxel_down_sample=0.005`、
   `register.fpfh_radius=0.02`、`icp_distance=0.02`，单位米）——对 5~30 cm 的小件
   体素过粗、FPFH 半径过大，会丢细节/配准失败。**需要按包围盒尺度自适应**。
2. `sfm_solve` 使用 `--ImageReader.single_camera 1` —— 假设全部照片同一相机同一
   焦距。多机位/变焦拍摄下会标定失败，需按 EXIF 分组或改 0。
3. 中小型文物需完整环绕 + 存在自遮挡（把手/镂空/凹槽）→ 照片覆盖空洞、
   Z-buffer 剔除后纹理出现空白。
4. 材质反射：青铜（高反）、陶瓷（高光）、玉器（半透）→ SIFT 在镜面区失效。
5. `mesh.poisson_depth=8` 对纹饰密集器物可能不足，需试 9~10。
6. 真实文物纹饰尺度远小于造像衣纹，`max_features`（默认 8192）与纹理图集
   尺寸需上调。

## 下午：尺度自适应已实现（本批交付）

### 设计（已落地）

- 新模块 `src/h3d/core/scale.py`（纯数学，不碰 IO，保持 core 底座自洽）：
  `bbox_diagonal` / `resolve_factor` / `scaled_config` / `describe`。
- 新配置段 `ScaleConfig`（`config.py` + `PipelineConfig.scale`）：
  `enabled` / `reference_diag` / `min_factor` / `max_factor` / `warn_diag_gt`。
- 公式：`factor = clip(bbox_diag / reference_diag, min, max)`，距离类参数线性缩放。
- **接入点**：`runner/batch_processor.py` 的 `resolve_task_config()`，在
  `_run_task`（单任务）与 `_run_task_worker`（并行）两条调度路径的任务开头
  解算一次，**零侵入 M1/M2/M3 业务层**。
- 尺度信息写入 `Task.scale_*` 字段并注入 M1 的 metrics（`scale_factor` /
  `scale_diag_m`），报表可追溯。

### 关键决策：默认基准 = 3.7 m

`reference_diag` 的语义是「现有默认参数是在多大的物体上调出来的」。
示例造像外接盒 2.0×2.6×1.7 m → 对角线 **3.7066 m**，实测确认。取 3.7 使
示例与历史项目 factor≈1.0（实测 1.0018），**保证零回归**。

### 参与 / 不参与缩放的字段（设计边界）

- **缩放**（有长度量纲）：`preprocess.voxel_down_sample`、`register.fpfh_radius`、
  `register.ransac_distance`、`register.icp_distance`、`mesh.alpha`、
  `mesh.ball_radii`（列表逐元素）、`change.core_radius`。
- **不缩放**（无量纲）：k 近邻数、迭代次数、泊松深度、比率与倍数。
  理由：体素随尺度缩放后点密度相对物体恒定，这些量自洽。

### 连带修复：GUI 配置模板污染（既有缺陷）

`gui/config_edit.py` 的 `to_yaml` 原用 `dict(SCENE1_CONFIG)` **浅拷贝**模块级
模板，随后对嵌套字典赋值（`cfg["scale"]["enabled"] = ...`）会**就地改写全局
模板** → 同进程内第二次生成的配置继承上次用户选择。已改 `copy.deepcopy`

## 晚上：追加「点间距下限」第二层保护 + 一条重要教训

### 为什么加第二层保护

尺度缩放是**乘法**的，隐含假设「点间距随物体尺寸同比变化」。真实扫描通常满足，
但**网格均匀采样**、**多精度设备混用**、**照片稠密重建**得到的固定密度点云不满足：
小尺度下 `fpfh_radius × factor` 可能**小于点间距** → 邻域只剩自身 → FPFH 退化
→ 粗配准直接失败。

修正：`参数 = max(参数 × factor, k × 点间距)`，k=4.0（fpfh/ransac）、2.0（icp）。
点间距用 **1-NN 距离中位数**估计（比均值稳健，不受离群点/孔洞影响），采样 4000 点。
**对正常点云零改动**（常规情况点间距远小于参数值）→ 零回归保证，
示例实测下限 0.111 m < FPFH 0.200 m，不生效 ✓

### ⚠️ 重要教训：合成点云不能用来验证 FPFH 配准

做配准对比实验时出现**反直觉结果**：在光滑合成表面（椭球 ± 多频调制）上，
**关闭尺度自适应（FPFH 半径大）反而配准更准**（角误差 0.01°），
开启自适应（半径小）却失败。

**根因**：合成点云表面光滑、无纹理，**局部** FPFH 描述子判别力弱；
半径放大后邻域覆盖更多几何上下文，等价于「全局形状描述子」，反而更强。
真实扫描点云（有噪声、有细节、密度随尺度变化）的特性**与此相反**。

**结论/约束**：配准层面的尺度自适应效果**必须用真实数据验证**，
不得用合成点云下结论。这条已写入交付文档「已知限制」。
实验脚本 `output/_t_scale_verify.py` 的实验 B 已降级为探索性诊断（不用于验收）。
