## 多视图光度校准：上限实测，代码到头了（ADR-0012）

### 做了什么
标准光度校准建模：`log c[i,k,ch] = mu[i,ch] + g[k,ch]`（双向固定效应），
交替估逐纹素真值与逐相机增益，固定一台为参考。校正后残差 = 该模型的**下限**。
不需要真值，不改产品代码。

### 结果（6 万抽样纹素，86% 被 ≥2 台相机看到，平均 5.4 视角）
| | 视图间色散（log RMS 中位） |
|---|---|
| 校正前 | **0.4028**（≈40%） |
| 校正后 | **0.4038**（−0.2%，等于没降） |
| 相机增益偏差 | 中位 **0.0%**，最大 15% |

**校正无效是因为"没有可校正的东西"**：大多数相机响应几乎一致（增益偏差中位 0%）。

### 那 40% 来自哪
1. 局部光照不均（与相机无关）
2. 斜视（cos>0.3 允许到 72°，不同视角看到**不同表面**）
3. 遮挡（探针没做 z-buffer，采到对侧颜色 → 数值偏高）

第 3 点让绝对值偏高（产品内实测 32.67 ≈ 13%），但**不影响结论**——遮挡噪声只会
让增益估**偏大**，偏大都没东西可校，真实只会更少。

### 决策
- **不做多视图光度校准**（写进 ADR 防止将来再想起）
- 色调问题剩余部分归入采集（光源布置 + 拍摄角度），与 X2 缺色卡同类
- 保留 `balance_exposure` 作为 11% 的免费改善，不再投力

### 探针踩坑
第一版全 NaN：某些相机在抽样里一个视角都没有，`nanmean` 把 NaN 传遍全部。
修法：`gnew = np.where(np.isfinite(gnew), gnew, g)`，无样本相机保持 0。

### 今天的整体结论
代码侧三条线（X2/X3/S0）全部收敛到「照片之间色彩/光照不统一」，
而这不是算法能补的。**下一步只能是采集**（规范已备好：docs/采集规范-色卡与ArUco.pdf）。

## projected_cameras=11/30 查清了：19 台相机位姿无效（提交 3b6ea50）

### 结论
| | 能看到多少纹素 | 投影区亮度 |
|---|---|---|
| 11 台 | 6% ~ 83% | 91~155（都采到文物） |
| **19 台** | **一个都看不到** | — |

不是权重问题（"看得到却不被选"的是 0 台）。

### 这 19 条的位姿本身是坏的
- R 都正交、det=+1、内参全一致 → 不是格式问题
- cam00 的照片（DSC_0014）里文物在**画面正中**，但位姿投影不出任何东西
- 拿 cam00 的位姿去试**全部 30 张照片** → **0 张有投影**
- 所以不是"配错了图片"，是这 19 条 R/t **本身无效**（可能来自另一次采集）

### 两个重要澄清
1. **不污染颜色**：权重恒为 0。我先前怀疑"采到背景导致色调跳变"是**错的**。
2. **91~155 的亮度差是真实的光照/反射差异** —— 这正好解释 ADR-0012 为什么
   光度校准无效：差异不在相机响应，在场景本身（不同角度反射不同）。

### 改了什么
`cameras_blind` / `cameras_total` 进 metrics（看到 <50 纹素算盲）。
真机：blind=19 / total=30。

### 又踩缓存（今天第二次）
新指标报 None —— 图集缓存复用"首件 metrics"，旧缓存没这些键。
修法：**`CACHE_VERSION` 1 → 2**。纪律：**凡 metrics 键集合变了就升版本号**，
比"记得清 atlas_cache"可靠。

第一次是 `balance_exposure` 没进 `params_fingerprint`（改参数无效）；
这次是加了产出指标（新键永远 None）。两者都是"缓存挡路且不报错"，
但触发条件不同：**参数键 / 输出 schema**。
