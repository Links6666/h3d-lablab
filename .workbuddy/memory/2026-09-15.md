# 2026-09-15 实机 BUG 修复与全流程可复现性根治

## 起点：实机反馈两处 BUG

1. **E601 柱状图崩溃**：`plot_stage_timings → plot_bar` 抛 `[E601] 柱状图数据为空或
   labels/values 长度不一致`，整个报表阶段失败并弹崩溃框，另伴随连续跳出的命令行窗口。
2. **向导第一步空白**：场景①/场景② 单选按钮不显示，需先「下一步」再「上一步」才可见。

  成为无父顶层窗口，首次 setVisible 不参与排版）。

## 深层排查：定位「S1 注册数 2~16 随机波动」真因

排查链条（每条结论均由实测支撑）：

1. **排除随机种子**：三个 DB × seed 0~4，同一 DB 注册数完全一致（rep/db 恒 3/16，
   db_p1/db_p2 恒 16/16）→ mapper 与种子无关。
2. **定位线程**：`--default_random_seed` 默认值本就是 0，单独设置**无效**。
   实测：提取 t=8 → 关键点哈希不一致；提取 t=1 + 匹配 t=8 → 内点哈希不一致；
   提取 t=1 + 匹配 t=1 → **文件 md5 完全一致**。真因是多线程浮点归约顺序不定。
   另测 mapper BA 位姿末位差 6.2e-15（双精度舍入噪声）。
3. **真因（重大）**：COLMAP mapper 在匹配图不连通时产出**多个子重建**，且
   **不保证 sparse/0 最大**。实测 sparse/0 = 2 张（碎片，图像集合
   `{demo_0_02, demo_1_02}` 是主模型子集，因扩展失败被丢弃、图像退回池后再注册，
   故两模型**图像集合重叠**，2+16>16），sparse/1 = 完整 16 张。
   而 `run_colmap_sparse` 硬编码只读 `sparse/0` → 所谓"波动"就是 0 号槽位
   被哪个子重建占用。与种子、线程均无关。

## 修复（管线级，sfm_solve.py）

- 新增 `_model_num_images()`：读 `images.bin` 头 8 字节（小端 uint64 = 图像数），
  不依赖 pycolmap。
- 新增 `_pick_largest_model()`：遍历 `sparse/` 取图像最多的子重建，多子重建时 warning。
- 新增 `_normalize_model_slot()`：把最大者归一化到 `sparse/0`（下游 dense/增量按
  `<sparse>/0` 约定取模型），被替换者改名 `<n>_0_replaced` **保留不删**。
- 新增 `_repro_args()`：`deterministic=True` 时 `FeatureExtraction/FeatureMatching.num_threads=1`。
- 新增 `_mapper_threads()`：确定性模式 mapper 也单线程（BA 亦有抖动）。
- `core/config.py` 新增 `sfm_solve.deterministic`（默认 True）、`sfm_solve.num_threads`。
- **另发现两处隐藏缺陷**：
  - `run_incremental_sparse` 把配置值 `"exhaustive"` 当 colmap 子命令（实为
    `exhaustive_matcher`）→ P3 增量**每次第 2 步失败并静默回退全量，功能从未生效**。
    新增 `_matcher_cmd()` 统一别名映射。
  - `run_sfm_solve` 中无条件 `inc_meta = {"incremental": False}` **覆盖**增量分支结果，
    致报表误标 + fallback error 丢失；顺带删除死代码（第二个 `run_colmap_sparse`）。
  - 增量路径另补：清理 `0_inc` 残留、预创建输出目录（COLMAP 4.x 对
    `--output_path` 做 `ExistsDir` 校验）。
- **第 4 项隐藏缺陷**：`_prepare_photos` 对「不需降采样」的照片，副本已存在时
  **无条件跳过写入** → 源照片被替换/重拍后重跑会**静默沿用过期副本**
  （表现为「换了照片但重建结果不变」）。新增 `_cache_is_stale()`（源 mtime 比副本新
  或副本缺失时刷新，容差 1s）+ 4 项回归测试。
- `h3d_gui.spec`：隐藏导入写错模块名 `h3d.report.html`（不存在）→ 改为
  `h3d.report.html_export`，消除每次打包的 ERROR 行。

## 示例数据重构：纹理适配 SIFT

- 旧纹理（θ/φ 参数域正弦叠加）三缺陷：极点附近各向异性、细尺度能量仅占 1/√20、
  60° 周期方格造成近自相似。实测仅 **403 关键点/图、45/120 像对可匹配**。
- 新纹理：**球面随机平面波场**（Berry 随机波）`Σ a_k·sin(f_k·(d_k·p)+ψ_k)`，
  d_k 为三维随机方向；依据「SIFT 是 DoG 极值检测器，带限随机场局部极值数 ∝ f²」，
  把能量集中到 3~12 px 周期频段 + 12~60 px 低频段（共 72 分量），a ∝ f^-0.5。
  新增 `PIX_PER_UNIT = FOCAL_RATIO*W/CAMERA_DISTANCE ≈ 163.6` 做像素周期↔波数换算。
- 对照实验（`output/_t_tex.py`，同一套确定性 COLMAP）：
  base 403kp/45对/63内点/3-16 → wave_hi **4248kp/76对/522内点/16-16**（采用）。
  wave_lat（加周期方格）34/120 更差 → 印证方格破坏匹配。λ<3px 会混叠。
- 渲染提速 4×：纹理在 1× 分辨率求值后 `np.repeat` 广播到 2× 超采样网格
  （带限纹理 2×2 块取值几乎相同，等价），16 视角由 ~90s 降到 ~25s。
  高斯斑点场方案因 `(N_blobs, N_pixels)` 距离矩阵致 85s/图、3.3GB 内存，已弃用。

## 关键教训

- **「随机波动」未必来自随机数**：先排除种子（实测一致），再排除线程，最后才落到
  数据结构/模型选择逻辑。COLMAP 多子重建是最易被忽略的一类。
- **静默降级要不得**：增量路径 `except SfmError` 吞异常 + 只留 warning，掩盖了
  「子命令名错误致功能从未执行」达数周。
- **测试断言要锁行为本质**，不要只断言「不报错」：如「两轮 DB 逻辑签名相同」
  「0(2张)/1(16张) 时 sparse/0 最终必须 16 张」。
