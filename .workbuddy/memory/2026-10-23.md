e2e 的 web/mobile 引擎（Playwright/设备）挂不上 PySide6 桌面程序（项目无 node 工程），
按 skill 的 **bug-bash 方法论** 套到自家栈：charter（5 个入口面）→ 并行 fan-out
（`_bugbash/charters.py`，6 个 charter）→ 合并 → triage → 每条候选**先写失败的复现
测试再修**。9 条候选，确认 6 条，拒绝 3 条。

### 确认并修复（v1.1.3）
1. **打包版 CLI 契约**：launcher 只认 `--batch`/`--report`，`H3D.exe --version` /
   `doctor` / `validate` 全落进 GUI 分支 → 脚本里**永久挂起**（charter c6 实测卡 10 min，
   我自己的探测被吊死，得 taskkill）。改为 `_CLI_PASSTHROUGH` 白名单透传 `h3d.cli`，
   无参数仍进 GUI。**判据：凡是"打包版和源码行为不同"都要按 exe 实测，不能只看源码。**
2. **manifest 非原子写 + 零容错**（`core/metadata.py`）：`open(path,"w")` 先清空再写，
   硬杀/断电留下截断 JSON → 之后每次 `_init_manifest` 抛 `JSONDecodeError`，
   项目**永久跑不起来**（这条管线的常态就是 `taskkill /F /T`、超时杀）。
   改 `tmp + fsync + os.replace`；损坏时备份 `<name>.corrupt-<时间戳>` + WARNING +
   空 manifest 重跑；`stages` 非 dict 就地纠正（否则 `.get` 在很远的地方 AttributeError）。
   实测 `_init_manifest` 不再抛，stages={}，备份文件生成。
3. **系统目录变文物**：`00_raw/.git`、`__MACOSX`、`$RECYCLE.BIN`、
   `System Volume Information`、平铺模式 `._xxx.ply`（AppleDouble）各成一件任务，
   随后 M1 报"点云为空"（实测 1 件 → 3 件）。加 `_is_junk_dir()` 过滤。
4. **GBK/ANSI 配置报 Python 栈**：中文 Windows 记事本"ANSI"=GBK →
   `UnicodeDecodeError` 直穿。改 `utf-8-sig` 读 + 捕获 `UnicodeDecodeError` →
   `[E001] 配置文件编码不是 UTF-8…请另存为 UTF-8`。
   **BOM 不是 bug**：PyYAML 自己会吃 BOM（原用例全 ASCII，测了个寂寞，triage 时拒绝）。
5. **`validate` 0 件仍 rc=0**：当 CI 门禁时空项目蒙混过关。改 rc=1 + 排查方向。

## 实机「M1 跑 50 分钟 / 10GB」根因与修复（v1.1.4）

**现象**：真实件（30 张 4496×3000，纯照片场景②），S1 30 min 正常，M1 跑 50 min
未完成、内存 10 GB，人工取消；但中途 PLY 几何形态"还不错"。

**定位**（同一份真实 fused_dense.ply，677274 点 / diag=15.3546 / MPS=0.00299）：
- load 0.2s、深拷贝 0.0s → `cluster_dbscan(eps=0.02*diag=0.3071)` **284s 未结束、
  RSS 4.6GB 且持续增长**（我手工 kill）；对照：降采样到 70k 后同一调用 1.4s。
- 根因：`eps` 只跟**包围盒对角线**挂钩 → 0.3071 = **102×MPS**，每点邻域 **279** 个点
  （中位 319）→ 677k×279 ≈ **1.9 亿条边**；Open3D cluster_dbscan 单线程、逐点建
  完整邻域表、67 万个各自堆分配的 vector → 内存 45MB/s 线性涨。
- **复杂度缺陷，不是参数没调好**：成本 ∝ N×平均邻域，邻域又随密度涨；6 万点的旧
  数据上同一段代码只要 1.4s，所以长期没暴露。

**修复（三重保险，`preprocess/background.py`）**：
1. `eps = min(cluster_eps_frac*diag, bg_cluster_eps_k*MPS)`（默认 k=10，MPS 取
   工作副本上的最近邻中位数）；
2. 聚类只在 **≤ bg_max_cluster_points（15 万）的工作副本**上做 → 标签按最近邻
   **回投**全分辨率（原始点一个不丢）；
3. 邻域表预算看门狗：判据是 **n × avg_neighbors > 6e7 条边**（不是邻居数！面状
   点云 avg≈πk²，只卡邻居数会把正常点云误判），超了逐级收紧 eps（k→4→2×MPS），
   仍超才放弃聚类且**必须**写 metrics+WARNING（禁止静默跳过=背景剔除失效）。
配套：M1 打印背景剔除摘要；config 增 `bg_cluster_eps_k`/`bg_max_cluster_points`。

**验证**：677k 背景剔除 284s未完成→**4.9s**，内存 4.6GB→**0.23GB**，保留 622157 点
（91.9%），diag 15.35→**5.95**；M1 全阶段 **6.28s**（manifest 实测），M2 0.03s、
M3 2.09s、M4 98.7s、M5 0.78s、M6 0.42s，全链路 done=1 failed=0，80_export 出
ply/obj/mtl/glb/diffuse.png。

**S1 30 min 归因（COLMAP 自己的 timer 日志，99_runs/sfm_tmp/<id>/logs/）**：
特征提取 1.62min / 匹配(exhaustive 435 对) 4.57min / mapper 0.72min /
undistort 0.04min / **patch_match_stereo 两遍 22.63min（76%）** / fusion 0.13min。
→ 稠密段是正常开销；旋钮：`dense_geom_consistency=false`（减半）、
`dense_max_image_size` 1600→1200（像素 ×0.56）、matcher sequential（配对 435→58）。
**顺手修的两个度量/契约缺陷**：① `elapsed` 在 dense 之前取 → 22min 稠密从
elapsed_s 里凭空消失（改到 dense 之后）；② GUI 默认写 `matcher: sequential`，
auto_calibrate 却偷偷改成 exhaustive —— 改为 `matcher: auto`（标定决定）+ 显式
值以配置为准（WARNING 提示分歧）。

**测试** 668 passed（+4：eps 受 MPS 约束 / 工作副本有上限 / 回投保留全分辨率 /
预算超限是收紧半径而非静默跳过）。教训：**凡以包围盒对角线（几何极值）做尺度基准
的参数，必须同时受点间距约束**——极值只描述"多大"，点间距才描述"多密"。

## v1.1.4 正式打包发行（22:00-22:45）

**用户反馈**：1.1.4 根本没有打包发布。核实两点：①`release/` 下只有 `H3D_v1.1.0`，没有
发行目录 / 安装包 / zip；②更关键——`packaging/version_info.txt` 还停在 1.1.3.0，所以
`build_out_v10/H3D.exe` 的**属性页显示 1.1.3**，与 `--version` 的 1.1.4 自相矛盾。

**已交付**：
- `release/H3D_v1.1.4/`：H3D.exe（238,138,428 B / PE 1.1.4.0）、H3D-Setup-v1.1.4.exe
  （236,839,138 B）、README、VERSION（含实测 SHA-1）、configs、docs（40 份，新增
  v1.1.4-r8 发行说明 9 页）、source（189 文件镜像快照）、tools
- `release/H3D_v1.1.4_发行包_20261023.zip`：465 MB / 235 条目 / CRC 全检 / 必须项全在
- 测试 **671 passed**（+3 条 windowed stdio 回归）

**顺手补掉的真实缺陷**（来自用户 21:10 的崩溃日志，不是代码审查）：
`preview.py:45` 读模型时 `AttributeError: 'NoneType' object has no attribute 'write'` ——
windowed 下 `sys.stdout/stderr` 为 None，Open3D 打一条警告就抛进 Qt 槽，预览停在空白。
已在 `_force_utf8_stdio()` 里把 None 流置换为 `_NullStream`。这条能解释"预览看着像加载失败"。

**工程化（防复发）**：
- `scripts/make_version_info.py`：PE 版本资源由 `__version__` 生成，spec 打包时强制重算；
- `scripts/_relver.py`：三个发行脚本的版本 / 目录名统一来源（此前各自写死 1.1.0）；
- `scripts/build_installer.py`：iss 参数化（`#ifndef` 兜底 + ISCC `/D` 注入），编译前校验
  exe 的 PE 版本与 `__version__` 一致，编译后自动复制进发行目录；
- zip 大文件走 `ZIP_STORED`：打包 7 min 降到 3 s。

**三个踩坑**：
1. 先 `sync_source_snapshot` 后改 iss / 加脚本 → 快照里是 1.1.0 硬编码的旧 iss、缺
   build_installer.py，zip 已生成才发现，只能重做一轮。**快照必须最后同步**。
2. `update_release_meta` 的 `count(标题)` 被"修订九之二"等子章节干扰（数出 5 次）；
   VERSION 文件清单行用 `startswith(新文件名)` 匹配不上旧行，导致新版 VERSION 里留着
   `H3D-Setup-v1.1.0.exe 236,730,290 B（r7）`。已改为唯一标记 / 前缀匹配。
3. 核版本串别用 PowerShell 字符串拼接看尾部：Inno 定长空格填充会被终端显示成多一个
   字符，误判成缺陷；用 VerQueryValue 读 repr 才准（实测无多余字符）。
