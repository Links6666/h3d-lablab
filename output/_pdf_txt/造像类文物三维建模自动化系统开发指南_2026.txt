第零篇 方法论与核心指导方针
本篇在动手写任何一行代码之前，先确立全书的立场、原则与读法。它回答三个问题：我们为何用软件工
程的方法做文保？全书要守住哪些底线？不同背景的读者该怎样使用这本书？
0.1 本书的双重立场：软件工程 × 文保实践
传统文保数字化教程多停留在「某软件怎么点」；纯软件工程教程又假定读者已有成熟业务。本书坚持双
视角：
• 工程视角（从业开发者立场）：把「造像三维建模」当作一个可定义需求、可拆解模块、可测试、可复
现、可交付的软件产品来对待。强调版本控制、自动化、可维护性、文档与著作权。
• 文保视角（研究生 / 业务方立场）：每一行代码都要回应真实的文物保护问题——无损、精度可溯源、
符合 WW/T 行业标准、服务于病害定量与材料评价，而非炫技。
• 交汇点：可复现（reproducible）= 学术诚信 + 工程质量。你今天能一键重跑的管线，既是可发表的
成果，也是可申请软件著作权的客体。
0.2 核心指导方针（十条）
1. 先定义需求，再写代码。一切功能从「文保场景的真实痛点」倒推，禁止为了堆功能而写代码。
2. 可复现优先于一次性结果。任何模型都必须由脚本 + 配置 + 原始数据可追溯地重生，严禁手点 GUI 
后只交一个模型文件。
3. 批处理优先于单样本。系统从第一天就按「目录进、目录出」设计，单一造像只是批量里的一个 item。
4. 开源合规是不可逾越的红线。引入每一个库先查许可证；GPL 类只能子进程调用，绝不静态链接进你
的闭源/登记版。
5. 精度必须量化并署不确定度。报告「配准误差 1.8 mm ±0.4 mm」远胜「配准良好」。
6. 数据只读、永不覆盖原始。原始扫描永远放在 00_raw 且仅读，所有产物落在派生目录。
7. 失败隔离、断点续跑。一个坏文件不能让整批崩溃；重跑只补未完成的 item。
8. 留痕即护权。开发过程的 commit、issue、notebook 是你的独创性证据，也是应对 2026 软著实质
审查的弹药。
9. 中文界面与中文注释。成果最终服务于中国文博单位，文档与代码注释使用中文。
10. 小步快跑、每周可演示。研一就能跑通 MVP，再逐版本加模块，避免毕业前才发现架构走不通。

第一篇 背景：技术管线故事、文保场景与政策
本篇回答「我们为什么要从零搭一套自动化建模系统」。它从一线文保的真实困境讲起，铺陈造像类文物
的特殊性、西南潮湿环境的额外挑战，综述前人研究，最后引出本书的主角——技术路线 E 自动化管线，
并在背景中论述多时相与色度差分两块可扩展能力。
1.1 文保数字化的现实困境（背景故事）
故事从一个具体场景开始。某石窟寺需对一尊彩绘造像做三维存档：
• 现场用结构光 / 激光扫描得到数十站、数百万到上亿点的点云；用单反拍得数百张高像素 RAW 纹理。
• 传统工作流：把这些数据导入商业 GUI 软件（如 Metashape、CloudCompare、Geomagic），人工
逐站配准、手动去噪、手工重建网格、肉眼检查。一个熟练工程师处理一尊造像要数天。
• 痛点 1——不可复现：同样的数据换个人、换台机器，点几下不同，结果就不同，无法在论文里说清「
我怎么得到的」。
• 痛点 2——不可批处理：十尊、一百尊造像时，手工流程彻底崩溃，且无法保证一致性。
• 痛点 3——核心算法黑箱：商业软件配准用的什么方法、误差多大，用户不知道，调参靠经验。
• 痛点 4——成本与许可：商业软件按节点收费，课题组预算有限；且生成结果的法律属性（能否开源、
能否申请软著）模糊。
这些痛点并非个例。它解释了为何「用开源、可脚本、可复现的 Python 管线替代手工 GUI」对文保研究
方向生具有战略价值：它把你和「只会点软件的技术员」区分开，是你的核心壁垒。

1.3 西南潮湿环境的特殊挑战
以重庆及川渝石窟寺为例，潮湿环境带来四类额外难题【推断＋标准】:
• 水盐 cycle：雨季水汽携带可溶盐（硫酸盐、硝酸盐）反复结晶—溶解，体积变化应力破坏地仗，引发
酥碱、起甲、龟裂、脱落（与灵岩寺罗汉像病害机制同源，见 1.5.1）。
• 可逆湿胀干缩形变：同一造像在湿季 / 旱季表面有毫米级可逆位移，与不可逆风化难以分离——这正
是多时相差分（第五篇）要专门处理的不确定性来源。
• 低光照 + 高湿的纹理采集：洞窟内光照弱、湿度大，色卡校准与 RAW 工作流更关键（见 2.4、第五篇
 5.2）。
• 设备与准入门槛：大场景激光扫描设备稀缺、核心区准入需正式渠道；故系统以「摄影测量替代激光、
院内结构光做高精度、借用合作单位数据」为低成本方案（见 1.6）。

1.6 本文提出的解决办法：技术路线 E 自动化管线
技术路线 E 是用 Python + Open3D（+ py4dgeo） 复现并自动化导师商业软件工作流的开源管线。它的
主张：
• 可复现：同一个 config.yaml + 同一份原始数据，任何人重跑得到同一结果。
• 可批处理：输入一个目录（N 尊造像），输出 N 套模型 + 一份 run_manifest.json 溯源清单。
• 可开源 / 可申请软著：纯 MIT 栈（Open3D/py4dgeo/colour-science/NumPy）使著作权与合规无
虞（见第三篇 3.5）。
• 低成本起步：一台普通笔记本即可跑通 MVP；GPU 为加分项非必需（降采样 + 分块）。
• 方法底座：作为 A（大足彩绘石质造像病害定量）、B（多时相差分）、C（材料形貌响应）、D（色
彩规范）四方向的技术底座，而非孤立工具。
管线主线聚焦「文物批量数字化处理 + 自动化输出数字模型」；多时相差分与标准色差计算设计为两个可
选的次要模块（配置开关），既聚焦 V1.0 功能描述，又为 V2.0 单独登记留空间（见 1.7、第二篇 2.1）。

1.7.1 多时相建模（M3C2 板块）

2.4.2 精度保障的工程落点
• 配准误差预算：把 WW/T 的 5 mm 中误差拆到各工序（扫描仪本身、标靶、全局配准、ICP），每步

3.5.2 plyfile 的 GPL 隐蔽陷阱（重点）
plyfile 是最常用的 PLY 读写库，但其许可证为 GPL-3.0+。一旦 import plyfile 写进你的登记版源码，整
个程序可能被认定为 GPL 衍生作品，与「闭源登记 / 商用」冲突。规避：一律用 Open3D 的 
o3d.io.read_point_cloud/write_point_cloud 读写 PLY（MIT），不安装 plyfile。
3.5.3 GPL 库的安全使用方式
• 子进程调用：subprocess.run(["CloudCompare", "-O", ...])，你的代码与 GPL 程序是独立进程，不构
成衍生作品。
• 声明与署名：在 NOTICE/文档中列出所用 GPL 组件及其许可证与获取方式（软著新规也要求标注开源
来源）。
• 不静态链接：绝不把 GPL 的 .so/.py 直接 import 进登记版主程序。
• 优先纯 MIT 栈：管线 V1.0 主体用 Open3D/py4dgeo/colour-science/NumPy（全 MIT/BSD），
从源头消除传染。
3.5.4 数据许可：代码开源 ≠ 数据公开
原始造像点云/纹理属文博单位资产，具敏感性与版权。原则：代码仓库开源，原始数据目录（00_raw）永
不随代码发布；发布示例用公开数据集（Stanford Bunny、Open Heritage 3D、Zenodo 文化遗产点云）
。

# h3d/io_adapters.py
import open3d as o3d
import glob, os
def load_all(pattern):
    """读取匹配模式的所有点云，返回 (路径, 点云) 列表。"""
    paths = sorted(glob.glob(pattern))
    if not paths:
        raise FileNotFoundError("未匹配到任何点云: " + pattern)
    pcds = []
    for p in paths:
        pcd = o3d.io.read_point_cloud(p)   # PLY/OBJ 由 Open3D(MIT) 读取，避开 plyfile(GPL)
        if not pcd.has_points():
            raise ValueError("空点云: " + p)
        pcds.append((p, pcd))
    return pcds
4.4.3 M2 预处理（降采样 / 去噪 / 法线）
# h3d/preprocess.py
import open3d as o3d
def preprocess(pcd, voxel_size, normal_radius, nnb=30):
    pcd = pcd.voxel_down_sample(voxel_size)                       # 降采样
    pcd, ind = pcd.remove_statistical_outlier(nb_neighbors=20,   # 去噪
                                              std_ratio=2.0)
    pcd.estimate_normals(
        o3d.geometry.KDTreeSearchParamHybrid(radius=normal_radius, max_nn=nnb))
    pcd.orient_normals_consistent_tangent_plane(k=nb_neighbors=15)  # 法线一致化
    return pcd
4.4.4 M3 配准（全局 + 精配准）
# h3d/registration.py
import open3d as o3d
def global_register(src, tgt, fpfh_radius, ransac_dist, nnb=30):
    # 计算 FPFH 特征
    for pcd in (src, tgt):
        pcd.fpfh = o3d.pipelines.registration.compute_fpfh_feature(
            pcd, o3d.geometry.KDTreeSearchParamHybrid(fpfh_radius, nnb))
    result = o3d.pipelines.registration.registration_ransac_based_on_feature_matching(
        src, tgt, src.fpfh, tgt.fpfh,
        mutual_filter=True,
        max_correspondence_distance=ransac_dist,
        estimation_method=o3d.pipelines.registration.TransformationEstimationPointToPoint(False),
        ransac_n=4,
        checkers=[o3d.pipelines.registration.CorrespondenceCheckerBasedOnEdgeLength(0.9),
                  o3d.pipelines.registration.CorrespondenceCheckerBasedOnDistance(ransac_dist)],
        criteria=o3d.pipelines.registration.RANSACConvergenceCriteria(max_iteration=200000))
    return result
def icp_refine(src, tgt, init, max_dist):
    return o3d.pipelines.registration.registration_icp(
        src, tgt, max_dist, init,
        o3d.pipelines.registration.TransformationEstimationPointToPoint())

import open3d as o3d
def simplify(mesh, target=200000):
    return mesh.simplify_quadric_decimation(target_number_of_triangles=target)
def hausdorff(mesh_a, mesh_b):
    # 用 Open3D 采样点计算两网格 Hausdorff 距离，作为几何误差指标
    a = mesh_a.sample_points_uniformly(100000)
    b = mesh_b.sample_points_uniformly(100000)
    d = a.compute_point_cloud_distance(b)
    return max(d)
4.4.7 M6 批量调度（续跑 / 隔离）
# h3d/pipeline.py
import json, glob, os, logging
from h3d import io_adapters, preprocess, registration, reconstruct, postprocess
def run_pipeline(cfg):
    manifest = load_or_init_manifest(cfg)
    items = sorted(glob.glob(cfg["object_glob"]))
    for raw in items:
        item_id = os.path.basename(raw).split(".")[0]
        if manifest.done(item_id):            # 断点续跑：跳过已完成
            logging.info("跳过已完成: %s", item_id); continue
        try:                                  # 失败隔离：单 item 异常不影响整批
            pcd = io_adapters.load_one(raw)
            pcd = preprocess.preprocess(pcd, cfg["voxel_size"], cfg["normal_radius"])
            # ... 配准 / 重建 / 度量 ...
            mesh = reconstruct.poisson_mesh(pcd, cfg["poisson_depth"])
            out = os.path.join("03_model", item_id + ".ply")
            o3d.io.write_triangle_mesh(out, mesh)
            manifest.mark_done(item_id, out)
        except Exception as e:
            logging.error("item 失败 %s: %s", item_id, e)
            manifest.mark_failed(item_id, str(e))
    manifest.save()

5.1 多时相建模与劣化速率量化（X1）
5.1.1 M3C2 原理
M3C2（Lague et al. 2013）在核心点沿其法线方向，分别于两期点云做局部球状邻域最佳拟合平面，计算
法向距离差即为变化量；可附加误差传播（M3C2-EP, Winiwarter 2021）给出不确定度。py4dgeo（MIT）
原生实现 M3C2/M3C2-EP/PB-M3C2。
5.1.2 py4dgeo 调用示例
import py4dgeo
import numpy as np
# 两期点云（py4dgeo.PointCloud 包裹 numpy 数组）
t1 = py4dgeo.PointCloud(np.load("scan_2025.npy"))
t2 = py4dgeo.PointCloud(np.load("scan_2026.npy"))
# 核心点取首期点；法线由 Open3D 估算后传入
core_points = t1
normals = np.load("normals_2025.npy")
m3c2 = py4dgeo.M3C2(
    core_points=core_points,
    normals=normals,
    working_distance=3.0,     # mm，局部邻域半径
)
distances = m3c2.compute(t1, t2)   # 沿法向的距离变化（正=外鼓/沉积，负=侵蚀）
print("平均变化 mm:", np.nanmean(distances))
5.1.3 实施要点
• 配准误差会直接污染差分结果 → 先用 CloudCompare/Open3D 把两期配准误差压到亚毫米。
• 潮湿环境可逆湿胀与不可逆风化难分 → 用「加速老化模拟样块 + 高频短周期（月）监测 + 历史 vs 现
状差分」组合。
• 环境变量（温湿度/水盐）耦合建模，量化不确定性，不报单一确定值。

4.4.8 尺度自适应与 MPS 倍数体系
不同尺度造像（掌印小龛 vs 大佛）应使用不同 voxel_size。本书采用「基准尺度 × MPS 倍数」的尺度自
适应策略【设计】：以一尊约 1 m 造像的 voxel=2.0 mm 为基准（MPS=1），更大对象按线性比例放大
倍数。
def adaptive_voxel(base_size_mm, object_bbox_mm, mps=1.0):
    """按对象包围盒最长边相对基准(1000mm)的比例，乘 MPS 倍数得到 voxel。"""
    scale = max(object_bbox_mm) / 1000.0
    voxel = 2.0 * scale * mps
    return round(voxel, 3)
# 例：2.4 m 大佛，MPS=1 -> voxel≈4.8mm
print(adaptive_voxel(2.0, [2400, 1800, 1600]))

5.1.4 M3C2 误差传播（不确定度同报）
M3C2-EP（Winiwarter et al. 2021）将两期点云各自的局部平面拟合不确定度 propagate 为距离差的总
不确定度 σ。实务中：
• 核心点法向距离差 d；不确定度 σ = sqrt(σ ² + σ ² + σreg²)（σreg 为配准误差贡献）。
• 报告格式：「变化量 d = -1.3 mm ± 0.6 mm」，仅当 |d| > 2σ 才判定为显著变化。
• 这直接呼应 2.4.2「不确定度同报」原则，也是区分潮湿环境可逆形变与不可逆风化的关键。

5.2.3 色卡校准逐步流程（可落地的 D 方向规程）
1. 每次拍摄前放 X-Rite 24 色卡于造像同光照平面，同角度拍一张含色卡的原图（RAW）。
2. 用相机特性文件（ICC）将 RAW 转 ProPhoto/Adobe RGB 线性空间，避免显示器相关空间。
3. 在色卡区域用已知 Lab 值做色彩校正，求本场次色差补偿矩阵。
4. 对造像目标区域取色，转 Lab 后跨时段算 ΔE  。

2.6 标准符合性自检脚本

# h3d/compliance.py（示意）
CHECKS = [
    ("点云特征点中误差<=5mm", lambda r: r.max_pt_err <= 5.0),
    ("可见区域覆盖率>=80%",   lambda r: r.coverage >= 0.80),
    ("相邻站重叠>=30%",       lambda r: r.overlap >= 0.30),
    ("纹理>=3400万像素RAW",   lambda r: r.tex_mp >= 34.0),
]
def audit(report):
    return {name: ("PASS" if fn(report) else "FAIL") for name, fn in CHECKS}
