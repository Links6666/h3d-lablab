1.1 什么是「管线骨架」
管线骨架（pipeline skeleton）指软件最外层的可运行工程容器：一组约定俗成的目录、包边界、占位文
件与工程元数据文件。它不含算法实现，却决定了后续所有代码「放在哪里、如何被导入、如何被测试、
如何被打包」。骨架的价值在于：在写第一行业务代码之前，先固定工程的拓扑结构与契约，使多人协作、
增量演进、软著登记与自动化测试都站在同一套坐标上。 对造像类文物三维建模自动化系统而言，骨架即
《项目目录草案》所定义的路线 E（Open3D 开源管线）工程布局：以 src/h3d 为核心业务包，向下挂 8
个业务子包，向外挂测试、配置、文档与数据/产物隔离目录。

2.1 管线本质：分阶段的确定性数据流
三维建模自动化管线是一条「输入原始影像 / 点云 → 输出高保真模型 + 质检报告」的确定性数据流。其抽
象可表达为：
原始数据 raw
  -> [IO 适配]        读取 / 格式归一
  -> [预处理]         去噪 / 降采样 / 法线
  -> [配准]           异源点云 FPFH+RANSAC+ICP
  -> [建模核心]       稠密重建 / 网格化 / 纹理
  -> [可选 X1 多时相] M3C2 形变检测
  -> [可选 X2 色彩]   CIEDE2000 色差量化
  -> [质检/报表]      误差评估 / CSV / 图表
  -> 产物 output (模型 + run_manifest.json)
骨架必须让上述每一个阶段都拥有稳定的「家」（目录 + 包 + 占位文件），使得阶段之间只能通过显式导
入 / 配置耦合，而不是散落在脚本根目录的扁平 .py 文件。
2.2 五层架构在骨架上的投影
设计书提出的五层架构（L0 依赖 / L1 适配 / L2 业务 / L3 编排 / L4 应用）在骨架目录中体现为清晰的层

2.3 骨架是抽象架构的「可编译投影」
设计书的模块标识（M0~M6、X1、X2）是逻辑概念；骨架将其映射为物理包名，使概念可被文件系统直
接验证。这种「概念→目录」的投影关系见第 4 章映射表。骨架因此成为架构一致性的第一道守门员：若
某段业务代码无法归入 8 个子包之一，说明模块边界或需求定义存在问题，应回到设计书修订，而非随意
新增扁平脚本。

8.2 与「教学版开发指南」的关系
教学指南以「从零手把手」方式带读者实现系统，其「工程组织 / 包结构」一章即本骨架的逐步落地版。

架脚本获得空工程，再按教学指南逐章填充实现，二者互补。
8.3 与「软件著作权」的关系
• 纯 MIT/BSD 依赖栈在 pyproject.toml 中固化，从工程声明层面杜绝 GPL 传染风险
• data/ 与 output/ 被 .gitignore 忽略，落实「数据开源 ≠ 数据公开」，保护原始文物数据
• runner/manifest 与 metadata.py 占位预设溯源能力，支撑软著「实质 coding」举证
• tests/ 独立统计、不混入业务源码，符合软著提交「前后各 30 页源码」的清晰边界
• 软著登记版须为完全人工重写；骨架占位仅作开发起点，登记前应替换为真实、原创实现
8.4 与「文保标准（WW/T 0117 / 0115）」的关系
骨架本身不实现精度阈值，但通过 configs/example.yaml 的 preprocess/register 参数段与 report 子包
占位，把「中误差≤5mm、覆盖≥80%、重叠≥30%」等标准的落点预留出来：后期在 register/evaluate

9.2 工程纪律：单文件上限与 cloc 口径
《项目目录草案》给出两条关键工程经验，骨架生成后须长期遵守：
• 单文件有效代码尽量不超过 350 行；某文件持续膨胀即拆分（如 register 拆分为
feature/ransac/icp/evaluate 四个文件）
• cloc 统计口径：只算 .py 业务源码，剔除注释、空行、yaml/md、测试、数据、缓存；tests 单独统计
不计入业务行数
• 高内聚、可复现、清晰接口优先于行数；约 2500 行高质量代码即可支撑硕士小论文 + 软著 + 求职作
品集
• 探索期草稿（notebooks/ 与临时脚本）不纳入发布与软著统计，登记前清理

function New-Dir {
    param([string]$Path)
    if (-not (Test-Path -LiteralPath $Path)) {
        $null = New-Item -ItemType Directory -Path $Path -Force
        Write-Host ("  [DIR ] " + $Path) -ForegroundColor Cyan
        $script:createdDirs++
    } else {
        Write-Host ("  [SKIP] " + $Path) -ForegroundColor DarkGray
        $script:skipped++
    }
}
